## Egy kattintás útja

Eddig a Rozsda csak a saját gépedről nyitott meg fájlokat. Egy igazi böngésző viszont ezt csinálja, amikor beírod, hogy `http://pelda.hu/cikkek/rozsda.html`:

```text Ábra
 1. URL feldolgozása       http://pelda.hu/cikkek/rozsda.html
                           séma   gépnév   útvonal
 2. DNS: név → IP-cím      pelda.hu  →  93.184.215.14          (UDP, 53-as port)
 3. TCP-kapcsolat          a gépem:51234  ⇄  93.184.215.14:80   (háromutas kézfogás)
 4. HTTP-kérés             GET /cikkek/rozsda.html HTTP/1.1
 5. HTTP-válasz            HTTP/1.1 200 OK … és a HTML (gyakran gzip-pel tömörítve)
 6. a böngésző többi része: parser, CSS, layout, rajzolás (ezt már megírtad!)
```

Mindegyik lépés egy-egy **protokoll**: egy szabály arról, hogy a két fél milyen sorrendben, milyen formában küld egymásnak bájtokat. Egymásra épülnek, mint a rétegek:

| Réteg | Protokoll | Mit tud | Mi írjuk? |
|---|---|---|---|
| Alkalmazás | HTTP, DNS | „add ide ezt az oldalt”, „mi a címe ennek a névnek” | **igen**, nulláról |
| Szállítás | TCP, UDP | megbízható bájtfolyam (TCP), vagy egyszerű csomagok (UDP) | az operációs rendszer adja |
| Hálózat | IP | csomagok címzése és útválasztása (routing) | az operációs rendszer adja |
| Fizikai | Wi-Fi, Ethernet | bitek a levegőben vagy a kábelen | a hálózati kártya |

A TCP-t és az IP-t a Windows (és minden operációs rendszer) megírta helyettünk: a Rust `std::net`-je ezeket hívja. Minden, ami felettük van, a mi kódunk lesz.

:::compare Hálózat máshol
@@ C#
Egy sor: `await new HttpClient().GetStringAsync("http://pelda.hu/")`. Mögötte a .NET a DNS-t, a TCP-t, a HTTP-t, a tömörítést és az átirányításokat is elintézi. Mi most ezt a `HttpClient`-et írjuk meg.
@@ C++
A `libcurl` a klasszikus: C-ben írt, szinte mindenhol ott van (a Windows 10 óta a `curl.exe` is). Alacsonyabb szinten a Winsock vagy a POSIX `socket()` hívások.
@@ Python
`urllib.request.urlopen(…)` vagy a `requests` csomag. A 07-es leckétől a tesztszerverünk is Pythonban lesz, a beépített `http.server` modullal.
@@ Rust
A profi Rust-világban a `reqwest` (HTTP-kliens) és a `url` crate a szabvány. A 16. modulban ezek kerülnek a kapcsoló mögé.
@@ Érettségi
Az informatika érettségi hálózati témaköre: az OSI-modell rétegei, IP-cím, port, DNS, protokoll. Most mindegyiket kódban is látni fogod.
:::

## Az első darab: százalékos kódolás

Egy URL-ben csak az ASCII-karakterek egy része állhat: betűk, számok és néhány jel. Minden más (szóköz, ékezetes betű, és a URL-ben különleges jelentésű `#` vagy `?`) **százalékosan kódolva** utazik: a karakter UTF-8 bájtjai `%XX` alakban, ahol `XX` a bájt hexadecimálisan.

```text Ábra
árvíz tűrő.html

  á → C3 A1 → %C3%A1        í → C3 AD → %C3%AD
  ű → C5 B1 → %C5%B1        ő → C5 91 → %C5%91
  (szóköz) → 20 → %20

→ %C3%A1rv%C3%ADz%20t%C5%B1r%C5%91.html
```

Az, hogy melyik karaktert kell kódolni, a URL **részétől** függ. A `?` az útvonalban kódolandó, mert ott a lekérdezés elejét jelentené; a lekérdezésben viszont már nyugodtan állhat. A WHATWG URL-szabvány ezért **kódolási halmazokat** (percent-encode sets) ad meg:

| Halmaz | Mit kódol (a vezérlőkaraktereken és a nem ASCII bájtokon kívül) |
|---|---|
| C0 control | semmi mást |
| fragment (`#` után) | szóköz `"` `<` `>` `` ` `` |
| query (`?` után) | szóköz `"` `#` `<` `>` |
| special-query (http, https …) | mint a query, és `'` |
| path (útvonal) | mint a query, és `?` `` ` `` `{` `}` |

A **kódolás** (encode) karakterenként dönt a halmaz alapján. A **visszafejtés** (decode) egyszerű: minden `%XX`-ből egy bájt lesz. Ha a `%` után nem két hexa jegy jön (pl. `100%`), a szabvány szerint a `%` egyszerűen marad.

Miért ad a `percent_decode` bájtokat, és nem `String`-et? Mert a `%FF` egy érvényes kódolás, de az `FF` bájt önmagában nem érvényes UTF-8. A hívó dönti el, mit kezd vele.

```rust test
#[cfg(test)]
mod tests {
    use super::*;

    // 08-01
    #[test]
    fn decoding() {
        assert_eq!(percent_decode("a%20b"), b"a b");
        assert_eq!(percent_decode("%C5%91"), "ő".as_bytes());
        assert_eq!(percent_decode("100%"), b"100%", "a magányos % marad");
        assert_eq!(percent_decode("%zz%4"), b"%zz%4");
    }

    #[test]
    fn encoding() {
        assert_eq!(percent_encode("a b", EncodeSet::Path), "a%20b");
        assert_eq!(percent_encode("ő", EncodeSet::C0Control), "%C5%91");
        assert_eq!(percent_encode("mi?", EncodeSet::Path), "mi%3F");
        assert_eq!(percent_encode("mi?", EncodeSet::Query), "mi?");
        assert_eq!(percent_encode("it's", EncodeSet::SpecialQuery), "it%27s");
    }
}
```

:::hint
A visszafejtésnél egy `while` ciklus kell egy `i` indexszel, mert a `%XX` három bájtot fogyaszt el, a többi egyet. A két hexa jegy: `bytes.get(i + 1..i + 3)` (ez `None`, ha kilógna), aztán `std::str::from_utf8` és `u8::from_str_radix(h, 16)`.
---
A `contains`-ben a vezérlőkarakterek és a nem ASCII bájtok: `!(0x20..0x7F).contains(&b)`. A többi halmaz ehhez tesz hozzá néhány jelet. Egy bájtszeletben gyorsan lehet keresni: `b" \"<>`".contains(&b)`.
---
A kódolásnál a `format!("%{b:02X}")` két jegyű, nagybetűs hexát ad (`%0A`, `%C5`). Ami nem kódolandó, az ASCII, ezért `b as char` biztonságosan visszaadja.
:::

:::solution
```rust
//! Százalékos kódolás (percent-encoding): a URL-ben nem megengedett bájtok `%XX` alakban.

/// `%XX` → bájt. Ami nem érvényes `%XX`, az változatlanul marad (a szabvány is így kéri).
pub fn percent_decode(input: &str) -> Vec<u8> {
    let bytes = input.as_bytes();
    let mut out = Vec::with_capacity(bytes.len());
    let mut i = 0;
    while i < bytes.len() {
        let hex = bytes
            .get(i + 1..i + 3)
            .and_then(|h| std::str::from_utf8(h).ok());
        match hex.and_then(|h| u8::from_str_radix(h, 16).ok()) {
            Some(byte) if bytes[i] == b'%' => {
                out.push(byte);
                i += 3;
            }
            _ => {
                out.push(bytes[i]);
                i += 1;
            }
        }
    }
    out
}

/// Melyik bájtot kell kódolni? A szabvány „kódolási halmazai” (percent-encode sets) a URL
/// egyes részeire mások: a `?` az útvonalban kódolandó, a lekérdezésben nem.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum EncodeSet {
    /// A vezérlőkarakterek és minden nem ASCII bájt
    C0Control,
    /// A `#` utáni részlet (fragment)
    Fragment,
    /// A `?` utáni lekérdezés (query)
    Query,
    /// A lekérdezés a speciális sémákban (http, https …): az `'` is kódolandó
    SpecialQuery,
    /// Az útvonal egy szegmense
    Path,
}

impl EncodeSet {
    fn contains(self, b: u8) -> bool {
        let c0 = !(0x20..0x7F).contains(&b);
        match self {
            EncodeSet::C0Control => c0,
            EncodeSet::Fragment => c0 || b" \"<>`".contains(&b),
            EncodeSet::Query => c0 || b" \"#<>".contains(&b),
            EncodeSet::SpecialQuery => c0 || b" \"#<>'".contains(&b),
            EncodeSet::Path => c0 || b" \"#<>?`{}".contains(&b),
        }
    }
}

/// A szöveg UTF-8 bájtjai, a halmazba tartozók `%XX` alakban (nagybetűs hexa).
pub fn percent_encode(input: &str, set: EncodeSet) -> String {
    let mut out = String::with_capacity(input.len());
    for &b in input.as_bytes() {
        if set.contains(b) {
            out.push_str(&format!("%{b:02X}"));
        } else {
            out.push(b as char);
        }
    }
    out
}
```
:::

A `Some(byte) if bytes[i] == b'%'` egy **őrfeltételes** (guarded) minta: csak akkor illik, ha a hexa jegyek is rendben vannak, és az aktuális bájt tényleg `%`. Minden más eset a `_` ágba megy.

:::why Mélyvíz: a `+` a lekérdezésben
Ha egy HTML-űrlapot (`<form>`) küldesz el, a böngésző a mezőket `application/x-www-form-urlencoded` formában kódolja: `nev=Rozsda+B%C3%B6ng%C3%A9sz%C5%91`. Itt a szóközből `+` lesz, nem `%20`. Ez egy régebbi, a URL-szabványtól független szokás, és csak a lekérdezésre meg az űrlap törzsére vonatkozik. Az útvonalban a `+` egyszerűen egy `+`. Ezért van külön `percent_decode` és űrlap-visszafejtés: a lenti gyakorlófeladat épp ez utóbbi.
:::
