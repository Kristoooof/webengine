:::goal
A dobozok a helyükre kerülnek: kiszámolod a **pozíciójukat** és a **magasságukat**, és a blokk-gyerekek egymás alá rendeződnek. Közben megírod a CSS egyik leghíresebb furcsaságát, az **összeomló margókat** (margin collapsing).
:::

## Kívülről befelé, belülről kifelé

Az előző leckében láttad: a szélesség **kívülről befelé** számolódik. A szülő tudja, milyen széles, és ebből adja a gyereknek a helyet.

A magasság épp fordítva megy: **belülről kifelé**. Egy `<div>` olyan magas, amilyen a tartalma. Ezt csak akkor tudjuk, ha a gyerekei már elkészültek. Egy blokk layoutja ezért négy lépés, ebben a sorrendben:

1. **szélesség** (05-05): ehhez a szülő szélessége kell
2. **pozíció**: hol a tartalom bal felső sarka
3. **gyerekek**: egymás alá, mindegyik a saját négy lépésével (rekurzió!)
4. **magasság**: az utolsó gyerek aljáig tart

```text Ábra
layout_block(html)
├─ szélesség, pozíció
├─ gyerekek:
│  └─ layout_block(body)
│     ├─ szélesség, pozíció
│     ├─ gyerekek: layout_block(h1), layout_block(p), …
│     └─ magasság = az utolsó gyerek alja − a tartalom teteje
└─ magasság
```

## A pozíció

A `layout_block` megkapja, hova kerüljön a doboz **margódobozának** bal felső sarka: `(x, y)`. A tartalom ettől jobbra és lejjebb van, a margó, a keret és a kitöltés vastagságával:

```text Ábra
(x, y) ┌──────────── margó ────────────┐
       │   ┌──────── keret ─────────┐  │
       │   │  ┌──── kitöltés ────┐  │  │
       │   │  │ (content.x,      │  │  │
       │   │  │  content.y)      │  │  │
```

`content.x = x + margin.left + border.left + padding.left`, és ugyanígy felül.

:::warn A százalékos függőleges margó a SZÉLESSÉGHEZ mér
A `padding-top: 10%` nem a szülő magasságának 10%-a, hanem a **szélességének**. Ez elsőre hibának tűnik, de logikus: a magasság a 3. lépésben derül ki, a margók viszont már a 2. lépésben kellenek. A szélesség addigra biztosan megvan. (Ezt a trükköt sokáig használták fix arányú dobozokhoz: `padding-top: 56.25%` egy 16:9-es videónak.)
:::

## Egymás alá: a kurzor

A gyerekek elhelyezése olyan, mint a szövegszerkesztőben a kurzor. A kurzor a szülő tartalmának tetején indul. Minden gyerek a kurzorhoz kerül, aztán a kurzor lecsúszik a gyerek **margódobozának aljára**. A végén a szülő tartalmának magassága: ameddig a kurzor eljutott.

## Összeomló margók

Két bekezdés, mindkettőn `margin: 16px 0`. Mekkora köztük a távolság? Józan ésszel 16 + 16 = 32px. A CSS szerint viszont **16px**: a szomszédos függőleges margók **összeomlanak** (collapse), és a kettő közül a **nagyobbik** marad.

:::compare Összeomló margók
@@ CSS
```css
p { margin: 16px 0; }
h2 { margin: 20px 0; }
/* <p>…</p><h2>…</h2>: a távolság max(16, 20) = 20px, nem 36px */
```
@@ C#
A WPF `Margin` és a WinForms `Margin` **nem** omlik össze: két `StackPanel`-gyerek között a margók összeadódnak. A CSS a nyomdai hagyományt követi: egy bekezdés „körül legyen ennyi hely”, nem „mellette”.
@@ Érettségi
Két szomszédos szakasz `[a, a+m1]` és `[b−m2, b]` hossza helyett az átfedésük számít. Ha a két margó egymásra csúszhat, a közös rész a rövidebbik, és a távolság a hosszabbik lesz: `m1 + m2 − min(m1, m2) = max(m1, m2)`.
:::

A megvalósítás egy kivonás. Ha az előző gyerek alsó margója és a mostani felső margója közül a kisebbik `overlap`, akkor a következő gyerek nem a kurzorhoz, hanem `overlap`-pel feljebb kerül:

```text Ábra
előző doboz alja ─────────────────
  alsó margó: 10  ┐
                  │ overlap = min(10, 20) = 10
  felső margó: 20 ┘ ← a margók egymásra csúsznak
következő doboz teteje ───────────   távolság: 20
```

:::note Amit kihagyunk
A szabvány a negatív margókat is összeomlasztja (azoknál a legnegatívabb nyer), és a **szülő és az első gyerek** margója is összeomlik. A Rozsda csak a pozitív, szomszédos testvérmargókat kezeli: a `.max(0.0)` biztosítja, hogy negatív margónál ne legyen „átfedés”. A szülő-gyerek esetet lent, a mélyvízben nézzük meg.
:::

## A megadott magasság

Ha a stílusban `height: 40px` áll, az nyer: a tartalom magassága 40 lesz, akkor is, ha a gyerekek magasabbak (ilyenkor kilógnak). A százalékos magassággal nem foglalkozunk: az csak akkor működik, ha a szülő magassága előre ismert, és ez ritka.

```rust
/// A függőleges margók, keretek, kitöltés, és a tartalom bal felső sarka.
/// Az `(x, y)` a margódoboz bal felső sarka.
pub fn calculate_position(b: &mut LayoutBox, x: f32, y: f32, cb_width: f32) {
    let s = &b.style;
    let d = &mut b.dimensions;
    // A függőleges auto margó 0, és a százalék is a SZÉLESSÉGHEZ mér.
    d.margin.top = s.margin.top.resolve(cb_width).unwrap_or(0.0);
    d.margin.bottom = s.margin.bottom.resolve(cb_width).unwrap_or(0.0);
    d.padding.top = s.padding.top.resolve(cb_width).unwrap_or(0.0);
    d.padding.bottom = s.padding.bottom.resolve(cb_width).unwrap_or(0.0);
    d.border.top = s.border_width.top;
    d.border.bottom = s.border_width.bottom;
    d.content.x = x + d.margin.left + d.border.left + d.padding.left;
    d.content.y = y + d.margin.top + d.border.top + d.padding.top;
}

/// A blokk-gyerekek egymás alá kerülnek. A szomszédos függőleges margók összeomlanak:
/// két doboz között a nagyobbik margó marad, nem az összegük.
fn layout_children(b: &mut LayoutBox) {
    let content = b.dimensions.content;
    let mut cursor = content.y;
    let mut previous_margin = 0.0_f32;
    for child in &mut b.children {
        let margin_top = child.style.margin.top.resolve(content.width).unwrap_or(0.0);
        let overlap = previous_margin.min(margin_top).max(0.0);
        layout_block(child, content.x, cursor - overlap, content.width);
        cursor = child.dimensions.margin_box().bottom();
        previous_margin = child.dimensions.margin.bottom;
    }
    b.dimensions.content.height = cursor - content.y;
}

/// Ha a magasság meg van adva pixelben, az felülírja a tartalomból számoltat.
fn calculate_height(b: &mut LayoutBox) {
    if let Size::Px(height) = b.style.height {
        b.dimensions.content.height = height;
    }
}

/// Egy blokk teljes layoutja: szélesség, pozíció, tartalom, magasság.
pub fn layout_block(b: &mut LayoutBox, x: f32, y: f32, cb_width: f32) {
    calculate_width(b, cb_width);
    calculate_position(b, x, y, cb_width);
    layout_children(b);
    calculate_height(b);
}
```
:::

:::why A szülő és a gyerek margója
Nyiss meg egy oldalt egy igazi böngészőben, amin ez áll: `<div style="background: yellow"><p>szia</p></div>`. A `p` 16px-es felső margója **nem** a sárga dobozon belül lesz, hanem fölötte! A szabvány szerint, ha a szülőnek nincs felső kerete és kitöltése, az első gyerek felső margója „kiszivárog” a szülőből, és összeomlik a szülő saját margójával.

Ez a CSS egyik legtöbbet kérdezett jelensége a Stack Overflow-n („miért van rés a div fölött?”). A megoldás egy `padding-top: 1px`, egy keret, vagy `display: flow-root`. Mindegyik megszakítja a kiszivárgást.

A Rozsdában a margó a szülőn belül marad, ezért a sárga háttér a margót is beborítja. Az igazi összeomlás egy rekurzív „mennyi margó jön fel alulról?” számítás, amit a gyerekek layoutja előtt kell elvégezni. Ha kedved van, a 05-09-es snapshot tesztekkel biztonságosan beépítheted később.
:::

```rust
fn stack_height(blocks: &[(f32, f32, f32)]) -> f32 {
    let mut total = 0.0;
    let mut previous = 0.0_f32;
    for &(top, height, bottom) in blocks {
```
