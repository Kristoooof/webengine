:::goal
Kiíratod a teljes layout-fát: minden doboz, sor és szövegdarab a helyével és méretével. Megírod az első **snapshot tesztedet**, ami egy egész oldal layoutját rögzíti. Ha később valami elcsúszik, egy pixelnyit is, ez a teszt szólni fog.

## Miért kell kiírás?

A layout számok tömege. Egy kis oldalon is több tucat téglalap van, és ha egy rossz, a képernyőn csak annyit látsz, hogy „valami furcsa”. A 3. modulban a `--dom`, a 4.-ben a `--stilus` segített. Most a layout-fa következik:

```text Ábra
<html> 0,0 400×146.88
  <body> 8,8 384×130.88
    <h1> 8,29.44 384×48
      sor 8,29.44 384×48
        "Szia!" 8,29.44 160×48
    <p> 8,98.88 384×24
      sor 8,98.88 384×24
        "Egy" 8,98.88 48×24
        "kettő" 72,98.88 80×24
        "három" 168,98.88 80×24
```

Minden sor egy doboz **tartalomterülete** (`x,y szélesség×magasság`), alatta a sorai, azok alatt a darabjai. A névtelen blokkok `névtelen` néven szerepelnek.

## Olvassuk el, mint egy layout-mérnök

Ellenőrizzük a számokat fejben, a `<h1>Szia!</h1><p>Egy <b>kettő</b> három</p>` oldalon, 400px széles ablakban:

- `<body>`: a UA-stíluslap 8px margót ad neki (05-03). Ezért `8,8`, és a szélessége 400 − 2·8 = **384**.
- `<h1>`: a betűmérete 2em = 32px, a margója 0.67em = **21.44px**. Az `y` tehát 8 + 21.44 = **29.44**. A betűi 4× nagyok: „Szia!” = 5 · 32 = **160** széles, a sora **48** magas.
- `<p>`: a `h1` alsó margója (21.44) és a `p` felső margója (16) **összeomlik** (05-06): a nagyobbik marad. 29.44 + 48 + 21.44 = **98.88**.
- „kettő”: 8 + 48 („Egy”) + 16 (szóköz) = **72**.
- A `<body>` magassága: 21.44 + 48 + 21.44 + 24 + 16 = **130.88**. (A `p` alsó margója a `body`-n belül marad, mert a szülő-gyerek összeomlást kihagytuk.)

:::adhd Nem kell mindet kiszámolnod
Elég egy-két számot ellenőrizni. A snapshot teszt lényege épp az, hogy **egyszer** nézed meg alaposan, és onnantól a gép figyeli.
:::

## Snapshot tesztek

Eddig minden tesztünk egy-egy számot ellenőrzött. A **snapshot teszt** (pillanatkép-teszt) egy egész kimenetet hasonlít össze egy elmentett, „jónak elfogadott” változattal. A menete:

1. Írd meg a tesztet egy üres elvárt értékkel.
2. Futtasd: elbukik, és a hibaüzenet kiírja a tényleges kimenetet.
3. **Nézd át alaposan.** Ha jó, másold be elvártnak.
4. Ha később elbukik: vagy hibát vezettél be, vagy szándékosan változtattál. Az utóbbi esetben frissítsd.

:::compare Snapshot tesztek
@@ C#
A `Verify` könyvtár (`await Verify(result);`) ugyanezt csinálja, a pillanatképet egy `.verified.txt` fájlba menti.
@@ Python
A `syrupy` és a `pytest-snapshot` csomagok. A Jest (JavaScript) tette népszerűvé (`toMatchSnapshot()`).
@@ Rust
Az `insta` crate a szokásos eszköz: `insta::assert_snapshot!(dump)`, és a `cargo insta review` paranccsal egyenként fogadhatod el az új pillanatképeket. Most kézzel csináljuk, hogy lásd, mi van mögötte.
@@ Érettségi
Olyan, mint amikor a programod kimenetét a minta-kimenettel hasonlítod össze (`fc` Windowson, `diff` Linuxon). A tesztelő rendszerek (pl. a Mester) is így pontoznak.
:::

:::warn A lebegőpontos zaj
A `8.0 + 21.44 + 48.0 + 21.44` `f32`-ben nem pontosan 98.88, hanem `98.880005` (ezt egy valódi futás írta ki). Ha ezt írnánk ki, a pillanatkép tele lenne ilyen számokkal, és egy apró kerekítési változás is eltörné. Ezért **két tizedesjegyre kerekítünk**, és a fölösleges nullákat elhagyjuk: `21.44`, `8`, `146.88`.
:::

```rust
//! A layout-fa kiírása: minden doboz és sor a helyével és méretével.

use rozsda_core::dom::Document;
use rozsda_core::layout::{BoxKind, LayoutBox, Rect};

/// Egy szám legfeljebb két tizedesjeggyel, fölösleges nullák nélkül.
fn num(v: f32) -> String {
    let rounded = (v * 100.0).round() / 100.0;
    format!("{rounded}")
}

pub fn format_rect(r: &Rect) -> String {
    format!(
        "{},{} {}×{}",
        num(r.x),
        num(r.y),
        num(r.width),
        num(r.height)
    )
}

pub fn dump_layout(doc: &Document, root: &LayoutBox) -> String {
    let mut out = String::new();
    dump_box(doc, root, 0, &mut out);
    out
}

fn dump_box(doc: &Document, b: &LayoutBox, depth: usize, out: &mut String) {
    let indent = "  ".repeat(depth);
    let name = match b.kind {
        BoxKind::Block(id) => format!("<{}>", doc.tag_name(id).unwrap_or("?")),
        BoxKind::Anonymous => "névtelen".to_string(),
    };
    out.push_str(&format!(
        "{indent}{name} {}\n",
        format_rect(&b.dimensions.content)
    ));
    for line in &b.lines {
        out.push_str(&format!("{indent}  sor {}\n", format_rect(&line.rect)));
        for f in &line.fragments {
            out.push_str(&format!(
                "{indent}    {:?} {}\n",
                f.text,
                format_rect(&f.rect)
            ));
        }
    }
    for child in &b.children {
        dump_box(doc, child, depth + 1, out);
    }
}
```
:::

```rust
fn first_difference(expected: &str, actual: &str) -> Option<(usize, String, String)> {
    let mut e = expected.lines();
    let mut a = actual.lines();
    let mut n = 1;
    loop {
        match (e.next(), a.next()) {
            (None, None) => return None,
            (x, y) if x != y => {
                return Some((n, x.unwrap_or("").to_string(), y.unwrap_or("").to_string()));

            _ => n += 1,
        }
    }
}
```

```rust
fn first_difference(expected: &str, actual: &str) -> Option<(usize, String, String)> {
    for (i, (x, y)) in expected.lines().zip(actual.lines()).enumerate() {
        if x != y {
            return Some((i + 1, x.to_string(), y.to_string()));
        }
    }
    None
}
```

@@ teszt-lassú
```rust
fn first_difference(expected: &str, actual: &str) -> Option<(usize, String, String)> {
    let e: Vec<String> = expected.lines().map(|l| l.to_string()).collect();
    let a: Vec<String> = actual.lines().map(|l| l.to_string()).collect();
    for i in 0..e.len().max(a.len()) {
        let x = e.get(i).cloned().unwrap_or_default();
        let y = a.get(i).cloned().unwrap_or_default();
        if x != y || (i >= e.len()) != (i >= a.len()) {
            return Some((i + 1, x, y));
        }
    }
    None
}
```
