## Szövegmérés: egy fix szélességű betű

A tördeléshez tudni kell, milyen széles egy szó. Az igazi böngészők ehhez megnyitják a betűtípus-fájlt, és betűpáronként mérnek (a „Va”-ban a V és az a közelebb van, mint a „Vb”-ben). Nekünk a 2. modul **8×8 pixeles bitképes betűi** vannak, és ez most nagy könnyebbség: **minden betű egyforma széles** (monospace).

A betűméretből egy **nagyítás** (scale) lesz: a 16px-es szöveg 2×, a 32px-es `h1` 4× nagyítású.

| `font-size` | nagyítás | betű szélessége | sor magassága |
|---|---|---|---|
| 8px | 1× | 8px | 12px |
| 16px (alap) | 2× | 16px | 24px |
| 18.72px (`h3`) | 2× | 16px | 24px |
| 32px (`h1`) | 4× | 32px | 48px |

A sor magassága a betű magasságának másfélszerese: így marad hely a sorok között. (A CSS-ben ez a `line-height: normal`. A böngészők 1,2 körüli szorzót használnak, de a mi kis betűinknek a több levegő jobban áll.)

```rust
/// A 8×8-as betűk nagyítása a betűméretből: 16px → 2×, 32px → 4×.
pub fn glyph_scale(style: &ComputedStyle) -> f32 {
    (style.font_size / 8.0).round().max(1.0)
}

/// Egy karakter szélessége. A betűtípusunk fix szélességű: minden betű egyforma.

    8.0 * glyph_scale(style)
}

/// Egy sor magassága: a betű magasságának másfélszerese.

    12.0 * glyph_scale(style)
}

pub fn text_width(text: &str, style: &ComputedStyle) -> f32 {
    text.chars().count() as f32 * char_width(style)
}
```

## Mohó sortörés

A szabály egyszerű, és minden szövegszerkesztő így csinálja:

> Tedd a szót a sor végére. Ha nem fér ki, kezdj új sort, és oda tedd.

```text Ábra
max_width = 160, betű = 16px, szóköz = 16px

"egy kettő három négy"
 egy          48           sor: [egy]               pen = 48
 + kettő      48+16+80=144 ≤ 160 → [egy kettő]       pen = 144
 + három      144+16+80=240 > 160 → új sor!
              [három]                               pen = 80
 + négy       80+16+64=160 ≤ 160 → [három négy]      pen = 160
```

A `pen` (toll) a sor eddigi szélessége: ide kerül a következő szó. Három részlet:

- **A szóköz a sor elején eltűnik.** Ha a szó új sorba kerül, az előtte lévő szóköz nem kell.
- **A túl hosszú szó kilóg.** Ha egy szó magában is szélesebb a sornál, akkor is a sor elejére tesszük, különben végtelen sok üres sor lenne. (A CSS-ben az `overflow-wrap: break-word` törné el, ezt kihagyjuk.)
- **A szóköz a következő szó stílusával mér.** Az `a <b style="font-size: 32px">nagy</b>` esetén a szóköz 32px széles.

## Darabok a sorban

A sor nem szavakat tárol, hanem **darabokat** (`TextFragment`, 05-04): egy szöveget, egy téglalapot és egy elemet. Ezeket fogja kirajzolni a festő (05-10). Két szabály:

1. **Az azonos elemhez tartozó szomszédos szavak egy darabba olvadnak.** Az „egy kettő” egy darab lesz, nem kettő. Így kevesebb a darab, és a kiírás (05-09) is olvashatóbb.
2. **A sor magassága a legmagasabb darabé**, de legalább a blokk saját sormagassága. Az utóbbi az üres soroknak is ad magasságot (`<br><br>`): ezt a szabvány **strut**-nak (merevítő) hívja. A kisebb darabok a sor **aljához** igazodnak. (A szabvány az alapvonalhoz (baseline) igazít, de a mi betűinknél ez nagyjából ugyanaz.)

```text Ábra
┌─ sor (48 magas) ──────────────────────────────┐
│                ┌──────────────┐               │
│ ┌────┐         │     nagy     │      ┌──────┐ │
│ │Szia│         │   (32px)     │      │világ │ │
└─┴────┴─────────┴──────────────┴──────┴──────┴─┘
```

Ezért a darabok `y`-ja csak a sor lezárásakor derül ki: amíg a sor készül, nem tudjuk, milyen magas lesz. Az `x` is relatív (a `pen`-hez mér), és a lezáráskor toljuk el a blokk bal szélére.

## A sorépítő

Az állapot sok mindenből áll, ezért egy structba gyűjtjük. A struct referenciákat tárol (a stílusokra), ezért kell az élettartam-paraméter, mint a 03-11-es `Flattener`-nél:

```rust
/// Sorok építése balról jobbra: ha a következő szó már nem fér ki, új sor kezdődik.
struct LineBuilder<'a> {
    styles: &'a StyleMap,
    block: &'a ComputedStyle,
    x: f32,
    max_width: f32,
    top: f32,
    lines: Vec<LineBox>,
    current: Vec<TextFragment>,
    pen: f32,
}

impl LineBuilder<'_> {
    fn style(&self, node: NodeId) -> &ComputedStyle {
        self.styles.get(node).unwrap_or(self.block)
    }

    /// Lezárja az aktuális sort. A sor legalább olyan magas, mint a blokk egy sora,
    /// és a darabok a sor aljához igazodnak.
    fn finish_line(&mut self) {
        let height = self
            .current
            .iter()
            .map(|f| f.rect.height)
            .fold(line_height(self.block), f32::max);
        let mut fragments = std::mem::take(&mut self.current);
        for f in &mut fragments {
            f.rect.x += self.x;
            f.rect.y = self.top + height - f.rect.height;
        }
        self.lines.push(LineBox {
            rect: Rect {
                x: self.x,
                y: self.top,
                width: self.max_width,
                height,
            },
            fragments,
        });
        self.top += height;
        self.pen = 0.0;
    }
}
```

A `fold` egy kezdőértékből indul (a strut), és minden elemmel összevet (`f32::max`). Pythonban ez a `functools.reduce`, C#-ban az `Aggregate`. Azért nem `max()`, mert az `f32`-re nincs `Ord` (a `NaN` miatt, 04-01).

```rust
impl LineBuilder<'_> {
    // ... style és finish_line, mint fent

    fn add_word(&mut self, pieces: &[Piece], space_before: bool) {
        let mut space = if space_before && !self.current.is_empty() {
            char_width(self.style(pieces[0].node))
        } else {
            0.0
        };
        let width: f32 = pieces
            .iter()
            .map(|p| text_width(&p.text, self.style(p.node)))
            .sum();
        if !self.current.is_empty() && self.pen + space + width > self.max_width {
            self.finish_line();
            space = 0.0;
        }
        for (i, piece) in pieces.iter().enumerate() {
            let style = self.style(piece.node);
            let w = text_width(&piece.text, style);
            let h = line_height(style);
            let x = self.pen + if i == 0 { space } else { 0.0 };
            // Ugyanannak az elemnek a szomszédos szavai egy darabba olvadnak.
            match self.current.last_mut() {
                Some(last) if last.node == piece.node => {
                    if x > last.rect.right() {
                        last.text.push(' ');
                    }
                    last.text.push_str(&piece.text);
                    last.rect.width = x + w - last.rect.x;
                }
                _ => self.current.push(TextFragment {
                    rect: Rect {
                        x,
                        y: 0.0,
                        width: w,
                        height: h,
                    },
                    text: piece.text.clone(),
                    node: piece.node,
                }),
            }
            self.pen = x + w;
        }
    }
}

/// A szavakból sorok, az `(x, y)` ponttól, legfeljebb `max_width` szélesen.
pub fn break_lines(
    items: &[Item],
    styles: &StyleMap,
    block: &ComputedStyle,
    x: f32,
    y: f32,
    max_width: f32,
) -> Vec<LineBox> {
    let mut builder = LineBuilder {
        styles,
        block,
        x,
        max_width,
        top: y,
        lines: Vec::new(),
        current: Vec::new(),
        pen: 0.0,
    };
    for item in items {
        match item {
            Item::Break => builder.finish_line(),
            Item::Word {
                pieces,
                space_before,
            } => builder.add_word(pieces, *space_before),
        }
    }
    if !builder.current.is_empty() {
        builder.finish_line();
    }
    builder.lines
}

/// Egy inline tartalmú blokk sorai, és a magassága: a sorok magasságának összege.
pub fn layout_inline(b: &mut LayoutBox, doc: &Document, styles: &StyleMap) {
    let runs = collect_runs(doc, styles, &b.inline_nodes);
    let items = split_words(&runs);
    let content = b.dimensions.content;
    b.lines = break_lines(
        &items,
        styles,
        &b.style,
        content.x,
        content.y,
        content.width,
    );
    b.dimensions.content.height = b.lines.iter().map(|l| l.rect.height).sum();
}
```

:::why Miért nem a mohó tördelés a legszebb?
A mohó algoritmus minden sorban a lehető legtöbb szót viszi. Ettől az utolsó előtti sorok szépek, de egy rövid szó miatt egy sor nagyon „lyukas” lehet, főleg sorkizárt szövegnél. Donald Knuth a TeX-hez 1981-ben egy **dinamikus programozásos** algoritmust írt (Knuth–Plass): az egész bekezdést egyszerre nézi, és a sorok „csúnyaságának” összegét minimalizálja. Ez az érettségis DP-feladatok rokona: „hogyan vágd szét a sorozatot, hogy a költség minimális legyen?”

A böngészők sokáig csak mohón tördeltek, mert gyorsnak kell lenniük, és a szöveg folyton változik. A CSS-ben ma már van `text-wrap: pretty`, ami a Chrome-ban az utolsó néhány sort egy okosabb algoritmussal javítja. A `text-wrap: balance` pedig egyforma hosszú sorokat próbál adni a címeknek.

```rust
        }
```
```rust
        pen += w;
        count += 1;
    }
    if count > 0 {
        lines.push(count);
    }
    lines
}
```
:::
