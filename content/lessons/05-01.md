## Minden elem egy doboz

Nyiss meg egy weboldalt a Chrome-ban, kattints jobb gombbal valamire, és válaszd a *Vizsgálat* (Inspect) menüpontot. A jobb oldalon, a *Computed* fülön látsz egy ilyen ábrát:

```text Ábra
┌──────────────────────── margin (margó) ─────────────────────────┐
│                                                                 │
│   ┌─────────────────── border (keret) ───────────────────────┐  │
│   │                                                          │  │
│   │   ┌─────────────── padding (kitöltés) ────────────────┐  │  │
│   │   │                                                   │  │  │
│   │   │   ┌─────────── content (tartalom) ────────────┐   │  │  │
│   │   │   │                                           │   │  │  │
│   │   │   │     itt van a szöveg, 300 × 48 pixel      │   │  │  │
│   │   │   │                                           │   │  │  │
│   │   │   └───────────────────────────────────────────┘   │  │  │
│   │   └───────────────────────────────────────────────────┘  │  │
│   └──────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

| Réteg | Angolul | Mire való | Látszik? |
|---|---|---|---|
| Tartalom | content | a szöveg, a gyerekek | igen |
| Kitöltés | padding | hely a tartalom és a keret között | a háttérszín kitölti |
| Keret | border | egy vonal a doboz körül | igen, saját színe van |
| Margó | margin | távolság a szomszédoktól | soha, mindig átlátszó |

Minden rétegnek **négy oldala** van (fent, jobbra, lent, balra), és mindegyik lehet más vastag. A `padding: 10px 20px` például fent és lent 10, jobbra és balra 20 pixel.

## Négy téglalap egy dobozban

Ha tudjuk, hol a tartalom, és milyen vastag a kitöltés, a keret és a margó, akkor mind a négy réteg külső téglalapját ki tudjuk számolni. Kívülről befelé:

- **margódoboz** (margin box): a teljes hely, amit a doboz elfoglal a szomszédai között
- **keretdoboz** (border box): eddig ér a háttér és a keret
- **kitöltésdoboz** (padding box): a keret belső széle
- **tartalomdoboz** (content box): a tartalom helye

Mindegyik az előzőből jön egy lépéssel: a téglalapot minden oldalán kitoljuk a következő réteg vastagságával. Bal oldalon és fent az `x` és az `y` csökken, a szélesség és a magasság pedig mindkét oldal vastagságával nő.

:::note A koordináták
A képernyőn az `(0, 0)` pont a **bal felső** sarok, és az `y` **lefelé** nő. Ezt már a 02-04-ben, a `Canvas`-nál is láttad. A matekórán megszokott koordináta-rendszer fejjel lefelé van!
:::

## Generikus típus: `Sides<T>`

A négy oldal kell a margóhoz, a kerethez, a kitöltéshez, és a 05-02-ben a CSS-ből jövő értékekhez is (amik még lehetnek `auto` vagy százalék). Ugyanaz a szerkezet, csak más típusú értékekkel. Erre valók a **generikus típusok** (generics):

```rust
/// Valami a doboz négy oldalán: margó, keret, kitöltés.
#[derive(Debug, Clone, Copy, PartialEq, Default)]
pub struct Sides<T> {
    pub top: T,
    pub right: T,
    pub bottom: T,
    pub left: T,
}
```

A `T` egy **típusparaméter**: a `Sides<f32>` négy `f32`-t tárol, a `Sides<char>` négy karaktert. A fordító minden használt típushoz külön, ugyanolyan gyors kódot készít. A metódusoknál meg kell mondani, mit várunk a `T`-től:

```rust
impl<T: Copy> Sides<T> {
    /// Mind a négy oldal ugyanaz.
    pub fn all(value: T) -> Sides<T> {
        Sides {
            top: value,
            right: value,
            bottom: value,
            left: value,
        }
    }
}
```

A `T: Copy` egy **trait-korlát** (trait bound): ez a metódus csak olyan `T`-re létezik, ami másolható, mert a `value`-t négyszer használjuk fel.

:::compare Generikusok máshol
@@ C#
`class Sides<T> { public T Top, Right, Bottom, Left; }`. A korlát C#-ban `where T : struct`. A Rust ugyanazt a szintaxist használja, csak a korlát egy trait.
@@ C++
`template<typename T> struct Sides { T top, right, bottom, left; };`. A C++20 `concept`-jei hasonlítanak leginkább a Rust trait-korlátjaira. A különbség: a Rust már a definíciónál ellenőrzi, hogy a `T`-vel csak megengedett dolgokat csinálsz.
@@ Python
`class Sides(Generic[T])` a `typing` modulból. Pythonban ez csak a típusellenőrzőnek szól, futáskor nem számít.
:::

:::hint
Az `expanded_by` négy sor: `x: self.x - edges.left`, `y: self.y - edges.top`, és a szélességhez **mindkét** vízszintes oldal (`edges.left + edges.right`), a magassághoz mindkét függőleges hozzáadódik.
---
A `Dimensions` dobozai egymásra épülnek, mint a hagyma rétegei:
```rust
pub fn border_box(&self) -> Rect {
    self.padding_box().expanded_by(self.border)
}
```
---
Miért `self` és nem `&self` az `expanded_by`-ban? A `Rect` `Copy`, négy `f32` (16 bájt), így olcsóbb érték szerint átadni, mint referenciával. A Clippy is ezt szereti a kis `Copy` típusoknál.
:::

:::solution
```rust
//! A layout közös típusai: téglalapok, dobozok, sorok.

/// Egy téglalap a lapon, pixelben. Az `y` lefelé nő.
#[derive(Debug, Clone, Copy, PartialEq, Default)]
pub struct Rect {
    pub x: f32,
    pub y: f32,
    pub width: f32,
    pub height: f32,
}

impl Rect {
    pub fn right(&self) -> f32 {
        self.x + self.width
    }

    pub fn bottom(&self) -> f32 {
        self.y + self.height
    }

    /// A téglalap, minden oldalán kitolva a megadott vastagsággal.
    pub fn expanded_by(self, edges: Sides<f32>) -> Rect {
        Rect {
            x: self.x - edges.left,
            y: self.y - edges.top,
            width: self.width + edges.left + edges.right,
            height: self.height + edges.top + edges.bottom,
        }
    }
}

/// Egy doboz méretei a CSS doboz-modellje szerint.
#[derive(Debug, Clone, Copy, PartialEq, Default)]
pub struct Dimensions {
    /// A tartalom helye és mérete
    pub content: Rect,
    pub padding: Sides<f32>,
    pub border: Sides<f32>,
    pub margin: Sides<f32>,
}

impl Dimensions {
    pub fn padding_box(&self) -> Rect {
        self.content.expanded_by(self.padding)
    }

    pub fn border_box(&self) -> Rect {
        self.padding_box().expanded_by(self.border)
    }

    pub fn margin_box(&self) -> Rect {
        self.border_box().expanded_by(self.margin)
    }
}
```
(A `Sides<T>` és az `all` a lecke közepén van.)
:::

:::why A box-sizing háború
A CSS 1-ben (1996) a `width` a **tartalom** szélességét jelenti. Az Internet Explorer 5 viszont a **keretdoboz** szélességének vette, vagyis a kitöltést és a keretet is beleszámolta. Évekig külön CSS-t kellett írni a két értelmezésre. Végül kiderült, hogy az IE-féle a kényelmesebb: ha azt írod, `width: 300px; padding: 20px`, valószínűleg azt szeretnéd, hogy a doboz 300 pixel legyen, nem 340. Ma a `box-sizing: border-box` tulajdonsággal választhatsz, és a legtöbb weboldal az első sorában ezt írja: `* { box-sizing: border-box }`. A Rozsda (és minden böngésző alapból) a szabványos `content-box`-ot használja.
:::
