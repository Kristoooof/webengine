:::goal
Visszahozod a görgetést, de most rendesen: egy saját `Scroll` típussal, ami sosem lóg ki a lapból. Működik vele az egérgörgő, a touchpad, a nyilak, a PageUp/PageDown, a Home és az End. A raszterizáló pedig megtanulja kihagyni azt, ami nem látszik (**culling**).

## Mit jelent a görgetés?

Az ablak egy kis **nézőablak** (viewport) a hosszú lapra. A görgetés csak annyi, hogy ez a nézőablak hol áll:

```text Ábra
 lap (content_height magas)
┌──────────────────┐ 0
│                  │
├──────────────────┤ ◄── offset (a görgetés)
│    az ablak      │
│  (viewport.height│
│      magas)      │
├──────────────────┤
│                  │
│                  │
└──────────────────┘ content_height

offset: 0 és max között,  max = content_height − viewport.height  (de legalább 0)
```

Ha a lap rövidebb az ablaknál, a `max` 0, és nem lehet görgetni. Ha átméretezik az ablakot, a `max` változik, és az `offset`-et vissza kell húzni a határok közé.

A görgetés **után** csak akkor kell újrarajzolni, ha tényleg elmozdult a lap. A lap alján a „le” nyíl nem csinál semmit, és ilyenkor kár lenne rajzolni.

```rust test
    use super::*;

    #[test]
    fn stays_within_the_page() {
        let mut s = Scroll::default();
        s.set_limits(1000.0, 720.0);
        assert_eq!(s.max, 280.0);
        assert!(s.by(LINE));
        assert_eq!(s.offset, 40.0);
        assert!(s.by(1000.0));
        assert_eq!(s.offset, 280.0);
        assert!(!s.by(LINE), "a lap alján már nem mozdul");
        assert!(s.to(0.0));
        assert!(!s.by(-LINE));
    }

    #[test]
    fn short_page_does_not_scroll() {
        let mut s = Scroll::default();
        s.set_limits(300.0, 720.0);
        assert_eq!(s.max, 0.0);
        assert!(!s.by(LINE));
    }

    #[test]
    fn growing_window_pulls_the_page_back() {
        let mut s = Scroll::default();
        s.set_limits(1000.0, 500.0);
```

:::solution
```rust
//! Görgetés: hol tart az ablak a lapon, és meddig mehet.

/// Egy sornyi görgetés pixelben: egy egérgörgő-kattanás vagy egy nyíl billentyű.
pub const LINE: f32 = 40.0;

#[derive(Debug, Clone, Copy, PartialEq, Default)]
pub struct Scroll {
    /// Hány pixellel van lejjebb az ablak teteje a lap tetejénél.
    pub offset: f32,
    /// A legnagyobb `offset`: a lap magassága mínusz az ablaké, de legalább 0.
    pub max: f32,
}

impl Scroll {
    /// Új lap vagy új ablakméret: változik a határ, és az eltolás nem lóghat ki.
    pub fn set_limits(&mut self, content_height: f32, viewport_height: f32) {
        self.max = (content_height - viewport_height).max(0.0);
        self.offset = self.offset.clamp(0.0, self.max);
    }

    /// Ugrás egy adott helyre. Igaz, ha tényleg elmozdult: csak akkor kell újrarajzolni.
    pub fn to(&mut self, offset: f32) -> bool {
        let new = offset.clamp(0.0, self.max);
        let moved = new != self.offset;
        self.offset = new;
        moved
    }

    /// Görgetés `delta` pixellel (pozitív: lefelé).
    pub fn by(&mut self, delta: f32) -> bool {
        self.to(self.offset + delta)
    }
}
```
:::

## Az egérgörgő és a billentyűk

A winit kétféle görgetést küld (`MouseScrollDelta`):

- **`LineDelta(x, y)`**: egy hagyományos egérgörgő, „kattanásokban”. Egy kattanás nálunk `LINE` pixel.
- **`PixelDelta(pos)`**: touchpad vagy precíziós egér, pixelben. Így lesz sima a kétujjas görgetés.

Az előjel fordított: ha a görgőt **felfelé** forgatod, a delta pozitív, de a lap tartalma ilyenkor lefelé mozog, vagyis az `offset` **csökken**.

Az `App` két új mezőt kap: `scroll: Scroll` és `viewport: PhysicalSize<u32>` (az ablak aktuális mérete, a PageDown-hoz kell). A billentyűket egy külön metódus intézi:

```rust
    /// Görgetés, és újrarajzolás, de csak ha tényleg elmozdult.
    fn scroll_by(&mut self, delta: f32) {
        if self.scroll.by(delta) {
            self.request_redraw();
        }
    }

    fn scroll_to(&mut self, offset: f32) {
        if self.scroll.to(offset) {
            self.request_redraw();
        }
    }

    fn key(&mut self, key: &Key, event_loop: &ActiveEventLoop) {
        // Egy „oldalnyi” görgetés: az ablak magassága, kicsit átfedéssel.
        let page = self.viewport.height as f32 - 80.0;
        match key {
            Key::Named(NamedKey::Escape) => event_loop.exit(),
            Key::Named(NamedKey::ArrowDown) => self.scroll_by(LINE),
            Key::Named(NamedKey::ArrowUp) => self.scroll_by(-LINE),
            Key::Named(NamedKey::PageDown | NamedKey::Space) => self.scroll_by(page),
            Key::Named(NamedKey::PageUp) => self.scroll_by(-page),
            Key::Named(NamedKey::Home) => self.scroll_to(0.0),
            Key::Named(NamedKey::End) => self.scroll_to(self.scroll.max),
            _ => {}
        }
    }
```

A `NamedKey::PageDown | NamedKey::Space` egy **vagy-minta** egy változaton belül: a szóköz is egy oldalt lapoz, mint minden böngészőben.

```rust
                self.request_redraw();
            }
```

## Culling: ami nem látszik, azt ne rajzold

Egy hosszú oldal rajzlistájában több ezer parancs is lehet, de egyszerre csak a nézőablakba eső kis részük látszik. A raszterizáló eddig mindegyiket végigvitte: a `fill_rect` levágta a vásznon kívüli részt, de a ciklus addigra már lefutott, a szöveg betűit pedig egyenként vágta le.

A javítás egyszerű: minden parancsnak van egy befoglaló téglalapja, és ha az a nézőablakon kívül esik, kihagyjuk. Ezt hívják **culling**-nak (selejtezés). A játékmotorok ugyanígy kihagyják a kamera mögötti tárgyakat.

A `rozsda-core/src/display.rs` végére:

```rust
impl DisplayItem {
    /// A terület, amit a parancs befesthet: ezen kívül egy pixelt sem változtat.
    pub fn bounds(&self) -> Rect {
        match self {
            DisplayItem::Rect { rect, .. }
            | DisplayItem::Border { rect, .. }
            | DisplayItem::Text { rect, .. } => *rect,
        }
    }
}
```

A három változat egy közös ágban: a `|` mintákat köt össze, és mindháromban van egy `rect` mező, ugyanolyan típussal, ezért mehet egy ágba.

:::task
A `rasterize` adja vissza, hány parancsot rajzolt ki (`-> usize`), és hagyja ki azokat, amelyek a `[scroll, scroll + canvas.height]` sávon kívül vannak.
:::

```rust test
    #[test]
    fn items_outside_the_window_are_skipped() {
        let mut c = white(10, 100);
        let at = |y: f32| DisplayItem::Rect {
            rect: Rect {
                x: 0.0,
                y,
                width: 10.0,
                height: 10.0,
            },
            color: Color::BLACK,
            radius: 0.0,
        };
        let items = vec![at(0.0), at(150.0), at(500.0), at(1000.0)];
        assert_eq!(rasterize(&mut c, &items, 0), 1);
        assert_eq!(rasterize(&mut c, &items, 100), 1);
        assert_eq!(rasterize(&mut c, &items, 450), 1);
    }
```

:::solution
```rust
/// A rajzlista végrehajtása. Csak azokat a parancsokat rajzoljuk, amelyek belelógnak
/// az ablakba (culling). Visszaadja, hányat rajzolt ki.
pub fn rasterize(canvas: &mut Canvas, items: &[DisplayItem], scroll: i32) -> usize {
    let top = scroll as f32;
    let bottom = top + canvas.height as f32;
    let mut drawn = 0;
    for item in items {
        let b = item.bounds();
        if b.bottom() < top || b.y > bottom {
            continue;
        }
        drawn += 1;
        match item {
            // ... a régi ágak
        }
    }
    drawn
}
```
:::

A visszatérési érték csak a teszteknek kell. A `page.rs` `render`-je nem használja: a `raster::rasterize(…);` sor végén a `;` eldobja. A Rust ezt szó nélkül engedi, mert a `usize` nem `#[must_use]`. Egy eldobott `Result`-ra viszont figyelmeztetne a fordító (`unused_must_use`).

:::why Hogyan görget egy igazi böngésző?
A Chrome és a Firefox görgetéskor **nem** raszterizál újra mindent. A lapot előre kirajzolják csempékre (tiles) a nézőablaknál nagyobb területen, és görgetéskor a GPU csak eltolja a kész csempéket. Ez a **compositing**: egy külön szál (a compositor) végzi, ezért görgetni akkor is lehet, ha a JavaScript éppen lefagyasztja az oldal fő szálát.

A sima görgetés (smooth scrolling) egy rövid animáció: a lap nem ugrik 40 pixelt, hanem néhány képkocka alatt, lassulva csúszik oda. Ez a 13. modulban, az animációknál kerül sorra.
:::

@@ kód

@@ megoldás
```rust
fn visible(items: &[(f32, f32)], scroll: f32, viewport: f32) -> Vec<usize> {
    let bottom = scroll + viewport;
    items
        .iter()
        .enumerate()
        .filter(|&(_, &(y, h))| y + h >= scroll && y <= bottom)
        .map(|(i, _)| i)
        .collect()
}
```
