:::goal
Minden elem minden tulajdonsága értéket kap. Megtanulod, mi az **öröklődés** (*inheritance*) és a **kezdőérték** (*initial value*), és az `em`-ből meg a `%`-ból pixel lesz. A lecke végére a `compute` függvény a kaszkád eredményéből és a szülő stílusából elkészíti az elem teljes, **számított stílusát** (*computed style*).
:::

## Mi hiányzik még?

A kaszkád egy elemhez csak azokat a tulajdonságokat adja vissza, amiket valamelyik szabály beállított. Ebben a HTML-ben:

```html
<p style="color: navy">Szia, <b>Rozsda</b>!</p>
```

a `<b>`-re egyetlen szabály sem állít színt. Mégis mindenki tudja, hogy sötétkék lesz, mint a bekezdés. Ezt az **öröklődés** csinálja: bizonyos tulajdonságok, ha senki nem állítja őket, a szülőtől öröklődnek. A többi tulajdonság ilyenkor a **kezdőértékét** kapja, amit a szabvány minden tulajdonsághoz előír.

## Öröklődő és nem öröklődő tulajdonságok

| Tulajdonság | Öröklődik? | Kezdőérték |
|---|---|---|
| `color` | igen | `black` (valójában böngészőfüggő) |
| `font-size` | igen | `medium` = 16px |
| `font-weight` | igen | `normal` = 400 |
| `display` | **nem** | `inline` |
| `background-color` | **nem** | `transparent` |

Az ökölszabály: a **szöveggel** kapcsolatos tulajdonságok öröklődnek (szín, betű, sorköz, igazítás), a **dobozzal** kapcsolatosak nem (háttér, keret, margó, méret). Ha egy `div`-nek keretet adsz, nem akarod, hogy minden bekezdése, linkje és félkövér szava is keretet kapjon.

:::note A háttér trükkje
Ha a `background-color` nem öröklődik, miért van az, hogy egy sárga hátterű `div`-ben a bekezdés is sárga hátterű? Mert a bekezdés háttere `transparent`, vagyis **átlátszik** rajta a `div` sárgája. Nem öröklődik, csak látszik.
:::

A tulajdonság értékét két kulcsszóval is irányíthatod, bármelyik tulajdonságnál:

- **`inherit`**: „vedd a szülőét”, akkor is, ha a tulajdonság magától nem öröklődik (pl. `background-color: inherit`).
- **`initial`**: „vedd a kezdőértéket”, akkor is, ha egyébként öröklődne (pl. `color: initial` → fekete).

## A döntés minden tulajdonságnál

```text Ábra
           van-e érték a kaszkádból?
            ┌──────────┴──────────┐
           igen                  nem
            │                     │
   inherit? initial? más?    öröklődő tulajdonság?
      │        │      │        ┌──────┴──────┐
   szülőé  kezdőérték │       igen          nem
                      │        │             │
              ki kell számolni szülőé    kezdőérték
              (pl. 2em → 32px)
```

Ezt egy kis enum írja le:

```rust
/// Honnan jön egy tulajdonság értéke?
enum Source<'a> {
    Specified(&'a Value),
    Parent,
    Initial,
}
```

A `<'a>` itt is élettartam-paraméter, mint a `Flattener`-nél (03-11): a `Specified` egy referenciát tárol a kaszkád `HashMap`-jébe, és nem élheti túl azt.

## A gyökérelem

A `<html>` elemnek nincs szülője. Neki minden öröklődő tulajdonság a **kezdőértéket** örökli. Egyszerű trükk: ha nincs szülő, tegyünk úgy, mintha a szülő stílusa a csupa kezdőértékből álló stílus lenne.

## Számított érték: az `em` pixellé válik

```html
<h1>Nagy <span>még nagyobb</span></h1>
```
```css
h1   { font-size: 2em; }
span { font-size: 1.5em; }
```

A `h1` mérete a szülőé (16px) kétszerese: **32px**. A `span` mérete a **szülőé**, vagyis a `h1`-é másfélszerese: **48px**.

A kulcs: a gyerek a szülő **kiszámolt** értékét örökli (32px), nem a megadott szöveget (`2em`). Ha a `2em`-et örökölné, minden szinttel duplázódna a betű, és egy mélyen beágyazott szöveg képernyőnyi méretű lenne. Ezért a számított értékben mindig **abszolút** egység van: pixel, nem `em` és nem `%`.

| Megadott érték | Számított érték (ha a szülő 20px) |
|---|---|
| `12px` | 12px |
| `2em` | 40px |
| `150%` | 30px |
| `1.5rem` | 24px (a gyökér 16px-éhez mérve; mi egyszerűsítve mindig 16px-szel számolunk) |
| `large` | 18px |
| `larger` | 24px (a szülő 1,2-szerese) |

A `font-weight`-nél a `bold` 700, a `normal` 400, a szám önmaga. A `bolder` és a `lighter` a szülőhöz képest lép egyet a szabvány táblázata szerint (pl. a 400-ból `bolder` → 700, a 700-ból `bolder` → 900).

:::why A hat érték-szakasz
A szabvány hat lépést különböztet meg egy érték életében. **Deklarált**: minden, ami a stíluslapokban az elemre illik. **Kaszkádolt**: a kaszkád nyertese. **Megadott** (*specified*): a kaszkádolt, vagy ha nincs, az örökölt vagy a kezdőérték. **Számított** (*computed*): a relatív dolgok feloldva, amennyire layout nélkül lehet (`2em` → 32px). **Használt** (*used*): a layout után (`width: 50%` → 400px). **Tényleges** (*actual*): kerekítve, ahogy a képernyőn megjelenik. A JavaScript `getComputedStyle()` függvénye furcsa módon sokszor a *használt* értéket adja vissza, nem a számítottat. Mi most a számítottig jutunk el, a többi az 5. modul (layout) dolga.
:::

/// Egy elem számított stílusa: minden tulajdonságnak van értéke, abszolút egységekben.
#[derive(Debug, Clone, PartialEq)]
pub struct ComputedStyle {
    pub display: Display,
    pub color: Color,
    pub background_color: Color,
    /// pixelben
    pub font_size: f32,
    /// 100–900, a `normal` 400, a `bold` 700
    pub font_weight: u16,
}

impl Default for ComputedStyle {
    /// A kezdőértékek (initial values), ahogy a szabvány előírja.
    fn default() -> Self {
        ComputedStyle {
            display: Display::Inline,
            color: Color::BLACK,
            background_color: Color::TRANSPARENT,
            font_size: 16.0,
            font_weight: 400,
        }
    }
}

impl ComputedStyle {
    /// Rövid, egysoros leírás a `--stilus` kiíráshoz.
    pub fn describe(&self) -> String {
        let display = match self.display {
            Display::Inline => "inline",
            Display::Block => "block",
            Display::ListItem => "list-item",
            Display::None => "none",
        };
        format!(
            "display:{display} color:{} background:{} font-size:{}px font-weight:{}",
            self.color.to_hex(),
            self.background_color.to_hex(),
            self.font_size,
            self.font_weight
        )
    }
}

```rust
//! Számított értékek: öröklődés, kezdőértékek és a relatív egységek feloldása.

use crate::value::{Unit, Value};
use rozsda_core::style::{ComputedStyle, Display};
use std::collections::HashMap;

fn source<'a>(specified: &'a HashMap<String, Value>, name: &str, inherited: bool) -> Source<'a> {
    match specified.get(name) {
        Some(Value::Keyword(k)) if k == "inherit" => Source::Parent,
        Some(Value::Keyword(k)) if k == "initial" => Source::Initial,
        Some(v) => Source::Specified(v),
        None if inherited => Source::Parent,
        None => Source::Initial,
    }
}

/// A `font-size` pixelben. Az `em` és a `%` a szülő betűméretéhez képest értendő.
pub fn font_size_px(value: &Value, parent: f32) -> f32 {
    match value {
        Value::Length(n, Unit::Px) => *n,
        Value::Length(n, Unit::Em) => n * parent,
        Value::Length(n, Unit::Rem) => n * 16.0,
        Value::Percentage(p) => p / 100.0 * parent,
        Value::Keyword(k) => match k.as_str() {
            "xx-small" => 9.0,
            "x-small" => 10.0,
            "small" => 13.0,
            "medium" => 16.0,
            "large" => 18.0,
            "x-large" => 24.0,
            "xx-large" => 32.0,
            "larger" => parent * 1.2,
            "smaller" => parent / 1.2,
            _ => parent,
        },
        _ => parent,
    }
}

pub fn font_weight(value: &Value, parent: u16) -> u16 {
    match value {
        Value::Number(n) => *n as u16,
        Value::Keyword(k) => match k.as_str() {
            "normal" => 400,
            "bold" => 700,
            "bolder" if parent < 400 => 400,
            "bolder" if parent < 600 => 700,
            "bolder" => 900,
            "lighter" if parent < 600 => 100,
            "lighter" if parent < 800 => 400,
            "lighter" => 700,
            _ => parent,
        },
        _ => parent,
    }
}

pub fn compute(
    specified: &HashMap<String, Value>,
    parent: Option<&ComputedStyle>,
) -> ComputedStyle {
    let initial = ComputedStyle::default();
    let parent = parent.unwrap_or(&initial);

    let display = match source(specified, "display", false) {
        Source::Specified(Value::Keyword(k)) => match k.as_str() {
            "block" => Display::Block,
            "list-item" => Display::ListItem,
            "none" => Display::None,
            _ => Display::Inline,
        },
        Source::Parent => parent.display,
        _ => initial.display,
    };
    let color = match source(specified, "color", true) {
        Source::Specified(Value::Color(c)) => *c,
        Source::Parent => parent.color,
        _ => initial.color,
    };
    let background_color = match source(specified, "background-color", false) {
        Source::Specified(Value::Color(c)) => *c,
        Source::Parent => parent.background_color,
        _ => initial.background_color,
    };
    let font_size = match source(specified, "font-size", true) {
        Source::Specified(v) => font_size_px(v, parent.font_size),
        Source::Parent => parent.font_size,
        Source::Initial => initial.font_size,
    };
    let font_weight = match source(specified, "font-weight", true) {
        Source::Specified(v) => font_weight(v, parent.font_weight),
        Source::Parent => parent.font_weight,
        Source::Initial => initial.font_weight,
    };
    ComputedStyle {
        display,
        color,
        background_color,
        font_size,
        font_weight,
    }
}

fn font_size_px(value: &str, parent: f32) -> Option<f32> {
    let table: Vec<(String, f32)> = vec![
        ("xx-small".to_string(), 9.0),
        ("x-small".to_string(), 10.0),
        ("small".to_string(), 13.0),
        ("medium".to_string(), 16.0),
        ("large".to_string(), 18.0),
        ("x-large".to_string(), 24.0),
        ("xx-large".to_string(), 32.0),
        ("larger".to_string(), parent * 1.2),
        ("smaller".to_string(), parent / 1.2),
    ];
    if let Some((_, v)) = table.iter().find(|(k, _)| k == value) {
        return Some(*v);
    }
    let units: Vec<(String, Box<dyn Fn(f32) -> f32>)> = vec![
        ("px".to_string(), Box::new(|n| n)),
        ("rem".to_string(), Box::new(|n| n * 16.0)),
        ("em".to_string(), Box::new(move |n| n * parent)),
        ("%".to_string(), Box::new(move |n| n / 100.0 * parent)),
    ];
    for (unit, f) in &units {
        if value.ends_with(unit.as_str()) {
            let number: String = value.chars().take(value.chars().count() - unit.chars().count()).collect();
            return number.parse::<f32>().ok().map(|n| f(n));
        }
    }
    None
}
```

:::quiz
A `<div style="background-color: yellow"><p>Szia</p></div>` esetén mi a `p` számított `background-color`-ja?
- [ ] `yellow`, mert örökli a `div`-től
- [x] `transparent`, mert a háttérszín nem öröklődik. Csak átlátszik rajta a `div` sárgája
- [ ] `white`
> A háttér doboz-tulajdonság, nem öröklődik. A kezdőértéke `transparent`, ezért a szülő háttere látszik át.
:::

:::quiz
A `h1 { font-size: 2em }` és a `h1 span { font-size: 2em }` mellett mekkora lesz egy `h1`-beli `span` betűmérete, ha a `body` 16px?
- [ ] 32px
- [x] 64px
- [ ] 16px
> A `h1` 2·16 = 32px. A `span` a szülője (a `h1`) **számított** értékének kétszerese: 2·32 = 64px.
:::

:::card
K: Mi a különbség az öröklődő és a nem öröklődő tulajdonságok között?
V: Ha egyetlen szabály sem állítja őket, az öröklődők (pl. `color`, `font-size`) a szülő számított értékét veszik át, a nem öröklődők (pl. `display`, `background-color`) a kezdőértéküket.
:::

:::card
K: Miért pixelben van a számított `font-size`, és nem `em`-ben?
V: Mert a gyerekek a számított értéket öröklik. Ha az `em` öröklődne, minden szinten újra megszorzódna, és a betűméret szintről szintre nőne.
:::
