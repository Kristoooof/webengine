## Egy teszt, ami rossz okból zöld

Próbáld ki ezt a kis oldalt (`oldalak/body.html`):

```html
<body style="background: navy" class="lap"><p>Szia
```

Egy igazi böngészőben sötétkék a háttér. A Rozsdában fehér. Nézzük meg a DOM-ot:

```powershell
cargo run -p rozsda-browser -- oldalak/body.html --dom
```

```text Kimenet
| <html>
|   <head>
|   <body>
|     <p>
|       "Szia"
```

A `<body>`-nak nincs attribútuma. A 3. modulban a fa-építő a `<body>`-t az `ensure_body`-val hozza létre, akár a `<body>` tag hozza oda, akár egy `<p>` kényszeríti ki. Mindkét esetben **üres** attribútumlistával (`vec![]`). A tag saját attribútumai elvesznek.

És itt a meglepő rész: van egy tesztünk, ami pont ezt az esetet nézi. A 06-01-es `body_background_is_not_in_the_list`:

```rust
        let items = list_of("<body style=\"background: #00ff00\"></body>", false);
        assert!(items.is_empty());
```

Azt akarta ellenőrizni, hogy a `body` háttere nem kerül a rajzlistába, mert a vászon kapja. A teszt zöld volt, de **nem ezért**: a `body`-nak egyszerűen nem volt háttere, mert az attribútum elveszett. A teszt akkor is átment volna, ha a festő hibásan kirajzolja a `body` hátterét.

:::adhd Ez nem a te hibád
Minden komoly projektben vannak ilyen tesztek. A tanulság nem az, hogy „rosszul tesztelsz”, hanem egy jó szokás: ha egy új teszt **elsőre** zöld, egy pillanatra gyanakodj. A legegyszerűbb ellenőrzés, hogy szándékosan elrontod a kódot, és megnézed, hogy a teszt tényleg pirosra vált-e. Ennyi.
:::

## Mit mond a szabvány?

A WHATWG fa-építő szabálya az „in body” állapotban: ha jön egy `<body>` (vagy `<html>`) start tag, és az elem már létezik, akkor **minden olyan attribútumot, ami még nincs rajta, rá kell tenni**. A meglévőket nem írjuk felül. Ezért egy `<body class="a"><p>x<body id="b" class="c">` után a `body`-n `class="a"` és `id="b"` lesz.

## Te jössz

:::task
1. A `rozsda-core/src/dom.rs`-ben, a `Document`-ben: `pub fn add_missing_attrs(&mut self, id: NodeId, attrs: Vec<(String, String)>)`. Ha a csomópont elem, minden olyan párt tegyen az attribútumai közé, aminek a neve még nincs ott.
2. A `rozsda-html/src/tree_builder.rs` `start_tag` függvényében a `"html"` és a `"body"` ág az elem létrehozása (`ensure_html`, `ensure_body`) **után** tegye rá az attribútumokat.
:::

```rust test
    #[test]
    fn body_attributes_are_kept() {
        let doc = parse_document(
            "<body style=\"background: navy\" class=\"a\"><p>x<body id=\"b\" class=\"c\">",
        );
        let body = doc.element(doc.find_first("body").unwrap()).unwrap();
        assert_eq!(body.attr("style"), Some("background: navy"));
        assert_eq!(body.attr("class"), Some("a"));
        assert_eq!(body.attr("id"), Some("b"));
    }
```

:::hint
Az `add_missing_attrs`-ban egy `if let` kell, ami **módosítható** referenciát ad az elem adataira:
```rust
if let NodeData::Element(e) = &mut self.nodes[id.0].data {
    for (name, value) in attrs {
        // …ha az `e.attr(&name)` `None`, akkor push
    }
}
```
A `for (name, value) in attrs` **elfogyasztja** (move) a vektort: a párokat nem kell klónozni, egyszerűen átkerülnek az elemre.
---
A fa-építőben a `"body"` ág:
```rust
"body" => {
    self.ensure_body();
    if let Some(body) = self.body {
        self.doc.add_missing_attrs(body, attrs);
    }
}
```
A `self.body` `Option<NodeId>`, és az `ensure_body` után biztosan `Some`. Az `if let` mégis tisztább, mint egy `unwrap`.
:::

:::solution
```rust
    /// Új attribútumok egy meglévő elemre. Ami már megvan, az marad.
    pub fn add_missing_attrs(&mut self, id: NodeId, attrs: Vec<(String, String)>) {
        if let NodeData::Element(e) = &mut self.nodes[id.0].data {
            for (name, value) in attrs {
                if e.attr(&name).is_none() {
                    e.attrs.push((name, value));
                }
            }
        }
    }
```

A `start_tag`-ben:

```rust
            // A szabvány szerint a `<html>` és a `<body>` attribútumai a már meglévő
            // elemre kerülnek, akkor is, ha a parser maga hozta létre.
            "html" => {
                self.ensure_html();
                if let Some(html) = self.html {
                    self.doc.add_missing_attrs(html, attrs);
                }
            }
```

```rust
            "body" => {
                self.ensure_body();
                if let Some(body) = self.body {
                    self.doc.add_missing_attrs(body, attrs);
                }
            }
```
:::

:::exercise Hiányzó attribútumok
@@ feladat
Az `elem` egy elem attribútumai, a `uj` egy második start tag attribútumai. Add vissza az egyesített listát: az `elem` eredeti sorrendjében, utána az `uj`-ból azok, amelyeknek a neve még nem szerepel (az `uj` sorrendjében, és ha az `uj`-ban kétszer szerepel egy név, csak az első). A meglévő értékeket nem írjuk felül.
@@ kód
```rust
fn add_missing(elem: &[(&str, &str)], uj: &[(&str, &str)]) -> Vec<(String, String)> {
    todo!()
}
```
@@ megoldás
```rust
fn add_missing(elem: &[(&str, &str)], uj: &[(&str, &str)]) -> Vec<(String, String)> {
    let mut out: Vec<(String, String)> = elem
        .iter()
        .map(|&(n, v)| (n.to_string(), v.to_string()))
        .collect();
    for &(name, value) in uj {
        if !out.iter().any(|(n, _)| n == name) {
            out.push((name.to_string(), value.to_string()));
        }
    }
    out
}
```
@@ magyarázat
Az attribútumok száma kicsi (egy elemen ritkán van tíznél több), ezért egy lineáris keresés a vektorban gyorsabb, mint egy `HashSet` felépítése. A HTML-parserek a gyakorlatban így is csinálják.
@@ esetek
```rust
add_missing(&[("class", "a")], &[("id", "b"), ("class", "c")])
add_missing(&[], &[("style", "x")])
add_missing(&[("style", "x")], &[])
add_missing(&[("id", "1")], &[("id", "2"), ("lang", "hu"), ("lang", "en")])
add_missing(&[("a", "1"), ("b", "2")], &[("b", "3"), ("a", "4")])
```
@@ mérés
```rust
let elem = [("class", "kartya"), ("id", "elso")];
let uj = [("id", "masodik"), ("style", "color: red"), ("lang", "hu"), ("class", "x")];
---
(0..2000).map(|_| add_missing(std::hint::black_box(&elem), std::hint::black_box(&uj)).len()).sum::<usize>()
```
@@ teszt-rossz
```rust
fn add_missing(elem: &[(&str, &str)], uj: &[(&str, &str)]) -> Vec<(String, String)> {
    let mut out: Vec<(String, String)> = elem
        .iter()
        .map(|&(n, v)| (n.to_string(), v.to_string()))
        .collect();
    for &(name, value) in uj {
        match out.iter_mut().find(|(n, _)| n == name) {
            Some(existing) => existing.1 = value.to_string(),
            None => out.push((name.to_string(), value.to_string())),
        }
    }
    out
}
```

:::quiz
Mit jelent, hogy egy teszt „rossz okból zöld”?
- [ ] Hogy a teszt lassú
- [x] Hogy átmegy, de nem azért, amit ellenőrizni akart: egy másik hiba miatt az ellenőrzött eset elő sem állt
- [ ] Hogy a teszt nevében elírás van
> Itt a `body`-nak nem volt háttere (elveszett az attribútum), ezért nem kerülhetett a listába. A festő helyes viselkedését a teszt valójában nem ellenőrizte.

:::quiz
Mi lesz a `body` attribútuma ebből: `<body class="a"><p>x<body id="b" class="c">`?
- [ ] `class="c"`
- [ ] `id="b" class="c"`
- [x] `class="a" id="b"`
> A második `<body>` tag csak a hiányzó attribútumokat teszi hozzá (`id`), a meglévőt (`class`) nem írja felül.
