:::goal
Lecseréled a minifb-t két profi crate-re. A **winit** nyitja meg az ablakot és hozza az eseményeket, a **softbuffer** pedig kiteszi a pixeleidet a képernyőre. A böngésző ettől **eseményvezérelt** lesz: csak akkor rajzol, ha kell. Ha átméretezed az ablakot, a szöveg újratördelődik az új szélességre.

## Mi a baj a minifb-vel?

A minifb a 2. modulban tökéletes volt: egy ablak, egy pixeltömb, egy ciklus. A ciklusa viszont **másodpercenként 60-szor** rajzol akkor is, ha semmi nem változott. A laptopod ventilátora ezt meghallja. Átméretezni sem lehet rendesen az ablakot.

A nagy Rust-alkalmazások (az Alacritty terminál, a Bevy játékmotor, a Servo böngésző) a **winit**-et használják. Ez egy eseményhurok (event loop) a rendszer ablakkezelője fölött: Windowson a Win32 üzenetsor, Linuxon az X11 vagy a Wayland, macOS-en az AppKit. A winit nem rajzol, csak ablakot nyit és eseményeket ad. A rajzoláshoz kell mellé a **softbuffer**: egy `u32`-tömb, amit a rendszer kirak az ablakba, GPU nélkül. Ugyanaz a `0x00RRGGBB` formátum, mint a `Canvas`-unké.

```text Ábra
           események                        pixelek
Windows ─────────────► winit ──► App ──► Canvas ──► softbuffer ──► ablak
(egér, billentyű,              (a mi        (a mi
 átméretezés)                   kódunk)      vásznunk)
```

## Eseményvezérelt program

A minifb-nél a mi kódunk forgatta a ciklust (`while window.is_open() { … }`). A winitnél **fordítva** van: a winit forgatja, és meghívja a mi függvényeinket, amikor történik valami. Ezt hívják **inversion of control**-nak.

:::compare Eseményhurok
@@ C#
A WinForms `Application.Run(form)` pontosan ez: a keretrendszer forgatja a hurkot, te pedig eseménykezelőket írsz (`OnPaint`, `OnResize`, `OnKeyDown`). Az `Invalidate()` kér újrarajzolást, mint nálunk a `request_redraw()`.
@@ C++
Win32-ben te írod a hurkot (`while (GetMessage(&msg, …)) DispatchMessage(&msg);`), és egy `WndProc` függvény kapja az üzeneteket (`WM_PAINT`, `WM_SIZE`). A winit ezt csomagolja be minden rendszerre.
@@ Python
A tkinter `root.mainloop()`-ja ugyanez: utána már csak a visszahívott függvényeid futnak.
@@ Rust
A winit 0.30 egy traitet vár: `ApplicationHandler`. Két kötelező metódusa a `resumed` (most lehet ablakot nyitni) és a `window_event` (történt valami az ablakkal).
:::

A fontos események:

| Esemény | Mikor jön | Mit csinálunk |
|---|---|---|
| `Resized(size)` | átméretezték az ablakot (és induláskor) | layout az új szélességgel, újrarajzolás kérése |
| `RedrawRequested` | a rendszer engedélyt ad a rajzolásra | raszterizálás, a puffer kirakása |
| `CloseRequested` | a felhasználó bezárta az ablakot | kilépés |
| `KeyboardInput` | billentyű | `Escape`: kilépés |

A `request_redraw()` nem rajzol azonnal. Csak jelzi, hogy rajzolni kellene, és a rendszer a következő alkalmas pillanatban küld egy `RedrawRequested`-et. Ha közben tízszer kérted, akkor is csak egyszer.

```rust
use crate::canvas::Canvas;
use crate::{paint, raster};
use rozsda_core::display::DisplayItem;
use rozsda_core::dom::Document;
use rozsda_core::layout::LayoutBox;
use rozsda_core::style::{Color, StyleMap};
use rozsda_core::{HtmlParser, LayoutEngine, StyleEngine};

/// A három motor, ahogy a kapcsolók kiválasztották.
pub struct Engines {
    pub html: Box<dyn HtmlParser>,
    pub css: Box<dyn StyleEngine>,
    pub layout: Box<dyn LayoutEngine>,
    pub outlines: bool,
}

pub struct Page {
    pub doc: Document,
    pub styles: StyleMap,
    pub root: LayoutBox,
    pub items: Vec<DisplayItem>,
}

impl Page {
    // ... load és resize: ezeket te írod

    pub fn title(&self) -> String {
        match self.doc.title() {
            Some(t) => format!("{t} – Rozsda"),
            None => String::from("Rozsda"),
        }
    }

    /// Az oldal háttere: a `body` háttérszíne, ha van, különben fehér.
    pub fn background(&self) -> u32 {
        self.doc
            .find_first("body")
            .and_then(|body| self.styles.get(body))
            .map(|s| s.background_color)
            .filter(|c| c.a > 0)
            .unwrap_or(Color::WHITE)
            .to_u32()
    }

    pub fn render(&self, canvas: &mut Canvas, scroll: i32) {
        canvas.clear(self.background());
        raster::rasterize(canvas, &self.items, scroll);
    }
}
```

```rust
fn layout_and_paint(
    engines: &Engines,
    doc: &Document,
    styles: &StyleMap,
    width: f32,
) -> Result<(LayoutBox, Vec<DisplayItem>), String> {
    let root = engines
        .layout
        .layout(doc, styles, width)
        .ok_or("az oldalon nincs megjeleníthető elem")?;
    let items = paint::build_display_list(doc, styles, &root, engines.outlines);
    Ok((root, items))
}

impl Page {
    /// HTML-ből kész rajzlista: parse, stílus, layout, festés.
    pub fn load(engines: &Engines, source: &str, width: f32) -> Result<Page, String> {
        let doc = engines.html.parse(source);
        let styles = engines.css.style(&doc);
        let (root, items) = layout_and_paint(engines, &doc, &styles, width)?;
        Ok(Page {
            doc,
            styles,
            root,
            items,
        })
    }

    /// Új szélesség (átméretezték az ablakot): a DOM és a stílusok maradnak, a layout újra fut.
    pub fn resize(&mut self, engines: &Engines, width: f32) -> Result<(), String> {
        let (root, items) = layout_and_paint(engines, &self.doc, &self.styles, width)?;
        self.root = root;
        self.items = items;
        Ok(())
    }

    // ... title, background, render
}
```

Most jön az `src/app.rs`. Először a mezők:

```rust
//! Az ablak: a winit hozza az eseményeket, a softbuffer viszi ki a pixeleket.

use crate::canvas::Canvas;
use crate::page::{Engines, Page};
use std::error::Error;
use std::num::NonZeroU32;
use std::rc::Rc;
use winit::application::ApplicationHandler;
use winit::dpi::PhysicalSize;
use winit::event::WindowEvent;
use winit::event_loop::{ActiveEventLoop, EventLoop};
use winit::keyboard::{Key, NamedKey};
use winit::window::{Window, WindowId};

/// Az ablak kezdő mérete. Átméretezéskor a layout az új szélességgel fut újra.
pub const WIDTH: u32 = 960;
const HEIGHT: u32 = 720;

struct App {
    engines: Engines,
    page: Page,
    window: Option<Rc<Window>>,
    surface: Option<softbuffer::Surface<Rc<Window>, Rc<Window>>>,
}
```

Két új dolog van benne:

- **`Option<…>`**: az ablak nem létezik, amikor az `App` létrejön. A winit szabálya, hogy ablakot csak a `resumed`-ben szabad nyitni (mobilon az alkalmazás felfüggesztődhet, és ilyenkor az ablak megszűnik). Addig `None`.
- **`Rc<Window>`**: az ablakra két helyen is szükség van, nálunk és a softbuffer felületénél. Az `Rc` (reference counted) egy **megosztott tulajdonú** mutató: annyi `clone`-ja lehet, amennyi kell, és az ablak akkor szabadul fel, amikor az utolsó is eltűnik. C#-ban minden objektum-referencia így viselkedik (ott a szemétgyűjtő számol), C++-ban ez a `std::shared_ptr`.

Az ablak megnyitása és a rajzolás:

```rust
impl App {
    fn request_redraw(&self) {
        if let Some(window) = &self.window {
            window.request_redraw();
        }
    }

    fn redraw(&mut self) {
        let (Some(window), Some(surface)) = (&self.window, &mut self.surface) else {
            return;
        };
        let size = window.inner_size();
        // Lekicsinyített ablaknál 0 a méret: ilyenkor nincs mit rajzolni.
        let (Some(w), Some(h)) = (NonZeroU32::new(size.width), NonZeroU32::new(size.height)) else {
            return;
        };
        surface
            .resize(w, h)
            .expect("nem sikerült átméretezni a puffert");
        let mut canvas = Canvas::new(size.width as usize, size.height as usize);
        self.page.render(&mut canvas, 0);
        let mut buffer = surface.buffer_mut().expect("nincs puffer");
        buffer.copy_from_slice(&canvas.pixels);
        buffer.present().expect("nem sikerült kirakni a képet");
    }
}

impl ApplicationHandler for App {
    /// Az alkalmazás elindult (vagy mobilon visszatért): most lehet ablakot nyitni.
    fn resumed(&mut self, event_loop: &ActiveEventLoop) {
        let attrs = Window::default_attributes()
            .with_title(self.page.title())
            .with_inner_size(PhysicalSize::new(WIDTH, HEIGHT));
        let window = Rc::new(
            event_loop
                .create_window(attrs)
                .expect("nem sikerült ablakot nyitni"),
        );
        let context = softbuffer::Context::new(window.clone()).expect("nincs softbuffer");
        let surface = softbuffer::Surface::new(&context, window.clone()).expect("nincs felület");
        self.window = Some(window);
        self.surface = Some(surface);
    }

    // ... window_event: ezt te írod
}

pub fn run(engines: Engines, page: Page) -> Result<(), Box<dyn Error>> {
    let event_loop = EventLoop::new()?;
    let mut app = App {
        engines,
        page,
        window: None,
        surface: None,
    };
    event_loop.run_app(&mut app)?;
    Ok(())
}
```

A `NonZeroU32` egy olyan `u32`, ami biztosan nem 0: a softbuffer így a **típussal** kényszeríti ki, hogy ne kérj 0 széles puffert. A `NonZeroU32::new(0)` `None`-t ad, és a `let … else` kilép.

A `let (Some(window), Some(surface)) = (…) else { return; };` két `Option`-t csomagol ki egyszerre (04-05). Ha bármelyik `None`, kilépünk.

:::solution
```rust
    fn window_event(&mut self, event_loop: &ActiveEventLoop, _id: WindowId, event: WindowEvent) {
        match event {
            WindowEvent::CloseRequested => event_loop.exit(),
            WindowEvent::KeyboardInput { event, .. }
                if event.state.is_pressed()
                    && event.logical_key == Key::Named(NamedKey::Escape) =>
            {
                event_loop.exit();
            }
            WindowEvent::Resized(size) => {
                if let Err(e) = self.page.resize(&self.engines, size.width as f32) {
                    eprintln!("Hiba: {e}");
                }
                self.request_redraw();
            }
            WindowEvent::RedrawRequested => self.redraw(),
            _ => {}
        }
    }
```

@@ feladat
Szimuláld az eseményhurkot! Kezdetben az ablak 960 széles, és rajzolni kell (az első képkocka). Az események:
- `Resized(w)`: ha a szélesség **tényleg változott**, újra kell layoutolni (`layouts += 1`), és rajzolni kell. Ha ugyanakkora maradt, nem történik semmi.
- `RedrawRequested`: ha rajzolni kell, rajzolunk (`frames += 1`), és utána már nem kell. Ha nem kell, nem rajzolunk.

Add vissza a `(layouts, frames)` párt!

```rust
fn simulate(events: &[Event]) -> (u32, u32) {
    let mut width = 960;
    let mut dirty = true;
    let (mut layouts, mut frames) = (0, 0);
    for &event in events {
        match event {
            Event::Resized(w) => {
                if w != width {
                    width = w;
                    layouts += 1;
                    dirty = true;
                }

            Event::RedrawRequested => {
```

Mi történik, ha egy eseménykezelőben háromszor hívod a `request_redraw()`-t?
- [ ] Háromszor rajzol a program
- [x] A rendszer egyetlen `RedrawRequested` eseményt küld, egyszer rajzolunk
- [ ] Hibát kapunk
> A `request_redraw` csak jelez, hogy rajzolni kellene. A rendszer összevonja a kéréseket, és akkor küld eseményt, amikor alkalmas.

Miért kell átméretezéskor újra layoutolni, de újra parse-olni nem?

> A layout a szélességből indul ki (a blokkok szélessége kívülről befelé számolódik), a DOM és a kaszkád viszont nem függ az ablak méretétől.

:::card
K: Mi a különbség a minifb ciklusa és a winit eseményhurka között?
V: A minifb-nél a mi kódunk forgatja a ciklust, és folyamatosan rajzol. A winitnél a keretrendszer forgatja, és csak eseménykor hív minket: csak akkor rajzolunk, ha kell.
:::

K: Mire jó az `Rc<T>`?
V: Megosztott tulajdon: egy értéknek több tulajdonosa lehet (`clone` csak a számlálót növeli), és akkor szabadul fel, amikor az utolsó is eltűnik. C++-ban `shared_ptr`.
