:::goal
Létrehozod a **rozsda** repót a gépeden és a GitHubon, és elkészíted az első commitodat. Mostantól minden lecke végén lesz egy mentési pont, amihez bármikor visszatérhetsz.
:::

A Git olyan, mint a játékokban a mentés: bármikor visszatölthetsz egy korábbi állapotot. A GitHub pedig a felhő, ahol a mentéseid biztonságban vannak, akkor is, ha a gépeddel történik valami. Egy hónapokig tartó projektnél ez nem opcionális.

:::adhd Commit = kis győzelem
Szokj rá, hogy **minden lecke végén** commitolsz, valami ilyen üzenettel: `lecke 01-04: ownership gyakorlás`. A GitHub-profilodon a zöld négyzetek ugyanúgy mutatják a haladásod, mint itt az aktivitás-térkép. Ha pedig hetekig kimaradsz, a `git log` megmutatja, hol hagytad abba.
:::

## Telepítés és beállítás

:::steps
- Telepítsd a Gitet: [git-scm.com](https://git-scm.com/download/win), vagy PowerShellben `winget install Git.Git`. A telepítőben minden maradhat alapértelmezett.
- Nyiss **új** terminált, és ellenőrizd: `git --version`.
- Állítsd be a neved és az e-mail-címed (ugyanazt, amivel a GitHubon regisztráltál). Lásd lent.
- Állítsd be, hogy az alapértelmezett ág neve `main` legyen.
:::

```powershell
git config --global user.name "A Neved"
git config --global user.email "te@pelda.hu"
git config --global init.defaultBranch main
```

## A rozsda repó

A böngészőmotorod egy saját repóban fog élni. (A kurzus egy másik repóban van, a kettőt nem keverjük.)

:::steps
- Lépj be a GitHubra, és jobb fent a **+** → **New repository** menüponttal hozz létre egy repót **`rozsda`** néven. Lehet privát vagy publikus. **Ne** pipáld be, hogy README-t vagy .gitignore-t hozzon létre, üresen kell.
- A gépeden hozd létre a mappát, és inicializáld a Gitet (lásd az első parancsblokkot lent).
- Hozz létre egy `README.md` fájlt a mappában (VS Code-ban: `code README.md`), és írd bele, ami lent van, a saját szavaiddal.
- Készítsd el az első commitot (második parancsblokk).
- Kösd össze a GitHubbal, és töltsd fel (harmadik parancsblokk). Az első `push`-nál felugrik egy böngészőablak a GitHub-bejelentkezéshez. Ezt a Git Credential Manager intézi, és utána megjegyzi.
- Frissítsd a GitHub-oldalt: ott kell lennie a README-nek.
:::

```powershell
cd C:\kod
mkdir rozsda
cd rozsda
git init
```

Egy egyszerű README-kezdet (írd át nyugodtan):

```text
# Rozsda

Saját böngészőmotor Rustban, nulláról.

## Miért?
<ide írd a saját szavaiddal, miért akarsz böngészőt építeni>

## Állapot
- [ ] 0.1: szöveg megjelenítése saját ablakban
```

```powershell
git add README.md
git commit -m "Kezdet: README"
```

```powershell
git remote add origin https://github.com/FELHASZNALONEV/rozsda.git
git push -u origin main
```

:::warn
A `FELHASZNALONEV` helyére a saját GitHub-felhasználóneved kerül. A pontos címet a GitHub is kiírja az üres repó oldalán („…or push an existing repository from the command line”).
:::

## A napi négy parancs

Ennyi kell a mindennapokhoz. A többit akkor tanuljuk meg, amikor szükség lesz rá.

| Parancs | Mit csinál |
|---|---|
| `git status` | Mi változott a legutóbbi commit óta? **Ha bizonytalan vagy, ezt futtasd.** |
| `git add .` | Az összes változást „becsomagolja” a következő commitba |
| `git commit -m "üzenet"` | Elkészíti a mentési pontot |
| `git push` | Feltölti a GitHubra |

És egy bónusz: a `git log --oneline` megmutatja az eddigi mentési pontokat.

:::compare Ha ismered a mentést máshonnan
@@ Játékban
**Mentés** = `git commit`. **Felhőmentés** = `git push`. **Betöltés** = `git checkout` vagy `git restore` (ezt még nem kell tudnod).
@@ Wordben
A „Verzióelőzmények” kb. a `git log`. A Git annyival tud többet, hogy *te* döntöd el, mikor legyen mentési pont, és mindegyikhez üzenetet írsz.
:::

:::task
Nézd meg, mit csinál a `git status`, ha:
1. nem változtattál semmit;
2. átírsz egy sort a README-ben, de még nem futtattad a `git add`-ot;
3. futtattad a `git add`-ot, de a commitot még nem.

Végül commitold és pushold a változást `"README pontosítás"` üzenettel.
:::

:::hint
Az 1. esetben azt kell látnod, hogy *„nothing to commit, working tree clean”*.
---
A 2. esetben a fájl pirossal jelenik meg a *„Changes not staged for commit”* alatt, a 3.-ban zölddel a *„Changes to be committed”* alatt. A Git tehát külön kezeli, mi változott, és mi kerül be a következő commitba.
:::

:::why Mi az a „staging area”?
A Gitben három „hely” van: a **munkakönyvtár** (a fájljaid), a **staging area** (amit `git add`-dal kijelöltél), és a **repó** (a commitok). Azért van köztük egy lépcső, hogy egy commitba csak az összetartozó változások kerüljenek. Például ha közben egy másik fájlt is piszkáltál, azt nem kell beletenned. Eleinte a `git add .` (minden) teljesen rendben van.
:::

:::quiz
Commitoltál, de a GitHubon nem látod a változást. Mi maradt ki?
- [ ] `git add`
- [x] `git push`
- [ ] `git status`
> A commit csak helyben, a gépeden menti el az állapotot. A GitHubra a `git push` tölti fel.
:::

:::card
K: Mi a különbség a `git commit` és a `git push` között?
V: A `commit` helyi mentési pontot készít a gépeden. A `push` feltölti a commitokat a GitHubra (a távoli repóba).
:::

:::card
K: Melyik Git-parancsot futtasd, ha nem tudod, mi a helyzet?
V: `git status`. Megmutatja, mi változott, mi van kijelölve (staged), és mi a teendő.
:::

- Elkészítetted az első commitodat és pushodat.
- Ismered a napi négy parancsot: `status`, `add`, `commit`, `push`.
