:::goal
Megépíted a **layout-fát** (layout tree): a DOM-ból és a stílusokból egy fát, amiben minden látható blokknak egy doboz felel meg, a `display: none` elemek pedig nincsenek benne. Megismered a CSS egyik rejtett szereplőjét, a **névtelen blokkot** (anonymous block box). Létrejön az új `rozsda-layout` crate.
:::

## Miért kell egy harmadik fa?

Már két fánk van: a **DOM** (mi van a dokumentumban) és a stílusok (`StyleMap`: milyen legyen minden elem). A layouthoz egy harmadik kell, mert a DOM nem pontosan azt írja le, ami a képernyőre kerül:

| A DOM-ban | A layout-fában |
|---|---|
| `<head>`, `<script>`, `display: none` | **nincs benne** |
| egy `<p>` | egy blokkdoboz |
| `<b>`, `<a>`, szöveg | inline tartalom, egy blokk sorainak része |
| szöveg egy `<div>`-ben, `<p>`-k között | egy **névtelen blokk**, ami a DOM-ban nem létezik |

A böngészőkben ez a **render tree** vagy **layout tree** (a Firefoxban *frame tree*). Minden dobozban ott lesz a méret és a hely (`Dimensions`, 05-01), amit a 05-05 és 05-06 tölt ki.

## Blokkszintű és inline tartalom

A `display` (04-10) dönti el, mi lesz egy elemből:

- `block` és `list-item` → saját **blokkdoboz**, ami egymás alá kerül a testvéreivel
- `inline` (és a szöveg-csomópontok) → **inline tartalom**: sorokba rendeződik a blokk belsejében
- `none` → semmi, a gyerekeivel együtt

## A névtelen blokk

Nézd ezt a HTML-t:

```html
<div>
  eleje
  <p>közepe</p>
  vége <i>dőlt</i>
</div>
```

A `div` gyerekei vegyesek: szöveg (inline), egy `p` (blokk), aztán megint szöveg és egy `i` (inline). A CSS egyik alapszabálya: **egy blokk gyerekei vagy mind blokkok, vagy mind inline tartalom.** Ha keverednek, a böngésző az inline részeket egy-egy **névtelen blokkba** csomagolja:

```text Ábra
DOM:                          layout-fa:
<div>                         blokk <div>
├─ "eleje"                    ├─ névtelen blokk ── "eleje"
├─ <p>                        ├─ blokk <p> ─────── "közepe"
│  └─ "közepe"                └─ névtelen blokk ── "vége ", <i>dőlt</i>
├─ "vége "
└─ <i>
   └─ "dőlt"
```

A névtelen blokknak nincs eleme, ezért nincs saját CSS-e sem: az öröklődő tulajdonságokat (szín, betű) a szülőtől kapja, minden mást a kezdőértékén hagy (nincs margója, kerete).

:::note A szóközök két `<p>` között
A `<p>a</p>⏎  <p>b</p>` esetén a két bekezdés között ott van egy `"\n  "` szöveg-csomópont a DOM-ban (a `--dom` kimenetében látod). Ebből **nem** lesz névtelen blokk: a csak szóközből álló inline tartalom eltűnik. Különben minden HTML-fájl tele lenne üres dobozokkal, és a margók (05-06) sem működnének jól.
:::

:::warn Amit kihagyunk
Mi történik, ha egy inline elemben blokk van (`<a><div>…</div></a>`)? A szabvány szerint az inline elem „kettéválik”, és a blokk kiszabadul belőle (*block-in-inline splitting*). Ez bonyolult, és ritka. A Rozsda egyszerűen az egész `<a>`-t inline tartalomnak veszi, és a `div` szövege is sorokba kerül.
:::

## A típusok

A layout-fa típusai a `rozsda-core`-ba kerülnek, ugyanazért, amiért a DOM és a stílusok: a 16. modulban a profi layout-motor (Taffy) is ezt fogja előállítani.

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum BoxKind {
    /// Egy blokkszintű elem doboza
    Block(NodeId),
    /// Névtelen blokk: az inline tartalmat csomagolja, ha mellette blokkok is vannak
    Anonymous,
}

/// A layout-fa egy doboza.
#[derive(Debug, Clone, PartialEq)]
pub struct LayoutBox {
    pub kind: BoxKind,
    pub style: ComputedStyle,
    pub dimensions: Dimensions,
    /// Blokkszintű gyerekek
    pub children: Vec<LayoutBox>,
    /// Inline tartalom (szöveg, inline elemek), ha nincsenek blokk-gyerekek
    pub inline_nodes: Vec<NodeId>,
    /// A layout után: az inline tartalom sorai
    pub lines: Vec<LineBox>,
}
```

Egy doboznak vagy `children`-je van (blokkok), vagy `inline_nodes`-a (az inline tartalom DOM-csomópontjai), soha nem mindkettő. A `lines` a 05-08-ban telik meg. Most csak a típusa kell:

```rust
/// Egy szövegdarab egy sorban. A `node` az az elem, amelyiknek a stílusával rajzoljuk.
#[derive(Debug, Clone, PartialEq)]
pub struct TextFragment {
    pub rect: Rect,
    pub text: String,
    pub node: NodeId,
}

/// Egy sor egy blokkon belül.
#[derive(Debug, Clone, PartialEq)]
pub struct LineBox {
    pub rect: Rect,
    pub fragments: Vec<TextFragment>,
}
```

## Az algoritmus

`build_box(doc, styles, id)` egy blokkszintű elemre:

1. Készíts egy `LayoutBox`-ot `BoxKind::Block(id)`-val és az elem stílusával.
2. Sorold be a gyerekeket: blokk, inline vagy kihagyandó (`display: none`, komment).
3. Ha **nincs** blokk-gyerek: minden inline gyerek az `inline_nodes`-ba kerül. Kész.
4. Ha **van**: menj végig a gyerekeken. Az inline gyerekeket gyűjtsd egy listába. Blokk-gyereknél előbb a gyűjtött listából csinálj névtelen blokkot (ha nem csak szóköz), utána jöhet a blokk rekurzívan. A végén a maradékból is.

A fa gyökere a `<html>` elem doboza.

#[cfg(test)]
mod tests {
    use super::*;
    use rozsda_core::StyleEngine;
    use rozsda_css::OwnStyleEngine;
    use rozsda_html::tree_builder::parse_document;

    /// A fa alakja röviden: `tag[inline csomópontok száma](gyerekek)`.
    fn shape(doc: &Document, b: &LayoutBox) -> String {
        let name = match b.kind {
            BoxKind::Block(id) => doc.tag_name(id).unwrap_or("?").to_string(),
            BoxKind::Anonymous => "anon".to_string(),
        };
        let mut out = name;
        if !b.inline_nodes.is_empty() {
            out.push_str(&format!("[{}]", b.inline_nodes.len()));
        }
        if !b.children.is_empty() {
            let kids: Vec<String> = b.children.iter().map(|c| shape(doc, c)).collect();
            out.push_str(&format!("({})", kids.join(" ")));
        }
        out
    }

    fn tree(html: &str) -> String {
        let doc = parse_document(html);
        let styles = OwnStyleEngine.style(&doc);
        let root = build_layout_tree(&doc, &styles).unwrap();
        shape(&doc, &root)
    }

    #[test]
    fn blocks_and_inline_content() {
        assert_eq!(tree("<p>Szia <b>Rozsda</b>!</p>"), "html(body(p[3]))");
        assert_eq!(
            tree("<h1>Cím</h1><ul><li>a<li>b</ul>"),
            "html(body(h1[1] ul(li[1] li[1])))"
        );
    }

    #[test]
    fn anonymous_blocks() {
        assert_eq!(
            tree("<div>eleje<p>közepe</p>vége <i>dőlt</i></div>"),
            "html(body(div(anon[1] p[1] anon[2])))"
        );
    }

    #[test]
    fn whitespace_and_display_none() {
        assert_eq!(
            tree("<p>a</p>\n  <p>b</p><script>x</script><span style=\"display: none\">c</span>"),
            "html(body(p[1] p[1]))"

        assert_eq!(tree("<title>T</title><p>a</p>"), "html(body(p[1]))");
    }

            font_size: 20.0,

```rust
//! A layout-fa építése: melyik elemből milyen doboz lesz.

use crate::text::is_space;
use rozsda_core::dom::{Document, NodeData, NodeId};
use rozsda_core::layout::{BoxKind, LayoutBox};
use rozsda_core::style::{ComputedStyle, Display, StyleMap};

/// A névtelen blokk stílusa: az öröklődő tulajdonságokat a szülőtől kapja, a többi kezdőérték.
pub fn anonymous_style(parent: &ComputedStyle) -> ComputedStyle {
    ComputedStyle {
        display: Display::Block,
        color: parent.color,
        font_size: parent.font_size,
        font_weight: parent.font_weight,
        ..Default::default()
    }
}

enum Child {
    Block(NodeId),
    Inline(NodeId),
    Skip,
}

fn classify(doc: &Document, styles: &StyleMap, id: NodeId) -> Child {
    match &doc.node(id).data {
        NodeData::Text(_) => Child::Inline(id),
        NodeData::Element(_) => match styles.get(id).map(|s| s.display) {
            Some(Display::Block | Display::ListItem) => Child::Block(id),
            Some(Display::Inline) => Child::Inline(id),
            Some(Display::None) | None => Child::Skip,
        },
        _ => Child::Skip,
    }
}

/// Csak összevonható szóközből álló szöveg-csomópont?
fn is_blank(doc: &Document, id: NodeId) -> bool {
    matches!(&doc.node(id).data, NodeData::Text(t) if t.chars().all(is_space))
}

/// Az összegyűlt inline tartalmat névtelen blokkba csomagolja. A csak szóközből álló
/// tartalom (pl. a sortörés két `<p>` között) eltűnik.
fn flush_anonymous(doc: &Document, parent: &mut LayoutBox, run: &mut Vec<NodeId>) {
    if run.iter().all(|&n| is_blank(doc, n)) {
        run.clear();
        return;
    }
    let mut anonymous = LayoutBox::new(BoxKind::Anonymous, anonymous_style(&parent.style));
    anonymous.inline_nodes = std::mem::take(run);
    parent.children.push(anonymous);
}

/// Egy blokkszintű elem doboza a gyerekeivel együtt. Egy blokk gyerekei vagy mind
/// blokkok, vagy mind inline tartalom: ha keverednek, az inline részek névtelen blokkba kerülnek.
pub fn build_box(doc: &Document, styles: &StyleMap, id: NodeId) -> LayoutBox {
    let style = styles.get(id).cloned().unwrap_or_default();
    let mut layout_box = LayoutBox::new(BoxKind::Block(id), style);
    let children: Vec<Child> = doc
        .children(id)
        .iter()
        .map(|&c| classify(doc, styles, c))
        .collect();

    if !children.iter().any(|c| matches!(c, Child::Block(_))) {
        layout_box.inline_nodes = children
            .iter()
            .filter_map(|c| match c {
                Child::Inline(n) => Some(*n),
                _ => None,
            })
            .collect();
        return layout_box;
    }

    let mut run = Vec::new();
    for child in children {
        match child {
            Child::Block(n) => {
                flush_anonymous(doc, &mut layout_box, &mut run);
                layout_box.children.push(build_box(doc, styles, n));
            }
            Child::Inline(n) => run.push(n),
            Child::Skip => {}
        }
    }
    flush_anonymous(doc, &mut layout_box, &mut run);
    layout_box
}

/// A gyökérelem (`<html>`) doboza, vagy `None`, ha nincs elem a dokumentumban.
pub fn build_layout_tree(doc: &Document, styles: &StyleMap) -> Option<LayoutBox> {
    let root = doc
        .children(doc.root())
        .iter()
        .copied()
        .find(|&n| doc.element(n).is_some())?;
    Some(build_box(doc, styles, root))
}
```

:::why Miért nem minden elem kap dobozt?
Egy inline elem (`<b>`, `<a>`) dobozai a böngészőkben is léteznek, de másképp: egy hosszú link akár három sorra is eltörhet, és akkor *három* darabból áll (minden sorban egy). Ezért a böngészők az inline tartalmat nem fa-dobozokként, hanem a sorokban elhelyezett **darabokként** (fragments) kezelik. Mi is így teszünk: az inline elemek a 05-07-ben szövegdarabokká válnak, és a sorokba rendezés (05-08) dönti el, hol lesznek. Emiatt nálunk egy inline elem saját margója, kerete és háttere nem jelenik meg. Ezt majd egy későbbi modulban pótoljuk.
