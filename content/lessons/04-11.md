## A stíluslap a programban: `include_str!`

A stíluslapot egy külön fájlba írjuk (`crates/rozsda-css/src/ua.css`), mert így CSS-ként szerkeszthető és olvasható. A programba a fordító teszi bele:

```rust
/// A böngésző beépített stíluslapja, fordításkor a programba ágyazva.
pub const UA_CSS: &str = include_str!("ua.css");
```

Az `include_str!` egy makró, ami **fordításkor** beolvassa a fájlt, és egy `&'static str` konstanst csinál belőle. A kész `.exe` mellé nem kell külön fájlt másolni, és futásidőben nem kell semmit beolvasni. Ha a fájl nem létezik, a program le sem fordul.

:::compare Fájl a programba ágyazva
@@ C#
Egy *embedded resource*: a `.csproj`-ban `<EmbeddedResource Include="ua.css" />`, és futásidőben `Assembly.GetManifestResourceStream`-mel olvasod ki. Rustban ez egyetlen sor, és fordításkor ellenőrzött.
@@ C++
Régen az `xxd -i` eszközzel kellett C-tömböt generálni a fájlból. A C23 hozta el az `#embed` direktívát, ami végre ugyanezt tudja.
@@ Python
A `importlib.resources.read_text(...)` futásidőben olvassa be a csomag mellé tett fájlt. Ha a fájl hiányzik, csak futáskor derül ki.
:::

## A stílusfa: `StyleMap`

Minden elemhez kell egy `ComputedStyle`. Hol tároljuk? A DOM-ot nem akarjuk módosítani (az a HTML-parser terméke, és a profi parser is DOM-ot ad majd). Egy elegáns megoldás: egy **párhuzamos tömb**, ami ugyanúgy a `NodeId`-vel indexelhető, mint a DOM arénája.

```text Ábra
Document.nodes:  [ Document | <html> | <head> | <title> | "Cím" | <body> | ... ]
StyleMap.styles: [  None    |  Some  |  Some  |  Some   | None  |  Some  | ... ]
                    0          1        2        3         4       5
```

A szöveg-csomópontoknak nincs saját stílusuk (`None`): ők a szülő elemük stílusával jelennek meg.

:::compare Párhuzamos tömbök
@@ Érettségi
Emelt infón gyakori, hogy két tömb tartozik össze: `nev[i]` és `pont[i]` ugyanarról a versenyzőről szól. A `StyleMap` pontosan ez: a `styles[i]` a `nodes[i]` stílusa.
@@ C++
A játékmotorok ECS-rendszerei (Entity Component System) is így tárolják az adatot: minden „komponens” egy külön tömb, és az entitás azonosítója az index.
:::

## Egy bejárás, szülő a gyerek előtt

A számított stílushoz kell a szülő számított stílusa. Ha a DOM-ot **preorder** sorrendben járjuk be (mint a `descendants()`, 03-07), akkor a szülő mindig előbb jön, mint a gyerekei, tehát amikor egy elemhez érünk, a szülője stílusa már kész.

```rust
for id in doc.descendants(doc.root()) {
    // 1. kaszkád: melyik deklarációk nyernek
    // 2. a szülő stílusa a StyleMap-ből
    // 3. compute: a teljes számított stílus
    // 4. beírás a StyleMap-be
}
```

Itt egy Rust-finomság is van. A `styles.get(p)` egy **kölcsönzés** a `styles`-ból, a `styles.set(…)` pedig egy **módosító** kölcsönzés. A kettő nem élhet egyszerre. Mégis lefordul, ha így írod:

```rust
let parent = doc.parent(id).and_then(|p| styles.get(p));
let style = compute(&specified, parent);
styles.set(id, style);
```

A fordító látja, hogy a `parent`-et utoljára a `compute` hívásában használod, és **ott véget ér** a kölcsönzés. A `set`-nél már nincs élő olvasó kölcsönzés. Ezt hívják *non-lexical lifetimes*-nak (NLL): a kölcsönzés nem a kapcsos zárójel végéig tart, hanem az utolsó használatig.

```rust
/// Minden elem számított stílusa, a `NodeId` szerint indexelve.
#[derive(Debug, Clone, Default)]
pub struct StyleMap {
    styles: Vec<Option<ComputedStyle>>,
}

impl StyleMap {
    pub fn new(len: usize) -> StyleMap {
        StyleMap {
            styles: vec![None; len],
        }
    }

    pub fn get(&self, id: NodeId) -> Option<&ComputedStyle> {
        self.styles.get(id.0)?.as_ref()
    }

    pub fn set(&mut self, id: NodeId, style: ComputedStyle) {
        self.styles[id.0] = Some(style);
    }
}
```
A CSS crate `lib.rs`-e:
```rust
//! A Rozsda saját CSS-motorja: tokenizer, parser, szelektorok és kaszkád.

pub mod cascade;
pub mod computed;
pub mod parser;
pub mod selector;
pub mod tokenizer;
pub mod value;

use cascade::{Origin, cascade};
use computed::compute;
use parser::{Stylesheet, parse_stylesheet};
use rozsda_core::dom::{Document, NodeId};
use rozsda_core::style::StyleMap;

/// A böngésző beépített stíluslapja, fordításkor a programba ágyazva.
pub const UA_CSS: &str = include_str!("ua.css");

/// A dokumentum `<style>` elemeinek tartalma, dokumentum-sorrendben.
pub fn author_css(doc: &Document) -> Vec<String> {
    doc.descendants(doc.root())
        .into_iter()
        .filter(|&n| doc.tag_name(n) == Some("style"))
        .map(|n| doc.text_content(n))
        .collect()
}

/// Minden elem számított stílusa. A szülő mindig a gyereke előtt jön (preorder),
/// így a szülő stílusa már kész, amikor a gyerekhez érünk.
pub fn style_document(doc: &Document, author: &[Stylesheet]) -> StyleMap {
    let ua = parse_stylesheet(UA_CSS);
    let mut sheets = vec![(Origin::UserAgent, &ua)];
    sheets.extend(author.iter().map(|s| (Origin::Author, s)));

    let mut styles = StyleMap::new(doc.len());
    for id in doc.descendants(doc.root()) {
        if doc.element(id).is_none() {
            continue;
        }
        let specified = cascade(doc, id, &sheets);
        let parent = doc.parent(id).and_then(|p| styles.get(p));
        let style = compute(&specified, parent);
        styles.set(id, style);
    }
    styles
}

/// A számított stílusok kiírása behúzással, a DevTools „Computed” paneljéhez hasonlóan.
pub fn dump_styles(doc: &Document, styles: &StyleMap) -> String {
    let mut out = String::new();
    dump_node(doc, styles, doc.root(), 0, &mut out);
    out
}

fn dump_node(doc: &Document, styles: &StyleMap, id: NodeId, depth: usize, out: &mut String) {
    let mut depth = depth;
    if let (Some(name), Some(style)) = (doc.tag_name(id), styles.get(id)) {
        out.push_str(&format!(
            "{}<{name}> {}\n",
            "  ".repeat(depth),
            style.describe()
        ));
        depth += 1;
    }
    for &child in doc.children(id) {
        dump_node(doc, styles, child, depth, out);
    }
}
```
