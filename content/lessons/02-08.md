## 1. Takarítás

:::steps
- `cargo fmt --all`: egységes formázás az egész workspace-ben.
- `cargo clippy --workspace`: olvasd el a javaslatokat, és javítsd, amit érdemes. Nem kell mindegyiket, de mindegyiknél értsd meg, mit mond.
- `cargo test`: minden zöld?
- Nézd át a `rozsda-html`-ben az 1. modulból áthozott kódot: ha van benne olyan, amit már semmi nem használ, töröld. Amit nem használsz, az nem kell.
:::

:::tip Clippy-javaslatok, amiket valószínűleg látni fogsz
- **`manual_range_contains` / `manual_is_ascii_check`**: `c >= 'a' && c <= 'z'` helyett `c.is_ascii_lowercase()`.
- **`needless_return`**: `return x;` a függvény végén. Elég az `x`.
- **`explicit_counter_loop`**: kézzel növelt számláló helyett `.enumerate()`.
- **`new_without_default`**: ha van `new()`, legyen `Default` is.

A Clippy nem hibát jelez, hanem **idiomatikusabb** megoldást javasol. Minden javaslatnál ott van egy link, ami elmagyarázza, miért jobb.
:::

## 2. Release build

```powershell
cargo build --release -p rozsda-browser
```

A kész program: `target\release\rozsda-browser.exe`.

| | `cargo build` (debug) | `cargo build --release` |
|---|---|---|
| Fordítás | gyors | lassabb |
| Futás | lassabb (akár 10–50×) | gyors |
| Hibakereséshez | igen | nem igazán |
| Túlcsordulás-ellenőrzés | pánik | körbefordul |

Egy böngészőnél a különbség drámai lesz, amikor majd igazi layoutot és JavaScriptet futtatsz. Próbáld ki: nyiss meg egy nagy HTML-fájlt mindkét buildel, és hasonlítsd össze, milyen gyorsan indul.

## 4. Verziószám és tag

A Rust-crate-ek a **semver** szerint verzióznak: `FŐ.MELLÉK.JAVÍTÁS`. A `0.x` azt jelenti, hogy „még fejlesztés alatt, bármi változhat”.

:::steps
- Mindhárom crate `Cargo.toml`-jában ellenőrizd: `version = "0.1.0"`.
- A `rozsda-core` `version()` függvénye adja vissza a `"0.1.0"`-t (a `-dev` nélkül). Tipp: a `env!("CARGO_PKG_VERSION")` makró fordításkor beilleszti a `Cargo.toml`-ban lévő verziót, így nem kell két helyen karbantartani!
- Commit, aztán tag és push (lásd lent).
:::

```powershell
git add .
git commit -m "Rozsda 0.1.0"
git tag -a v0.1.0 -m "Rozsda 0.1: az első verzió"
git push
git push --tags
```

A **tag** egy névvel ellátott, megjelölt commit. Bármikor visszatérhetsz hozzá (`git checkout v0.1.0`), és a GitHub is mutatja.

## 5. GitHub Release

:::steps
- Nyisd meg a repód GitHub-oldalát, és jobb oldalt kattints a **Releases** → **Create a new release** gombra.
- A **Choose a tag** mezőben válaszd a `v0.1.0`-t.
- Cím: `Rozsda 0.1`. A leírásba írd le, mit tud (másold a README-ből), és tedd bele a képernyőképet is.
- A **„Attach binaries”** részre húzd rá a `target\release\rozsda-browser.exe`-t, és egy `pelda.html`-t is.
- **Publish release.** 🎉
:::

:::note Automatikus kiadás
Ezt a kurzust is GitHub Actions építi és adja ki automatikusan, a telepítővel együtt. A 20. modulban ugyanezt beállítod a Rozsdának is: egy `git push --tags` után a GitHub magától lefordítja, telepítőt készít, és kiadja. Most viszont kézzel csináld, hogy lásd, mi történik.
:::

Írj egy rövid visszatekintést a lecke jegyzetébe (és ha kedved van, a README aljára is):

2. Mire vagy a **legbüszkébb**?
3. Mi az, amit **másképp** csinálnál, ha most kezdenéd?
4. Mit vársz a legjobban a 3. modulban (igazi HTML-parser és DOM)?
:::

:::why Mi jön a 0.2-ig?
A 0.1 szándékosan „csal”: nincs DOM, nincs CSS, és a layout egy egyszerű lista. A 0.2-höz (3–6. modul) minden darabot lecserélsz egy igazira: **szabványkövető HTML-tokenizer** és **DOM-fa** (3. modul), **CSS-parser és kaszkád** (4. modul), **doboz-alapú layout** (5. modul), **display list és saját raszterizáló** igazi ablakkal (6. modul). Utána a Rozsda színes, formázott oldalakat fog megjeleníteni, valódi CSS-sel. A `Page` helyére a `Document` lép, és a fordító végigvezet a refaktoráláson.
:::
