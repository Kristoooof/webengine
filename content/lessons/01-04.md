:::goal
Megérted az ownership három szabályát, és megtanulod olvasni a „value moved” hibát. Ez a Rust legfontosabb ötlete. Ha ezt érted, a nyelv többi része a helyére kerül.
:::

:::adhd Ez a lecke elsőre furcsa lehet
Ha valami nem áll össze elsőre, az teljesen normális. Az ownership olyan, mint a biciklizés: magyarázatból nem lehet megtanulni, csak csinálva. Csináld meg a feladatokat, olvasd el a hibaüzeneteket, és egy hét múlva magától fog menni. Ha elfáradtál, a felénél is nyugodtan abbahagyhatod. Írd be a jegyzetbe, hol tartasz.
:::

## A probléma, amit megold

Minden program memóriát foglal, és azt valamikor fel kell szabadítani. Erre eddig két megoldást láttál:

| | Ki szabadítja fel? | Ára |
|---|---|---|
| **C++** (`new`/`delete`, vagy `unique_ptr`) | Te, kézzel (vagy RAII-vel) | Ha elrontod: memóriaszivárgás, dupla felszabadítás, „use after free”. Ezek a böngészők biztonsági hibáinak kb. 70%-át adják. |
| **C#, Python** | A szemétgyűjtő (GC) | Kiszámíthatatlan szünetek, több memória. Egy böngészőben, ami 60 FPS-sel rajzol, ez zavaró. |
| **Rust** | A fordító dönti el, fordítási időben | Meg kell tanulni a szabályokat. Ez a lecke erről szól. |

## A három szabály

1. **Minden értéknek pontosan egy tulajdonosa (owner) van.** A tulajdonos egy változó.
2. **Egyszerre csak egy tulajdonos lehet.**
3. **Amikor a tulajdonos kikerül a hatókörből** (a `}`-nél), **az érték felszabadul** (Rust-nyelven: *drop*).

```rust
fn main() {
    let name = String::from("div");   // a name a tulajdonos, a szöveg a heapen van
    println!("{name}");
}                                     // itt a name kikerül a hatókörből → a szöveg felszabadul
```

Eddig semmi meglepő: ez olyan, mint a C++ RAII, csak automatikusan.

## Move: a tulajdon átadása

Most jön a csavar:

```rust
fn main() {
    let a = String::from("div");
    let b = a;              // a tulajdon ÁTKERÜL b-hez
    println!("{a}");        // ❌
}
```

```text
error[E0382]: borrow of moved value: `a`
 --> src/main.rs:4:15
  |
2 |     let a = String::from("div");
  |         - move occurs because `a` has type `String`, which does not implement the `Copy` trait
3 |     let b = a;
  |             - value moved here
4 |     println!("{a}");
  |               ^^^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
  |
3 |     let b = a.clone();
  |              ++++++++
```

Olvasd el lassan: *„a `String` nem `Copy`, ezért az értékadásnál **move** történt. Az `a` értéke a 3. sorban átkerült, a 4. sorban mégis használni akarod.”*

Miért csinálja ezt a Rust? Ha `a` és `b` is ugyanarra a heapen lévő szövegre mutatna, a `}`-nél **kétszer** szabadulna fel ugyanaz a memória. Ez a C++ klasszikus „double free” hibája. A Rust ezt úgy előzi meg, hogy a régi változót **érvényteleníti**.

:::compare
@@ C++
```cpp
auto a = std::make_unique<std::string>("div");
auto b = std::move(a);   // a most nullptr
std::cout << *a;         // lefordul, és futáskor összeomlik
```
A Rust move ugyanaz, mint a C++ `std::move`, csak **automatikus**, és a fordító **megakadályozza** a régi változó használatát.
@@ C#
```csharp
var a = new StringBuilder("div");
var b = a;               // mindkettő ugyanarra az objektumra mutat
a.Append("!");           // b is megváltozik, meglepetés!
```
C#-ban két referencia mutat ugyanarra az objektumra, és a GC majd valamikor eltakarítja. Rustban ez a „két név, egy objektum, mindkettő írhatja” helyzet alapból nem fordulhat elő.
:::

## Clone: ha tényleg két példány kell

```rust
let a = String::from("div");
let b = a.clone();      // mély másolat: két külön szöveg a heapen
println!("{a} {b}");    // ✅
```

A `.clone()` mindig **látható** a kódban, így tudod, hol történik drága másolás. C++-ban ez a másoló konstruktorban rejtve maradhat.

## Copy: a kis típusok másolódnak

```rust
let x = 5;
let y = x;              // másolat, mert az i32 Copy
println!("{x} {y}");    // ✅
```

Az egyszerű, fix méretű, csak a stacken élő típusok (`i32`, `u8`, `usize`, `f64`, `bool`, `char`…) **`Copy`** típusok: értékadáskor egyszerűen lemásolódnak, mert az olcsó és biztonságos. A `String`, a `Vec` és minden, ami a heapen tart adatot, **nem** `Copy`.

## Függvényhívás is move

```rust
fn print_tag(name: String) {
    println!("<{name}>");
}   // itt a name felszabadul!

fn main() {
    let tag = String::from("p");
    print_tag(tag);         // a tag tulajdona átkerül a függvényhez
    print_tag(tag);         // ❌ value used after move
}
```

Ez kényelmetlen. Hogy hogyan lehet egy szöveget átadni úgy, hogy közben **ne** add oda a tulajdonát, arról a következő lecke szól (`&`). Addig két megoldás van: `clone()`, vagy **visszaadod** a tulajdont:

```rust
fn make_start_tag(name: String) -> String {
    format!("<{name}>")     // a format! egy új String-et épít, mint a println!, csak nem ír ki
}
```

## Te jössz: fordítóhiba-vadászat

:::task
Az alábbi négy kis program **nem fordul le**. Másold be őket egyenként a `main`-be (ez az egyetlen alkalom, amikor hibás kódot másolhatsz 😄), olvasd el a hibaüzenetet, és javítsd ki **a lehető legkisebb változtatással**. Minden javításhoz írj egy kommentet (`// ...`) arról, hogy **miért** volt hibás.

**1.**
```text
let tag = String::from("section");
let copy = tag;
println!("{tag} {copy}");
```
**2.**
```text
let name = String::from("h1");
let html = make_start_tag(name);
println!("{name} -> {html}");
```
**3.**
```text
let s = String::from("p");
let t = s;
let u = s;
```
**4.**
```text
let mut names = Vec::new();
let n = String::from("li");
names.push(n);
println!("{n}");
```
(A `Vec` egy növelhető tömb, mint a C# `List<T>`. A 01-09-es leckében részletesen megnézzük.)
:::

:::hint
Mindegyik ugyanaz a hiba: egy `String`-et move után használsz. A javítás mindig az egyik a kettő közül: `.clone()` a move előtt, **vagy** a sorrend megváltoztatása, hogy a használat a move **előtt** történjen.
---
A 2.-nál a `make_start_tag(name.clone())` működik. De azt is megteheted, hogy a `println!`-ben nem a `name`-et írod ki. A 4.-nél: `names.push(n.clone())`, vagy cseréld meg a két utolsó sort.
:::

:::solution
```rust
// 1. A `let copy = tag;` move volt, utána a tag érvénytelen. Clone-ozzuk:
let tag = String::from("section");
let copy = tag.clone();
println!("{tag} {copy}");

// 2. A make_start_tag megkapta a name tulajdonát. Adjunk neki másolatot:
let name = String::from("h1");
let html = make_start_tag(name.clone());
println!("{name} -> {html}");

// 3. Az s-t kétszer akartuk move-olni. A második legyen t-ből másolat:
let s = String::from("p");
let t = s;
let u = t.clone();

// 4. A push átvette n tulajdonát. Előbb írjuk ki, aztán push:
let mut names = Vec::new();
let n = String::from("li");
println!("{n}");
names.push(n);
```
:::

:::why Hol van ilyenkor a memória? Stack és heap
A **stack** gyors, és fix méretű adatoknak való: egy `i32` 4 bájt, mindig. A **heap** változó méretű adatoknak való: egy `String` hossza futás közben nő. Maga a `String` változó a stacken 24 bájt (64 bites gépen): egy **mutató** a heapre, a **hossz** és a **kapacitás**. Move-nál ez a 24 bájt másolódik át, a heapen lévő szöveg viszont nem mozdul. Ezért olcsó a move. A `clone()` viszont a heapen lévő szöveget is lemásolja.
:::

:::quiz
Melyik sor fordul le?
- [x] `let a = 'x'; let b = a; println!("{a}");`
- [ ] `let a = String::from("x"); let b = a; println!("{a}");`
- [ ] `let a = vec![1]; let b = a; println!("{:?}", a);`
> A `char` `Copy` típus, ezért az `a` megmarad. A `String` és a `Vec` heapen tárol, nem `Copy`, ezért move történik.
:::

:::quiz
Mikor szabadul fel egy `String` memóriája?
- [ ] Amikor a szemétgyűjtő úgy dönt
- [ ] Amikor meghívod a `free()`-t
- [x] Amikor a tulajdonosa kikerül a hatókörből
> A Rustban nincs szemétgyűjtő, és nem kell kézzel felszabadítani. A fordító a hatókör végére automatikusan beteszi a felszabadítást (drop).
:::

:::card
K: Mi az ownership három szabálya?
V: 1) Minden értéknek egy tulajdonosa van. 2) Egyszerre csak egy. 3) Amikor a tulajdonos kikerül a hatókörből, az érték felszabadul (drop).
:::

:::card
K: Mi a különbség a move és a clone között?
V: A **move** átadja a tulajdont (olcsó, a régi változó érvénytelen lesz). A **clone** mély másolatot készít (drága lehet, de mindkét változó használható marad).
:::

:::card
K: Mely típusok `Copy`-k?
V: Az egyszerű, fix méretű, stacken élő típusok: egészek, `f32`/`f64`, `bool`, `char`, és az ezekből álló tuple-ök és tömbök. A `String` és a `Vec` nem.
:::

:::win
- Ismered az ownership három szabályát.
- Érted, miért van move, és mikor kell clone.
- Négy fordítóhibát kijavítottál, és mindegyiknél meg tudod mondani, miért volt hiba.
:::
