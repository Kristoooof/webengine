## Hogyan néz ki egy bitmap betű?

A legegyszerűbb betűtípus egy **bitkép**: minden betű egy 8×8-as rács, ahol minden pixel vagy be van kapcsolva, vagy nincs. Egy sor 8 pixele pont belefér egy `u8`-ba (8 bit). Egy betű tehát 8 bájt, `[u8; 8]`.

Így néz ki az **A** betű a `font8x8` crate-ben:

```text
sor  bájt   bitek (bit0 = bal szél)
 0   0x0C   ..XX....
 1   0x1E   .XXXX...
 2   0x33   XX..XX..
 3   0x33   XX..XX..
 4   0x3F   XXXXXX..
 5   0x33   XX..XX..
 6   0x33   XX..XX..
 7   0x00   ........
```

:::warn Figyelem: fordított bitsorrend
A `font8x8`-ban a **0. bit a bal szélső** pixel. Ha a `0x0C`-t (binárisan `00001100`) „szemmel” olvasod, a két egyes a jobb oldalon van, a képen viszont balra kerül. Ezért a `0x0C` a `..XX....` sor. Egy pixel akkor van bekapcsolva, ha `bajt & (1 << oszlop) != 0`.
:::

## A font8x8 crate

```powershell
cd crates/rozsda-browser

cd ../..
```

```rust
use font8x8::{BASIC_FONTS, LATIN_FONTS, UnicodeFonts};

let a: Option<[u8; 8]> = BASIC_FONTS.get('A');   // ASCII (U+0000–U+007F)
let e: Option<[u8; 8]> = LATIN_FONTS.get('é');   // Latin-1 kiegészítés (U+00A0–U+00FF)
```

A `get` egy `Option`-t ad vissza, mert nem minden karakter van benne. A `UnicodeFonts` traitet is be kell importálni (`use`), különben a `get` metódus nem látszik. Pont ezt tanultad a 01-12-ben: egy trait metódusa csak akkor hívható, ha a trait látható.

### Az ő és az ű problémája

A **Latin-1** (ISO-8859-1) a nyugat-európai nyelvek karakterkészlete. Benne van az **á, é, í, ó, ö, ú, ü**, de az **ő** és az **ű** nincs! Ezek a „Latin Extended-A” blokkban vannak (U+0150 és U+0170 környékén), mert csak a magyar használja őket. Ezért szerepelt régen az interneten annyiszor a „hosszú ő helyett kalapos ô” hiba.

A 0.1-ben egy egyszerű tartalékkal (fallback) oldjuk meg: ha `ő` jön, `ö`-t rajzolunk. A 7. modulban, amikor saját TrueType-olvasót írsz, az igazi ő is meglesz.

:::hint
A `glyph`:
```rust
pub fn glyph(c: char) -> Option<[u8; 8]> {
    let c = fallback(c);
    BASIC_FONTS.get(c).or_else(|| LATIN_FONTS.get(c))
}
```
Az `or_else` csak akkor hívja meg a closure-t, ha az első `None` volt.
---
A `draw_char` lényege két egymásba ágyazott ciklus: sorok (`enumerate()`-tel, hogy legyen sorszám) és oszlopok (`0..8`):
```rust
for (row, bits) in rows.iter().enumerate() {
    for col in 0..8 {
        if bits & (1 << col) != 0 {
            canvas.fill_rect(x + col * scale, y + row as i32 * scale, scale, scale, color);
        }
    }
}
```
---
A tofu lehet négy vékony `fill_rect` (felső, alsó, bal, jobb oldal), egy `s = GLYPH * scale` méretű négyzet szélein. Nem kell tökéletesnek lennie.
---
A `draw_text`: egy `cx` változó indul `x`-ről, és minden karakter után `GLYPH * scale`-lel nő. A végén `cx - x` a szélesség.
:::

:::solution
```rust
use crate::canvas::Canvas;
use font8x8::{BASIC_FONTS, LATIN_FONTS, UnicodeFonts};

pub const GLYPH: i32 = 8;

/// Az ő/ű nincs a Latin-1 fontban: a hozzájuk legközelebbi betűt rajzoljuk.
fn fallback(c: char) -> char {
    match c {
        'ő' => 'ö',
        'Ő' => 'Ö',
        'ű' => 'ü',
        'Ű' => 'Ü',
        '\u{00A0}' => ' ',
        _ => c,
    }
}

pub fn glyph(c: char) -> Option<[u8; 8]> {
    let c = fallback(c);
    BASIC_FONTS.get(c).or_else(|| LATIN_FONTS.get(c))
}

pub fn draw_char(canvas: &mut Canvas, x: i32, y: i32, c: char, scale: i32, color: u32) {
    match glyph(c) {
        Some(rows) => {
            for (row, bits) in rows.iter().enumerate() {
                for col in 0..8 {
                    if bits & (1 << col) != 0 {
                        canvas.fill_rect(x + col * scale, y + row as i32 * scale, scale, scale, color);
                    }
                }
            }
        }
        None => {
            // "tofu": ismeretlen karakter helyén egy kis keret
            let s = GLYPH * scale;
            canvas.fill_rect(x + scale, y, s - 2 * scale, scale, color);
            canvas.fill_rect(x + scale, y + s - scale, s - 2 * scale, scale, color);
            canvas.fill_rect(x + scale, y, scale, s, color);
            canvas.fill_rect(x + s - 2 * scale, y, scale, s, color);
        }
    }
}

pub fn draw_text(canvas: &mut Canvas, x: i32, y: i32, text: &str, scale: i32, color: u32) -> i32 {
    let mut cx = x;
    for c in text.chars() {
        draw_char(canvas, cx, y, c, scale, color);
        cx += GLYPH * scale;
    }
    cx - x
}
```

:::why Hogyan csinálják a valódi böngészők?
A bitmap fontok a régi számítógépek világát idézik. A mai betűtípusok (TrueType, OpenType) **vektorosak**: minden betű görbék sorozata, amit a böngésző az aktuális méretre raszterizál, élsimítással (antialiasing). Ezen felül van **shaping** is (pl. arab írásnál a betűk alakja a szomszédoktól függ, és ligatúrák is vannak, mint az „fi”) meg **font fallback** (ha egy betű nincs az egyik fontban, a böngésző keres egy másikat). A 7. modulban saját TrueType-olvasót és élsimított raszterizálót írsz. A 16. modulban pedig a profi kapcsoló mögé jön a Parley/Swash, ami mindezt tudja.
:::
