## A toll és az alapvonal

A szöveg kirajzolása egy **toll** (pen) mozgatása az alapvonalon:

```text Ábra
          top ┌──────┐
              │ ▄▀▀▄ │  ← a glif bitképe (07-05): left, top a tollhoz képest
              │ █  █ │
   alapvonal ─┼─▀▄▄▀─┼──────────────
              ●      ●
            toll    toll + előrelépés (+ a következő párral a kerning)
```

Minden karakterre:

1. Keresd meg a glifet (`glyph_index`).
2. Ha volt előző glif, tedd hozzá a tollhoz a kettő **kerningjét**.
3. Raszterizáld a glifet, és tedd a bitképét a `(toll + left, alapvonal − top)` helyre.
4. Lépj a tollal a glif előrelépésével.

A lépések font-egységben jönnek, ezért a nagyítással (`méret / unitsPerEm`) pixelre kell váltani őket. A toll helye így tört szám lesz (pl. 23,4 pixel). A bitképet egész pixelre tesszük (`round`): ez **pixelre illesztés** (pixel snapping).

## Lefedettségből szín

A raszterizáló minden pixelre egy 0–255 közötti lefedettséget ad. Ez pontosan egy **átlátszóság** (alpha): a 255-ös pixel a szöveg színét kapja, a 128-as félig átlátszó, és a háttér átsejlik rajta. A 06-02-ben megírt keverés (`Canvas::fill_rect` egy átlátszó színnel) tehát pont jó:

```rust
                let a = ((color.a as u32 * coverage + 127) / 255) as u8;
                canvas.fill_rect(x + col as i32, y + row as i32, 1, 1, Color { a, ..color });
```

Ha a szöveg színe maga is átlátszó (pl. `rgba(0, 0, 0, 0.5)`), a két átlátszóság összeszorzódik. A `+ 127` a kerekítés, mint a 06-02-ben.

## Két betűkészlet, egy típus

A böngészőben ezentúl két betűkészlet lesz, és egy kapcsoló választ köztük (`--betu=vektor|bitkep`, a következő leckében). A `Typeface` egy **enum**:

```rust
pub enum Typeface {
    Bitmap,
    Vector(Font<'static>),
}
```

Miért nem `Box<dyn …>`, mint a motoroknál? Mert itt pontosan két, előre ismert változat van, és a `Bitmap`-nek nincs is adata. Egy `enum` egyszerűbb: nincs halomfoglalás, és a `match` mindkét esetet kikényszeríti. A motoroknál (`HtmlParser` stb.) azért trait, mert ott a 16. modulban külső crate-ek is beállnak a sorba.

A `Typeface` maga is megvalósítja a `FontMetrics`-et, így a layout és a festő is egyszerűen `&engines.font`-ot kaphat. A megvalósítás **továbbadás** (delegation): egy segéd visszaadja a megfelelő mérőt, és minden metódus azt hívja.

```rust
    fn metrics(&self) -> &dyn FontMetrics {
        match self {
            Typeface::Bitmap => &BitmapFont,
            Typeface::Vector(font) => font,
        }
    }
```

A `&BitmapFont` egy hivatkozás egy egységstruktúrára. Hogy élhet ez a függvény végéig, ha egy ideiglenes értékre mutat? A Rust az ilyen konstans kifejezéseket **statikus** memóriába teszi (*rvalue static promotion*), így a hivatkozás `&'static`.

```rust
//! A betűtípus: a 2. modul 8×8-as bitképes betűi, vagy a 7. modul TrueType-betűi.

use crate::canvas::Canvas;
use crate::text;
use rozsda_core::style::Color;
use rozsda_core::text::FontMetrics;
use rozsda_font::raster::GlyphBitmap;
use rozsda_font::{DEJAVU_SANS, Font};
use rozsda_layout::text::{BitmapFont, glyph_scale};

pub enum Typeface {
    Bitmap,
    Vector(Font<'static>),
}

impl Typeface {
    /// A beépített DejaVu Sans.
    pub fn vector() -> Typeface {
        Typeface::Vector(Font::parse(DEJAVU_SANS).expect("a beépített betűtípus hibátlan"))
    }

    fn metrics(&self) -> &dyn FontMetrics {
        match self {
            Typeface::Bitmap => &BitmapFont,
            Typeface::Vector(font) => font,
        }
    }

    /// Szöveg kirajzolása: `x` a toll kezdőhelye, `baseline` az alapvonal, a vászon koordinátáiban.
    pub fn draw_text(
        &self,
        canvas: &mut Canvas,
        x: f32,
        baseline: f32,
        s: &str,
        size: f32,
        color: Color,
    ) {
        match self {
            Typeface::Bitmap => {
                // a 8×8-as betűk alapvonala a 7. pixelsor alatt van
                let scale = glyph_scale(size);
                let top = (baseline - 7.0 * scale).round() as i32;
                text::draw_text(canvas, x.round() as i32, top, s, scale as i32, color);
            }
            Typeface::Vector(font) => draw_glyphs(font, canvas, x, baseline, s, size, color),
        }
    }
}

impl FontMetrics for Typeface {
    fn text_width(&self, text: &str, size: f32) -> f32 {
        self.metrics().text_width(text, size)
    }

    fn ascent(&self, size: f32) -> f32 {
        self.metrics().ascent(size)
    }

    fn descent(&self, size: f32) -> f32 {
        self.metrics().descent(size)
    }

    fn underline(&self, size: f32) -> (f32, f32) {
        self.metrics().underline(size)
    }
}

/// A glifek egymás után: a toll az előrelépéssel és az alávágással halad.
fn draw_glyphs(
    font: &Font,
    canvas: &mut Canvas,
    x: f32,
    baseline: f32,
    s: &str,
    size: f32,
    color: Color,
) {
    let scale = size / font.units_per_em as f32;
    let baseline = baseline.round() as i32;
    let mut pen = x;
    let mut previous = None;
    for c in s.chars() {
        let glyph = font.glyph_index(c);
        if let Some(p) = previous {
            pen += font.kerning(p, glyph) as f32 * scale;
        }
        if let Some(bitmap) = font.rasterize(glyph, size) {
            let left = pen.round() as i32 + bitmap.left;
            blit(canvas, &bitmap, left, baseline - bitmap.top, color);
        }
        pen += font.advance(glyph) as f32 * scale;
        previous = Some(glyph);
    }
}

/// A lefedettség az átlátszóság: a 255-ös pixel teljes színt kap, a 128-as félig átlátszót.
fn blit(canvas: &mut Canvas, g: &GlyphBitmap, x: i32, y: i32, color: Color) {
    for row in 0..g.height {
        for col in 0..g.width {
            let coverage = g.coverage[row * g.width + col] as u32;
            if coverage > 0 {
                let a = ((color.a as u32 * coverage + 127) / 255) as u8;
                canvas.fill_rect(x + col as i32, y + row as i32, 1, 1, Color { a, ..color });
            }
        }
    }
}
```

:::note Figyelmeztetések, amik most rendben vannak
A `cargo build` most négy figyelmeztetést ad: a `Typeface`-t, a `draw_glyphs`-t és a `blit`-et „senki nem használja”. A tesztek használják, de a kész programban még nincs bekötve. A következő leckében a rajzlista és az ablak is a `Typeface`-en keresztül dolgozik, és a figyelmeztetések eltűnnek.
:::

:::why Mélyvíz: glif-gyorsítótár és tört pixeles toll
**Gyorsítótár.** A `draw_glyphs` minden betűt minden képkockán újra raszterizál. Egy szövegekkel teli, 960×720-as oldalon ez kiadott (`--release`) módban kb. 6 ms, fejlesztői módban 25 ms körül van: görgetéshez még elég, de pazarló. A profi böngészők egy **glif-gyorsítótárat** (glyph cache) tartanak: a (glif, méret) párhoz egyszer kiszámolt bitképet eltárolják, és csak bemásolják. A GPU-s megoldások (a 16. modul Vellója) egy nagy textúrába, egy **atlaszba** gyűjtik a glifeket. Ha a Rozsdád lassúnak tűnik, egy `RefCell<HashMap<(u16, u32), Option<GlyphBitmap>>>` a `Typeface`-ben pár sorból megoldja.

**Tört pixeles toll.** A toll helyét kerekítjük. Egy 23,4-es tollhelyen a glif 23-ra kerül, és a betűközök kicsit egyenetlenek lesznek. A finomabb megoldás a **subpixel positioning**: a glifet a toll törtrészével eltolva raszterizáljuk (pl. negyed pixelenként 4 változatban, a gyorsítótárban). A macOS és a modern Chrome így rajzol.
:::

```rust
fn blend_glyph(bg: u32, color: (u8, u8, u8), coverage: u8) -> u32 {
    let a = coverage as u32;
    let mix = |top: u8, shift: u32| {
        let bottom = (bg >> shift) & 0xFF;
        ((top as u32 * a + bottom * (255 - a) + 127) / 255) << shift

    mix(color.0, 16) | mix(color.1, 8) | mix(color.2, 0)
```
