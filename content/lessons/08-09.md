## Ha a szerver még nem tudja a hosszt

A `Content-Length` csak akkor működik, ha a szerver **előre** tudja a válasz hosszát. Egy fájlnál ez könnyű. De a mai oldalak többségét egy program állítja elő menet közben: lekérdez egy adatbázist, kitölt egy sablont, és már az elején küldené a `<head>`-et, hogy a böngésző elkezdhesse letölteni a CSS-t. Ilyenkor a hossz a végén derül ki.

A kapcsolat bontása lenne a másik lehetőség, de akkor a kapcsolatot nem lehet újra használni, és a kliens nem tudja megkülönböztetni a teljes választ egy félbeszakadttól. A HTTP/1.1 megoldása a **darabolt átvitel**: `Transfer-Encoding: chunked`.

```text Ábra
1f4\r\n                     ← a darab hossza hexában: 0x1f4 = 500 bájt
<!DOCTYPE html>…\r\n        ← 500 bájt adat, utána sorvég
1f4\r\n
al, amit a <b>…\r\n         ← még 500 bájt
8e\r\n                      ← 0x8e = 142 bájt
   <li>Saját…\r\n
0\r\n                       ← a 0 hosszú darab: vége
\r\n                        ← (itt jöhetnének záró fejlécek), és egy üres sor
```

A szerver minden darab előtt megmondja a hosszát, **hexadecimálisan**. A végét egy 0 hosszú darab jelzi. A darabok határa bárhová eshet, akár egy UTF-8 karakter közepére is. Ezért bájtokat fűzünk össze, és csak a legvégén alakítjuk szöveggé.

Két apróság a szabványból:

- A hossz után `;`-vel **kiegészítések** (chunk extensions) jöhetnek: `3;nev=ertek`. Senki nem használja őket, de át kell ugrani.
- A 0-s darab után **záró fejlécek** (trailers) jöhetnek az üres sorig. Ezeket beolvassuk és eldobjuk.

Ha a `Transfer-Encoding` és a `Content-Length` is megvan, a `Transfer-Encoding` nyer: a darabok hossza számít.

:::solution
`chunked.rs`:

```rust
//! Darabolt átvitel (chunked transfer encoding): a törzs darabokban jön, mindegyik előtt a
//! hossza hexában, és egy 0 hosszú darab zárja. Így a szerver előre nem tudja, mekkora lesz.

use crate::http::{HttpError, MAX_BODY, read_line};
use std::io::BufRead;

pub fn read_chunked(reader: &mut impl BufRead) -> Result<Vec<u8>, HttpError> {
    let mut body = Vec::new();
    loop {
        let line = read_line(reader)?;
        // a hossz után `;`-vel kiegészítések (chunk extensions) jöhetnek: ezeket átugorjuk
        let size_hex = line.split(';').next().unwrap_or("").trim();
        let size = usize::from_str_radix(size_hex, 16).map_err(|_| HttpError::BadChunk)?;
        if size == 0 {
            break;
        }
        if body.len() + size > MAX_BODY {
            return Err(HttpError::TooLarge);
        }
        let start = body.len();
        body.resize(start + size, 0);
        reader.read_exact(&mut body[start..])?;
        // minden darab után egy sorvég
        if !read_line(reader)?.is_empty() {
            return Err(HttpError::BadChunk);
        }
    }
    // a záró fejlécek (trailers) az üres sorig: nem használjuk őket
    while !read_line(reader)?.is_empty() {}
    Ok(body)
}
```

A `http.rs`-ben a `use` sorok közé `use crate::chunked;`, a `HttpError`-ba `BadChunk,`, a `Display`-be:

```rust
            HttpError::BadChunk => write!(f, "hibás chunked törzs"),
```

A `read_body` eleje:

```rust
/// A törzs hossza háromféleképp derülhet ki: darabokban jön (chunked), előre megmondják
/// (`Content-Length`), vagy a szerver a végén bontja a kapcsolatot.
fn read_body(reader: &mut impl BufRead, response: &Response) -> Result<Vec<u8>, HttpError> {
    if matches!(response.status, 100..=199 | 204 | 304) {
        return Ok(Vec::new()); // ezeknek sosem lehet törzsük
    }
    let chunked = response
        .header("Transfer-Encoding")
        .and_then(|te| te.rsplit(',').next())
        .is_some_and(|last| last.trim().eq_ignore_ascii_case("chunked"));
    if chunked {
        return chunked::read_chunked(reader);
    }
    // ... innen a Content-Length, változatlan
```

:::why Mélyvíz: a HTTP/2-ben nincs chunked
A HTTP/2 és a HTTP/3 eleve **keretekben** (frames) küld mindent: minden keretnek van hossza, és egy jelző mondja meg, melyik az utolsó. Ezért ott nincs `Transfer-Encoding`, sőt kifejezetten tilos. A darabolás gondolata megmaradt, csak a protokoll mélyére került. A „hossz, aztán adat” minta (length-prefixed) amúgy mindenhol előjön: a DNS-nevek címkéinél (08-04) is ezt láttad, és a fontfájlok tábláinál (7. modul) is.
:::

@@ feladat

@@ kód

@@ megoldás
```rust
fn dechunk(data: &[u8]) -> Option<Vec<u8>> {
    let mut body = Vec::new();
    let mut rest = data;
    loop {
        let line_end = rest.windows(2).position(|w| w == b"\r\n")?;
        let line = std::str::from_utf8(&rest[..line_end]).ok()?;
        let size_hex = line.split(';').next()?.trim();
        let size = usize::from_str_radix(size_hex, 16).ok()?;
        rest = &rest[line_end + 2..];
        if size == 0 {
            return Some(body);
        }
        if rest.len() < size + 2 || &rest[size..size + 2] != b"\r\n" {
            return None;
        }
        body.extend_from_slice(&rest[..size]);
        rest = &rest[size + 2..];
    }
}
```
