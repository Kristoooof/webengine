:::goal
Bekötöd az igazi betűket a böngészőbe. A rajzlista szöveg-parancsa a nagyítás (`scale`) helyett az alapvonalat és a betűméretet kapja, a festő és a raszterizáló a `Typeface`-en keresztül mér és rajzol, és egy `--betu=vektor|bitkep` kapcsolóval választhatsz. A képernyőkép-teszt jelez, hogy megváltozott a kép, és írsz egy **reftestet** is.
:::

## Mi változik?

Végigmegyünk a böngésző útján, a layouttól a pixelekig:

```text Ábra
             Typeface (Bitmap vagy Vector)
            ╱        │              ╲
    layout (méri)   festő (méri)     raszterizáló (rajzol)
       │               │                  │
  LayoutBox  ──►  DisplayItem::Text  ──►  pixelek
                  { rect, baseline,
                    size, … }
```

Ugyanaz a `Typeface` méri a szöveget a layoutban és a festőben, és rajzolja a raszterizálóban. Ez fontos: ha a layout más betűkkel mérne, mint amivel a raszterizáló rajzol, a szavak egymásra csúsznának, vagy lyukak lennének köztük.

## 1. A rajzlista

A `rozsda-core/src/display.rs`-ben a `Text` parancs:

```rust
    /// Egy darab szöveg. A `baseline` az alapvonal helye, a `size` a betűméret pixelben.
    Text {
        rect: Rect,
        baseline: f32,
        text: String,
        color: Color,
        size: f32,
        bold: bool,
    },
```

A `scale: u32` a 8×8-as betűk nagyítása volt, ennek egy igazi betűtípusnál nincs értelme. Helyette a **betűméret** (`size`) és az **alapvonal** (`baseline`) kerül bele: a raszterizálónak pont ez kell a `Typeface::draw_text`-hez. Az alapvonalat a festő számolja ki, mert ő tudja, melyik betűtípussal mért a layout.

## 2. A festő

:::task
`paint.rs`:

1. A `paint_text`, a `paint_marker`, a `paint_box` és a `build_display_list` kapjon egy `fonts: &dyn FontMetrics` paramétert.
2. A `paint_text`: az alapvonal `rect.y + fonts.ascent(size)` (a layout úgy tette a darabot a sorba, hogy a teteje fölött `ascent` hely legyen). Az aláhúzás helye és vastagsága a `fonts.underline(size)`-ból jön.
3. A `paint_marker` a `BitmapFont` helyett a kapott `fonts`-szal mér.
4. A `--lista` kiírása: `{size}px` a `{scale}×` helyett.
5. A tesztekben a `build_display_list(&doc, &styles, &root, &BitmapFont, outlines)`, és a változott sorok:
:::

```rust test

            matches!(&items[2], DisplayItem::Text { text, size, .. } if text == "Szia" && *size == 16.0)
        );
```

```rust test
        // a sor 8-nál kezdődik, az alapvonal 8 + 18 = 26-nál, az aláhúzás 2 pixellel alatta
        assert_eq!((rect.y, rect.height, rect.width), (28.0, 2.0, 64.0));
```

```rust test

```

Az aláhúzás helye a 8×8-as betűkkel **nem változott** (28): a `BitmapFont` aláhúzása egy nagyításnyival az alapvonal alatt van, és ugyanoda esik, ahová eddig a „betű alja” képlet tette.

:::solution
```rust
fn paint_text(
    list: &mut Vec<DisplayItem>,
    fonts: &dyn FontMetrics,
    style: &ComputedStyle,
    rect: Rect,
    text: &str,
) {
    let size = style.font_size;
    // A layout úgy tette a darabot a sorba, hogy a teteje fölött `ascent` hely legyen.
    let baseline = rect.y + fonts.ascent(size);
    list.push(DisplayItem::Text {
        rect,
        baseline,
        text: text.to_string(),
        color: style.color,
        size,
        bold: style.font_weight >= 600,
    });
    if style.underline {
        let (offset, thickness) = fonts.underline(size);
        list.push(DisplayItem::Rect {
            rect: Rect {
                y: baseline + offset,
                height: thickness,
                ..rect
            },
            color: style.color,
            radius: 0.0,
        });
    }
}

/// A felsorolásjel a tartalom bal széle előtt, a kitöltésben.
fn paint_marker(list: &mut Vec<DisplayItem>, fonts: &dyn FontMetrics, b: &LayoutBox) {
    let s = &b.style;
    let c = b.dimensions.content;
    let width = fonts.text_width("»", s.font_size);
    let rect = Rect {
        x: c.x - 2.0 * width,
        y: c.y,
        width,
        height: fonts.line_height(s.font_size),
    };
    paint_text(list, fonts, s, rect, "»");
}
```

A `paint_box`-ban a hívások `paint_marker(list, fonts, b)`, `paint_text(list, fonts, style, f.rect, &f.text)` és `paint_box(list, doc, styles, child, fonts, outlines)`, a `build_display_list` pedig továbbadja a `fonts`-ot. A kiírás:

```rust
            DisplayItem::Text {
                rect,
                text,
                color,
                size,
                bold,
                ..
            } => format!(
                "szöveg {} {} {size}px{} {text:?}",
```

A `..` a mintában azt jelenti: „a többi mezőt (`baseline`) nem használom”.

## 3. A raszterizáló

:::task
`raster.rs`:

1. Az `use crate::text::{GLYPH, draw_text};` helyett `use crate::fonts::Typeface;`, a régi `text` függvény törölhető.
2. `pub fn rasterize(canvas: &mut Canvas, items: &[DisplayItem], scroll: i32, font: &Typeface) -> usize`.
3. A `Text` ág: `font.draw_text` az alapvonalra, a görgetést levonva. A félkövér marad a régi trükk: még egyszer, egy pixellel jobbra.
4. A tesztekben minden `rasterize(…)` hívás kapjon egy `&Typeface::Bitmap`-et, és a `text_is_centered_in_its_rect` legyen `text_sits_on_the_baseline`:
:::

```rust test
    #[test]
    fn text_sits_on_the_baseline() {
        let mut c = white(40, 40);
        let items = vec![DisplayItem::Text {
            rect: Rect {
                x: 0.0,
                y: 0.0,
                width: 16.0,
                height: 24.0,
            },
            baseline: 18.0,
            text: "I".to_string(),
            color: Color::BLACK,
            size: 16.0,
            bold: false,
        }];
        rasterize(&mut c, &items, 0, &Typeface::Bitmap);
        let rows: Vec<usize> = (0..40)
            .filter(|&y| (0..16).any(|x| pixel(&c, x, y) == 0))
            .collect();
        // a 8×8-as betű 2×-es nagyításban: 18 − 7·2 = 4-től 19-ig
        assert!(rows.iter().all(|&y| (4..20).contains(&y)), "{rows:?}");
    }
```

:::solution
```rust
            DisplayItem::Text {
                rect,
                baseline,
                text,
                color,
                size,
                bold,
            } => {
                let y = baseline - scroll as f32;
                font.draw_text(canvas, rect.x, y, text, *size, *color);
                if *bold {
                    // „ál-félkövér” (faux bold): még egyszer, egy pixellel jobbra
                    font.draw_text(canvas, rect.x + 1.0, y, text, *size, *color);
                }
            }
```

## Reftest: két oldal, egy kép

Az 5. modulban (05-09) említettük a **reftesteket**: két HTML-oldal, amelyeknek pixelre ugyanúgy kell kinézniük. Az egyik a tesztelt funkciót használja, a másik ugyanazt „butábban” írja le. Most, hogy van igazi betűtípusunk és képernyőképünk, írhatunk ilyet!

:::task
A `page.rs` tesztjei közé egy segéd, ami két oldalt kirajzol egy 300×120-as vászonra, és összehasonlítja a pixeleket, meg egy teszt három párral.
:::

```rust test
    /// Reftest: két oldal, amelyeknek pixelre ugyanúgy kell kinézniük.
    fn assert_same_pixels(test: &str, reference: &str) {
        let e = engines();
        let render = |html: &str| {
            let page = Page::load(&e, html, 300.0).unwrap();
            let mut canvas = Canvas::new(300, 120);
            page.render(&mut canvas, 0, &e.font);
            canvas.pixels
        };
        assert!(
            render(test) == render(reference),
            "a két oldal képe eltér:\n{test}\n{reference}"
        );
    }

    #[test]
    fn reftests() {
        assert_same_pixels(
            "<p><b>Árvíztűrő</b> tükörfúrógép</p>",
            "<p><span style=\"font-weight: bold\">Árvíztűrő</span> tükörfúrógép</p>",
        );
        assert_same_pixels(
            "<h1>Cím</h1>",
            "<div style=\"font-size: 32px; font-weight: bold; margin: 21.44px 0\">Cím</div>",
        );
        assert_same_pixels(
            "<p style=\"padding: 10px 20px\">AVATAR</p>",
            "<p style=\"padding-top: 10px; padding-left: 20px\">AVATAR</p>",
        );
    }
```

Az első pár a `<b>` UA-stílusát ellenőrzi, a második a `<h1>`-ét (2em = 32px, a margó 0,67em = 21,44px), a harmadik a `padding` rövidítést. A teszt nem a pixelek pontos értékét nézi, hanem azt, hogy a két út **ugyanoda** vezet. Ezért nem kell újra jóváhagyni, ha holnap szebb lesz az élsimítás.

Miért nem `assert_eq!(render(test), render(reference))`? Mert az eltérésnél kiírná mind a 36 000 pixelt. Az `assert!` a saját, rövid üzenetével olvashatóbb.

:::adhd Rossz okból zöld?
A 06-08-ban megtanultuk: ha egy új teszt elsőre zöld, egy pillanatra gyanakodj. Rontsd el szándékosan: írd a második párban `21.44px` helyett `23px`-et. Ha a teszt piros lesz („a két oldal képe eltér”), tényleg tesztel valamit. Aztán írd vissza.

## Próbáld ki itt, a kurzusban

:::exercise Az első eltérő pixel
@@ feladat
Két egyforma méretű kép (`a`, `b`) pixelei egy-egy listában, soronként balról jobbra, `width` pixel széles sorokkal. Add vissza az első eltérő pixel helyét `(x, y)` alakban, vagy `None`-t, ha a két kép egyforma. Egy reftest-futtató ezzel mutatja meg, **hol** tér el a két oldal.
@@ kód
```rust
fn first_difference(a: &[u32], b: &[u32], width: usize) -> Option<(usize, usize)> {
    todo!()
}
```
@@ megoldás
```rust
fn first_difference(a: &[u32], b: &[u32], width: usize) -> Option<(usize, usize)> {
    let i = a.iter().zip(b).position(|(p, q)| p != q)?;
    Some((i % width, i / width))
}
```
@@ esetek
```rust
first_difference(&[1, 2, 3, 4], &[1, 2, 3, 4], 2)
first_difference(&[1, 2, 3, 4], &[1, 2, 9, 4], 2)
first_difference(&[1, 2, 3, 4, 5, 6], &[1, 2, 3, 4, 5, 7], 3)
first_difference(&[0; 12], &[0; 12], 4)
first_difference(&[7], &[8], 1)
first_difference(&[], &[], 5)
```
@@ mérés
```rust
let a: Vec<u32> = (0..60000u32).map(|i| i.wrapping_mul(2654435761)).collect();
let mut b = a.clone();
b[59000] ^= 1;
---
first_difference(std::hint::black_box(&a), std::hint::black_box(&b), 300)
```
@@ teszt-rossz
```rust
fn first_difference(a: &[u32], b: &[u32], width: usize) -> Option<(usize, usize)> {
    let i = a.iter().zip(b).position(|(p, q)| p != q)?;
    Some((i / width, i % width))
}
```
