:::goal
A szelektorok találkoznak a DOM-mal: megírod a `matches(doc, id, &selector)` függvényt, ami megmondja, illik-e egy szelektor egy elemre. Megtanulod, miért olvassák a böngészők a szelektorokat **jobbról balra**, és mi az a visszalépés (*backtracking*).
:::

## A kérdés, amit a böngésző feltesz

A böngésző nem azt kérdezi, hogy „melyik elemekre illik ez a szabály?”, hanem fordítva: **„erre az elemre melyik szabályok illenek?”**. Minden elemre végigmegy a szabályokon, és mindegyiknél eldönti: igen vagy nem. Egy közepes weboldalon ez több ezer elem és több ezer szabály, vagyis milliónyi kérdés. Ezért számít, milyen gyorsan tudunk **nemet** mondani.

## Jobbról balra

Vegyük a `nav > ul li.aktiv a` szelektort és egy `<span>` elemet. Ha balról olvasnánk, először keresnénk egy `nav`-ot valahol az elem fölött, aztán egy `ul`-t alatta… Pedig az elem egy `span`, tehát **biztosan nem** illik, mert a szelektor `a`-ra végződik!

Jobbról olvasva az első kérdés: „ez az elem egy `a`?”. A legtöbb elemnél már itt kiderül, hogy nem, és kész is vagyunk. Csak a ritka egyezéseknél kell felfelé lépkedni a fában.

```text Ábra
nav > ul  li.aktiv  a          ← a szelektor
                    ▲
1. maga az elem: <a>? ─────────┘  ha nem, kész: NEM illik
2. a szülei között egy li.aktiv?   (leszármazott: bármelyik ős jó)
3. annak a szülei között egy ul?   (leszármazott)
4. annak a KÖZVETLEN szülője nav?  (gyerek: csak a szülő jó)
```

A kombinátorok jelentése jobbról balra:

| Kombinátor | Kérdés |
|---|---|
| `>` (gyerek) | A **szülő** illik-e az előző összetett szelektorra? |
| szóköz (leszármazott) | **Valamelyik ős** (szülő, nagyszülő, …) illik-e rá? |

## Egy összetett szelektor és egy elem

Előbb a legkisebb darab: illik-e egy `Compound` (pl. `li.aktiv`) egy elemre? Minden feltételének teljesülnie kell:

- Az elem tényleg elem (nem szöveg, nem komment).
- Ha van tag a szelektorban, egyezzen a tagnévvel.
- Ha van id, egyezzen az elem `id` attribútumával.
- **Minden** osztály szerepeljen az elem osztályai között.

A DOM `ElementData`-jának már megvan az `id()` és a `classes()` metódusa a 03-07-ből.

## A visszalépés

```html
<div class="a">
  <div>
    <div>
      <span></span>
    </div>
  </div>
</div>
```

Illik-e a `.a > div span` a `span`-re? Jobbról: a `span` stimmel. Kell egy `div` ős, aminek a **szülője** `.a`. A legközelebbi `div` ős a legbelső, de annak a szülője egy sima `div`, nem `.a`. Ha itt feladnánk, rossz választ adnánk! A középső `div` szülője viszont a `.a`, tehát **illik**.

A leszármazott-kombinátornál tehát nem elég az első egyező őst kipróbálni. Ha onnan nem jön ki a teljes egyezés, **vissza kell lépni**, és a következő őssel újra kell próbálni. Ezt a rekurzió szépen megoldja: a leszármazott-ág egy ciklus az ősökön, és mindegyikre rekurzívan meghívja ugyanazt az illesztést.

```rust test
        doc.append(doc.root(), nav);

        doc.append(nav, ul);

    fn simple_matching() {
        let (doc, ul, li, a) = sample();

        assert!(m(&doc, li, ".aktiv"));
        assert!(m(&doc, li, "li.elso.aktiv"));

        assert!(!m(&doc, nav, "div#fo"));
        let text = doc.children(a)[0];
        assert!(!m(&doc, text, "*"));
    }

    fn combinator_matching() {
        let (doc, _, li, a) = sample();
        assert!(m(&doc, a, "nav a"));
        assert!(m(&doc, a, "#fo li a"));
        assert!(m(&doc, a, "li > a"));
        assert!(!m(&doc, a, "ul > a"));
        assert!(m(&doc, a, "nav > ul a"));
        assert!(!m(&doc, a, "a a"));
        assert!(m(&doc, li, "nav li"));
        assert!(!m(&doc, li, "li nav"));
    }

    fn backtracking() {
        // <div class="a"><div><div><span></span></div></div></div>
        let mut doc = Document::new();
        let mut parent = doc.root();
        for attrs in [vec![("class".into(), "a".into())], vec![], vec![]] {
            let div = doc.create_element("div", attrs);
            doc.append(parent, div);
            parent = div;

        let span = doc.create_element("span", vec![]);
        doc.append(parent, span);
```

:::solution
```rust
pub fn compound_matches(doc: &Document, id: NodeId, c: &Compound) -> bool {
    let Some(el) = doc.element(id) else {
        return false;
    };
    if let Some(tag) = &c.tag
        && *tag != el.name
    {
        return false;
    }
    if let Some(want) = &c.id
        && el.id() != Some(want.as_str())
    {
        return false;
    }
    let classes = el.classes();
    c.classes
        .iter()
        .all(|class| classes.contains(&class.as_str()))
}

/// Jobbról balra illesztünk: előbb maga az elem, aztán a szülei.
pub fn matches(doc: &Document, id: NodeId, sel: &Selector) -> bool {
    matches_at(doc, id, sel, sel.compounds.len() - 1)
}

fn matches_at(doc: &Document, id: NodeId, sel: &Selector, i: usize) -> bool {
    if !compound_matches(doc, id, &sel.compounds[i]) {
        return false;
    }
    if i == 0 {
        return true;
    }
    match sel.combinators[i - 1] {
        Combinator::Child => doc
            .parent(id)
            .is_some_and(|p| matches_at(doc, p, sel, i - 1)),
        Combinator::Descendant => {
            let mut current = doc.parent(id);
            while let Some(p) = current {
                if matches_at(doc, p, sel, i - 1) {
                    return true;
                }
                current = doc.parent(p);
            }
            false
        }
    }
}
```

:::why Hogyan gyorsítanak a böngészők?
A jobbról balra olvasás csak az első lépés. A Firefox stílusmotorja (Stylo) és a Chrome is **előszűri** a szabályokat. A szabályokat az utolsó összetett szelektoruk szerint „vödrökbe” rakják: egy vödör az id-knek, egy az osztályoknak, egy a tageknek. Egy `<p class="intro">` elemnél csak a `p` tag-vödröt, az `intro` osztály-vödröt és az univerzális szabályokat nézik meg. Az ősök vizsgálatát egy **Bloom-szűrő** gyorsítja: egy kis bittömb, ami egy pillanat alatt megmondja, hogy „ilyen osztályú ős biztosan nincs”, így a fa bejárását sokszor meg sem kell kezdeni. A Stylo ráadásul több szálon, párhuzamosan számolja a stílusokat. Ezt a 16. modulban látod működés közben.

```rust
fn matches(parents: &[Option<usize>], tags: &[&str], node: usize, sel: &[&str]) -> bool {
    let sel: Vec<String> = sel.iter().map(|s| s.to_string()).collect();
    let mut ancestors: Vec<usize> = Vec::new();
    let mut current = parents[node];
    while let Some(p) = current {
        ancestors.push(p);
        current = parents[p];
    }
    fn go(parents: &[Option<usize>], tags: &[&str], node: usize, sel: &[String]) -> bool {
        let Some((last, rest)) = sel.split_last() else {
            return false;
        };
        if tags[node] != last.as_str() {
            return false;
        }
        if rest.is_empty() {
            return true;
        }
        if rest.last().map(|s| s.as_str()) == Some(">") {
            let rest = rest[..rest.len() - 1].to_vec();
            return parents[node].is_some_and(|p| go(parents, tags, p, &rest));
        }
        let mut ups = Vec::new();
        let mut current = parents[node];
        while let Some(p) = current {
            ups.push(p);
            current = parents[p];
        }
        ups.iter().any(|&p| go(parents, tags, p, &rest.to_vec()))
    }
    let _ = ancestors;
    go(parents, tags, node, &sel)
}
```
