:::goal
A szerver válaszát most **szétszeded**: státuszkód, fejlécek, törzs. Közben megtudod, honnan tudja a böngésző, hol ér véget egy válasz egy olyan kapcsolaton, ami csak bájtokat ad. A végén a `Client::get` egy hívással letölt egy oldalt, és a `letolt` már a feldolgozott választ írja ki.
:::

## A válasz szerkezete

A válasz ugyanúgy épül fel, mint a kérés: egy első sor, fejlécek, egy üres sor, és utána a **törzs** (body), vagyis maga a HTML.

```text Ábra
HTTP/1.1 404 Not Found                ← státuszsor: változat, kód, ok (reason)
Content-Type: text/html; charset=utf-8
Content-Length: 31                    ← a törzs pontosan 31 bájt
Connection: close
                                      ← üres sor
<h1>404: nincs ilyen oldal</h1>       ← törzs
```

A **státuszkód** háromjegyű szám. Az első számjegye az osztálya:

| Kód | Jelentés | Példa |
|---|---|---|
| 1xx | Tájékoztatás, várj | `100 Continue` |
| 2xx | Siker | `200 OK`, `204 No Content` |
| 3xx | Átirányítás: máshol keresd | `301 Moved Permanently`, `304 Not Modified` |
| 4xx | A kliens hibázott | `404 Not Found`, `403 Forbidden` |
| 5xx | A szerver hibázott | `500 Internal Server Error` |

Az **ok** (reason phrase, pl. `Not Found`) csak embereknek szól, a program a kódot nézi. Üres is lehet: a `HTTP/1.1 204` is érvényes státuszsor.

A **fejlécnevekben nem számít a kis- és nagybetű**: a `Content-Length`, a `content-length` és a `CONTENT-LENGTH` ugyanaz. A HTTP/2 például mindent kisbetűvel küld. Ezért keresünk az `eq_ignore_ascii_case`-szel.

### Hol ér véget a törzs?

A 08-06-ban láttad: a TCP bájtfolyam, nem jelzi az üzenetek végét. A fejléc végét az üres sor mutatja, de a törzs bármit tartalmazhat, üres sort is. A HTTP/1.1-ben háromféleképpen derül ki, hol a vége:

1. **`Content-Length: 477`**: a szerver előre megmondja a hosszát. Pontosan ennyi bájtot olvasunk (`read_exact`).
2. **`Transfer-Encoding: chunked`**: darabokban jön, mindegyik előtt a hossza. Ez a következő lecke.
3. **Egyik sem**: a törzs addig tart, amíg a szerver nem bontja a kapcsolatot. (A régi HTTP/1.0 így működött.)

Néhány válasznak **sosem** lehet törzse: az 1xx-eseknek, a `204 No Content`-nek és a `304 Not Modified`-nak. Ezeknél nem is próbálunk olvasni, különben egy nyitva tartott kapcsolaton örökké várnánk.

### Korlátok

Egy böngésző idegen szerverekkel beszél, és nem bízhat bennük. Egy hibás (vagy rosszindulatú) szerver küldhet végtelen hosszú sort, ezer fejlécet, vagy `Content-Length: 99999999999`-et. Ezért korlátokat szabunk: egy sor legfeljebb 8 KiB, a fejlécekből legfeljebb 100, a törzs legfeljebb 50 MiB. Ha valami túllépi, `TooLarge` hibát adunk, és nem foglalunk le hozzá memóriát.

### Pufferelt olvasás: `BufReader`

A sorok olvasásához egyesével kellene a bájtokat kérni, amíg `\n` nem jön. A `TcpStream::read` azonban minden hívásnál az operációs rendszerhez fordul (rendszerhívás, system call), ami lassú. A `BufReader` egyszerre egy nagy darabot (8 KiB-ot) olvas be, és abból adagol. Ő adja a `BufRead` traitet a `read_until`-lal és a `read_line`-nal.

A függvényeink `impl BufRead`-et kapnak, nem `TcpStream`-et. Így a tesztekben egy egyszerű bájtszeletből (`&[u8]`) is olvashatnak, hálózat nélkül.

:::compare A válasz máshol
@@ C#
`HttpResponseMessage`: a `StatusCode`, a `ReasonPhrase`, a `Headers` (kis- és nagybetű nem számít) és a `Content`. A `HttpClient.MaxResponseContentBufferSize` ugyanaz a korlát, mint a mi `MAX_BODY`-nk.
@@ C++
C++-ban a `std::istream` és a `std::getline` hasonló a `BufRead`-hez és a `read_line`-hoz. A libcurl a fejléceket egy visszahívással (callback) adja, soronként.
@@ Python
`response = http.client.HTTPConnection(...).getresponse()`: `response.status`, `response.reason`, `response.getheader("content-length")`, `response.read()`. A `socket.makefile("rb")` a Python `BufReader`-e.
@@ Érettségi
A 404-es kódot mindenki látta már. A kódok osztályai (2xx siker, 4xx kliens hiba, 5xx szerver hiba) jó példa arra, hogyan lehet egy szám első jegyébe jelentést kódolni.
:::

A státuszsorhoz a `strip_prefix` és a `split_once` elég:
```rust

use std::io::{self, BufRead, Read};

pub const USER_AGENT: &str = "Rozsda/0.3";
```

A `request` után:

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Response {
    pub status: u16,
    pub reason: String,
    pub headers: Vec<(String, String)>,
    pub body: Vec<u8>,
}

impl Response {
    /// Egy fejléc értéke. A fejlécnevekben nem számít a kis- és nagybetű.
    pub fn header(&self, name: &str) -> Option<&str> {
        self.headers
            .iter()
            .find(|(n, _)| n.eq_ignore_ascii_case(name))
            .map(|(_, v)| v.as_str())
    }

    /// Egy fejléc összes értéke (a `Set-Cookie` pl. többször is jöhet).
    pub fn headers_named<'a>(&'a self, name: &'a str) -> impl Iterator<Item = &'a str> + 'a {
        self.headers
            .iter()
            .filter(move |(n, _)| n.eq_ignore_ascii_case(name))
            .map(|(_, v)| v.as_str())
    }

    pub fn is_redirect(&self) -> bool {
        matches!(self.status, 301 | 302 | 303 | 307 | 308)
    }
}

/// Egy sor a sorvégig (`\r\n`, a kíméletesség kedvéért `\n` is), a sorvég nélkül.
fn read_line(reader: &mut impl BufRead) -> Result<String, HttpError> {
    let mut line = Vec::new();
    reader
        .take(MAX_LINE as u64 + 1)
        .read_until(b'\n', &mut line)?;
    if line.len() > MAX_LINE {
        return Err(HttpError::TooLarge);
    }
    if line.pop() != Some(b'\n') {
        return Err(io::Error::from(io::ErrorKind::UnexpectedEof).into());
    }
    if line.last() == Some(&b'\r') {
        line.pop();
    }
    Ok(String::from_utf8_lossy(&line).into_owned())
}

/// `HTTP/1.1 404 Not Found` → `(404, "Not Found")`. Az ok (reason) el is maradhat.
pub fn parse_status_line(line: &str) -> Result<(u16, String), HttpError> {
    let bad = || HttpError::BadStatusLine(line.to_string());
    let rest = line.strip_prefix("HTTP/1.").ok_or_else(bad)?;
    let (_minor, rest) = rest.split_once(' ').ok_or_else(bad)?;
    let (code, reason) = rest.split_once(' ').unwrap_or((rest, ""));
    if code.len() != 3 || !code.bytes().all(|b| b.is_ascii_digit()) {
        return Err(bad());
    }
    Ok((code.parse().map_err(|_| bad())?, reason.to_string()))
}

/// A válasz: státuszsor, fejlécek az üres sorig, aztán a törzs.
pub fn read_response(reader: &mut impl BufRead) -> Result<Response, HttpError> {
    let (status, reason) = parse_status_line(&read_line(reader)?)?;
    let mut headers = Vec::new();
    loop {
        let line = read_line(reader)?;
        if line.is_empty() {
            break;
        }
        if headers.len() == MAX_HEADERS {
            return Err(HttpError::TooLarge);
        }
        let (name, value) = line
            .split_once(':')
            .ok_or_else(|| HttpError::BadHeader(line.clone()))?;
        headers.push((name.trim().to_string(), value.trim().to_string()));
    }
    let mut response = Response {
        status,
        reason,
        headers,
        body: Vec::new(),
    };
    response.body = read_body(reader, &response)?;
    Ok(response)
}

/// A törzs hossza: előre megmondják (`Content-Length`), vagy a szerver a végén bontja
/// a kapcsolatot. (A harmadik lehetőség, a darabolt átvitel a 08-09-ben jön.)
fn read_body(reader: &mut impl BufRead, response: &Response) -> Result<Vec<u8>, HttpError> {
    if matches!(response.status, 100..=199 | 204 | 304) {
        return Ok(Vec::new()); // ezeknek sosem lehet törzsük
    }
    if let Some(length) = response.header("Content-Length") {
        let length: usize = length
            .parse()
            .map_err(|_| HttpError::BadHeader(format!("Content-Length: {length}")))?;
        if length > MAX_BODY {
            return Err(HttpError::TooLarge);
        }
        let mut body = vec![0; length];
        reader.read_exact(&mut body)?;
        return Ok(body);
    }
    let mut body = Vec::new();
    reader.take(MAX_BODY as u64 + 1).read_to_end(&mut body)?;
    if body.len() > MAX_BODY {
        return Err(HttpError::TooLarge);
    }
    Ok(body)
}
```

:::why Mélyvíz: miért nem `lines()`?
A `BufRead`-nek van `lines()` metódusa, ami kényelmes, de nekünk nem jó. Csak érvényes UTF-8-at fogad el, a fejlécekben pedig lehetnek régi, Latin-1 kódolású bájtok. Nincs benne hosszkorlát, így egy végtelen sor az egész memóriát megtöltené. És a `\r`-t is benne hagyja. Ezért olvasunk bájtokat a `read_until`-lal, és a `from_utf8_lossy` cseréli a hibás bájtokat `�`-re.

```rust test
#[cfg(test)]
mod tests {
    use super::*;
    use std::io::BufRead;
    use std::net::TcpListener;
    use std::thread::JoinHandle;

    /// Egy szerver a saját gépen: a sorban érkező kérésekre sorban a megadott válaszokat
    /// küldi, és visszaadja, milyen kéréseket kapott.
    fn serve(responses: Vec<Vec<u8>>) -> (u16, JoinHandle<Vec<String>>) {
        let listener = TcpListener::bind("127.0.0.1:0").unwrap();
        let port = listener.local_addr().unwrap().port();
        let handle = std::thread::spawn(move || {
            let mut requests = Vec::new();
            for response in responses {
                let (stream, _) = listener.accept().unwrap();
                let mut reader = BufReader::new(&stream);
                let mut request = String::new();
                loop {
                    let mut line = String::new();
                    reader.read_line(&mut line).unwrap();
                    if line == "\r\n" || line.is_empty() {
                        break;
                    }
                    request.push_str(&line);
                }
                requests.push(request);
                (&stream).write_all(&response).unwrap();
            }
            requests
        });
        (port, handle)
    }

    fn url(port: u16, path: &str) -> Url {
        Url::parse(&format!("http://localhost:{port}{path}")).unwrap()
    }

    // 08-08
    #[test]
    fn a_whole_request() {
        let (port, server) = serve(vec![
            b"HTTP/1.1 200 OK\r\nContent-Length: 5\r\n\r\nSzia!".to_vec(),
        ]);
        let response = Client::default().get(&url(port, "/pelda.html")).unwrap();
        assert_eq!(
            (response.status, response.body.as_slice()),
            (200, &b"Szia!"[..])
        );
        let requests = server.join().unwrap();
        assert!(requests[0].starts_with("GET /pelda.html HTTP/1.1\r\n"));
        assert!(requests[0].contains(&format!("Host: localhost:{port}\r\n")));
    }

    #[test]
    fn only_http_for_now() {
        let error = Client::default()
            .get(&Url::parse("https://pelda.hu/").unwrap())
            .unwrap_err();
        assert_eq!(
            error.to_string(),
            "a(z) https: címeket még nem tudjuk letölteni"
        );
    }
}
```

:::solution
```rust
//! A Rozsda hálózati kliense: cím → kapcsolat → kérés → válasz.

use crate::dns::DEFAULT_DNS;
use crate::http::{self, HttpError, Response};
use crate::tcp;
use crate::url::{Url, UrlError};
use std::fmt;
use std::io::{self, BufReader, Write};
use std::net::SocketAddr;

#[derive(Debug)]
pub enum NetError {
    Url(UrlError),
    Io(io::Error),
    Http(HttpError),
    /// Olyan séma, amit még nem tudunk (a `https:` a 9. modulban jön).
    Unsupported(String),
}

impl fmt::Display for NetError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            NetError::Url(e) => write!(f, "{e}"),
            NetError::Io(e) => write!(f, "{e}"),
            NetError::Http(e) => write!(f, "{e}"),
            NetError::Unsupported(scheme) => {
                write!(f, "a(z) {scheme}: címeket még nem tudjuk letölteni")
            }
        }
    }
}

impl std::error::Error for NetError {}

impl From<UrlError> for NetError {
    fn from(e: UrlError) -> NetError {
        NetError::Url(e)
    }
}

impl From<io::Error> for NetError {
    fn from(e: io::Error) -> NetError {
        NetError::Io(e)
    }
}

impl From<HttpError> for NetError {
    fn from(e: HttpError) -> NetError {
        NetError::Http(e)
    }
}

pub struct Client {
    /// Ezt a DNS-szervert kérdezzük
    pub dns: SocketAddr,
}

impl Default for Client {
    fn default() -> Client {
        Client { dns: DEFAULT_DNS }
    }
}

impl Client {
    /// Egyetlen kérés egy `http:` címre, átirányítások nélkül.
    pub fn get(&mut self, url: &Url) -> Result<Response, NetError> {
        if url.scheme != "http" {
            return Err(NetError::Unsupported(url.scheme.clone()));
        }
        let Some(host) = &url.host else {
            return Err(UrlError::BadHost(String::new()).into());
        };
        let stream = tcp::connect(host, url.port_or_default().unwrap_or(80), self.dns)?;
        (&stream).write_all(http::request(url, &[]).as_bytes())?;
        Ok(http::read_response(&mut BufReader::new(&stream))?)
    }
}
```

```rust
//! Egy oldal letöltése és kiírása: státusz, fejlécek, törzs.
//! `cargo run -p rozsda-net --example letolt -- http://localhost:8080/pelda.html`

use rozsda_net::{Client, Url};

fn main() {
    let Some(arg) = std::env::args().nth(1) else {
        eprintln!("használat: letolt <url>");
        std::process::exit(2);
    };
    let result = Url::parse(&arg)
        .map_err(|e| e.to_string())
        .and_then(|url| Client::default().get(&url).map_err(|e| e.to_string()));
    match result {
        Ok(r) => {
            println!("{} {}", r.status, r.reason);
            for (name, value) in &r.headers {
                println!("{name}: {value}");
            }
            println!();
            println!("{}", String::from_utf8_lossy(&r.body));
        }
        Err(e) => {
            eprintln!("Hiba: {e}");
            std::process::exit(1);
        }
    }
}
```

:::exercise Egy fejlécsor
@@ feladat
Bontsd szét egy fejléc sorát! Az első `:` előtt a név, utána az érték. A nevet add vissza **kisbetűsen** (a HTTP-ben a fejlécnevek nem kis- és nagybetű-érzékenyek), mindkettőről vágd le a szóközöket. Ha nincs `:`, vagy a név üres, vagy szóköz van benne, `None`.
@@ kód
```rust
fn parse_header(line: &str) -> Option<(String, String)> {
    todo!()
}
```
@@ megoldás
```rust
fn parse_header(line: &str) -> Option<(String, String)> {
    let (name, value) = line.split_once(':')?;
    if name.is_empty() || name.contains(' ') {
        return None;
    }
    Some((name.to_ascii_lowercase(), value.trim().to_string()))
}
```
@@ magyarázat
A `split_once` egyszer keres, és két szeletet ad, másolás nélkül. Ha előbb mindent szétvágsz a `split(':')`-tal, vagy karakterenként építed a nevet, feleslegesen foglalsz memóriát.
@@ esetek
```rust
parse_header("Content-Type: text/html")
parse_header("CONTENT-LENGTH:5")
parse_header("Date: Wed, 28 Oct 2026 19:22:57 GMT")
parse_header("Location:   http://localhost:8080/a   ")
parse_header("Rossz fejléc")
parse_header(": nincs neve")
parse_header("Rossz nev: x")
parse_header("X-Ures:")
```
@@ mérés
```rust
let lines: Vec<String> = (0..2000).map(|i| format!("X-Hosszu-Fejlec-Neve-{i}: http://localhost:8080/{i}/a:b:c:d")).collect();
---

```
@@ teszt-rossz
```rust
fn parse_header(line: &str) -> Option<(String, String)> {
    let (name, value) = line.split_once(':')?;
    Some((name.to_string(), value.trim().to_string()))
}
```
@@ teszt-lassú
```rust
fn parse_header(line: &str) -> Option<(String, String)> {
    let parts: Vec<String> = line.split(':').map(|p| p.to_string()).collect();
    if parts.len() < 2 || parts[0].is_empty() || parts[0].contains(' ') {
        return None;
    }
    let mut name = String::new();
    for c in parts[0].chars() {
        name = format!("{name}{}", c.to_ascii_lowercase());
    }
    Some((name, parts[1..].join(":").trim().to_string()))
}
```

:::quiz
A válaszban nincs se `Content-Length`, se `Transfer-Encoding`. Hol ér véget a törzs?
- [ ] Az első üres sornál
- [x] Ott, ahol a szerver bontja a kapcsolatot
- [ ] 8 KiB után
> Ez a legrégebbi módszer (HTTP/1.0). Működik, de a kapcsolatot nem lehet újra használni, és a kliens nem tudja megkülönböztetni a teljes választ egy félbeszakadttól.
:::

:::quiz
Miért nem olvasunk törzset egy `304 Not Modified` válasznál, még ha van is `Content-Length` fejléce?
- [ ] Mert a 304 hibát jelent
- [x] Mert a szabvány szerint ennek sosem lehet törzse (a fejléc a gyorsítótárban lévő példányra vonatkozik), és ha olvasni próbálnánk, a kapcsolaton örökké várnánk
- [ ] Mert a 3xx kódok mind átirányítások
> Az 1xx, a 204 és a 304 sosem visz törzset. A 304 `Content-Length`-je a gyorsítótárban lévő példány hosszát mondja meg, nem az ebben a válaszban következő bájtokét.
:::

:::card
K: Honnan tudja a HTTP/1.1 kliens, hol ér véget a válasz törzse?
V: A `Content-Length`-ből (pontos hossz), a `Transfer-Encoding: chunked`-ból (darabok, mindegyik előtt a hossza), vagy ha egyik sincs, a kapcsolat bontásából.
:::

:::card
K: Miért kell korlát a sorok, a fejlécek és a törzs méretére?
V: Mert a böngésző idegen szerverekkel beszél. Korlát nélkül egy hibás vagy rosszindulatú szerver egy végtelen sorral vagy egy óriási `Content-Length`-del megtölthetné a memóriát.
:::
