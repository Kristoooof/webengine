:::goal
Kiolvasod egy glif **körvonalát** (outline): a pontjait, és hogy melyik pont van a görbén, melyik nem. Ehhez két tábla kell: a `loca` megmondja, hol van a glif, a `glyf` leírja. A lecke végén egy teszt az `A` betű 11 pontját ellenőrzi.
:::

## A `loca`: hol van a glif?

A `glyf` tábla a glifek leírásainak egymás után fűzött sora. A glifek különböző hosszúak, ezért kell egy „tartalomjegyzék”: a `loca` (location) tábla. Benne `numGlyphs + 1` szám van, mindegyik egy hely a `glyf` elejétől. Az `i`-edik glif a `loca[i]`-től a `loca[i + 1]`-ig tart.

```text Ábra
loca:  [ 0,  68,  68,  68,  68, 168, …, 5432, 5684, …]
         │    │    │    │    │           │     │
glif:    0    1    2    3    4           36    37

  0. glif (.notdef, a „tofu”): 0-tól 68-ig, 68 bájt
  1–3. glif: üresek (68-tól 68-ig), a 3. a szóköz
  36. glif, az „A”: 5432-től 5684-ig, 252 bájt
```

Ha két szomszédos szám egyenlő, a glif **üres**: ilyen a szóköz, aminek nincs rajza, csak szélessége.

A `loca` kétféle lehet, a `head` tábla 50. bájtján álló `indexToLocFormat` dönti el:

- **rövid** (0): `u16` számok, és a tárolt érték a hely **fele**. Így 16 biten 128 KB-os `glyf` is elfér.
- **hosszú** (1): `u32` számok, a hely maga.

A DejaVu Sans `glyf` táblája 556 004 bájt, ezért hosszú formátumú.

## A `glyf`: egy glif leírása

Minden glif egy 10 bájtos fejléccel kezdődik:

| Hely | Típus | Mező |
|---|---|---|
| 0 | `i16` | `numberOfContours`: a kontúrok száma. **Negatív**, ha összetett glif (07-07) |
| 2–9 | 4 × `i16` | a befoglaló téglalap: `xMin`, `yMin`, `xMax`, `yMax` |

A **kontúr** (contour) egy zárt körvonal. Az `o`-nak kettő van (a külső és a belső kör), az `A`-nak is kettő (a külső alak és a háromszög alakú lyuk), az `i`-nek is kettő (a szár és a pont).

Egy **egyszerű** (simple) glif fejléc utáni része:

```text Ábra
endPtsOfContours   u16 × kontúrok   minden kontúr utolsó pontjának sorszáma
instructionLength  u16              a hinting-utasítások hossza
instructions       u8 × hossz       (átugorjuk)
flags              u8 × ?           pontonként egy jelző, ismétléssel tömörítve
xCoordinates       1 vagy 2 bájt    pontonként, az előzőhöz képest
yCoordinates       1 vagy 2 bájt    pontonként, az előzőhöz képest
```

Az `A` 252 bájtjából 194 a **hinting**-utasítás: egy kis program, ami kis méretben a pixelrácshoz igazítja a pontokat (lásd a mélyvizet). A 11 pont maga mindössze 42 bájtot foglal, mert erősen tömörítettek.

### A jelzők (flags)

Minden ponthoz tartozik egy jelzőbájt:

| Bit | Név | Jelentés |
|---|---|---|
| 0x01 | `ON_CURVE` | a pont a görbén van (különben vezérlőpont) |
| 0x02 | `X_SHORT` | az x 1 bájtos |
| 0x04 | `Y_SHORT` | az y 1 bájtos |
| 0x08 | `REPEAT` | a következő bájt megmondja, hányszor ismétlődik ez a jelző **még** |
| 0x10 | `X_SAME` | rövid x-nél: pozitív. Hosszú x-nél: nincs változás, nincs bájt |
| 0x20 | `Y_SAME` | ugyanez az y-ra |

### A koordináták: eltolások

A koordináták **eltolások** (delta) az előző ponthoz képest, az első pont a (0, 0)-hoz képest. Előbb jön az összes x, utána az összes y. Egy x a jelzője szerint:

- `X_SHORT` be: 1 bájt (0–255), és az `X_SAME` az előjel (1: +, 0: −).
- `X_SHORT` ki, `X_SAME` be: nincs bájt, az x **ugyanaz**, mint az előző.
- mindkettő ki: 2 bájtos, előjeles `i16`.

Így egy vízszintes szakasz végpontjának y-ja **nulla** bájt, egy kis lépés egy bájt. Ezért olyan kicsi egy glif.

```text Ábra
  az „A” pontjai (font-egységben)

                 3 ●─────● 4               3: (586, 1493)   4: (815, 1493)
                  ╱       ╲                5: (1384, 0)     6: (1174, 0)
                 ╱    ● 0  ╲               7: (1038, 383)   8: (365, 383)
                ╱    ╱ ╲    ╲              9: (229, 0)     10: (16, 0)
               ╱    ╱   ╲    ╲
              ╱  1 ●─────● 2  ╲            a lyuk: 0: (700, 1294)
             ╱                 ╲                   1: (426, 551)
            ╱  8 ●─────────● 7  ╲                  2: (975, 551)
           ╱    ╱           ╲    ╲
       10 ●───●  9         6 ●───● 5
```

:::hint
A `read_coords` egy összeg (`value`), amihez pontonként hozzáadod az eltolást, és a részösszegeket gyűjtöd:
```rust
for &flag in flags {
    if flag & short != 0 {
        // 1 bájt, a `same` bit az előjel
    } else if flag & same == 0 {
        // 2 bájtos i16
    }
    // különben: nincs változás
    out.push(value);
}
```
---
A jelzők ismétlése: olvass egy jelzőt, tedd a listába, és ha a `REPEAT` bit be van kapcsolva, olvasd ki a következő bájtot (`n`), és tedd be még `n`-szer. Addig, amíg meg nincs a pontok száma. A pontok száma az utolsó kontúr végpontja + 1.

Egy hibás fájl túl sok ismétlést is kérhet: a végén vágd le a listát (`flags.truncate(num_points)`).
---
A kontúrokra osztás: a `start` az első kontúrnál 0, utána mindig az előző `end + 1`. Egy kontúr a `start..=end` pontokból áll. Ellenőrizd, hogy az `end` nem kisebb a `start`-nál, és nem lóg ki: egy rossz fájlban ez is előfordulhat.
---
A `glyph_data`-ban a hosszú formátumnál `Reader::at(self.data, self.loca.offset + 4 * i)`, és két `u32`: ez a `loca[i]` és a `loca[i + 1]`. A rövidnél `2 * i`, két `u16`, és mindkettőt meg kell szorozni 2-vel.

:::solution
```rust
//! A glifek körvonalai: a `loca` megmondja, hol van egy glif a `glyf` táblában.

use crate::Font;
use crate::reader::Reader;

/// Egy kontúrpont font-egységben. A görbén kívüli pont egy Bézier-görbe vezérlőpontja.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Point {
    pub x: f32,
    pub y: f32,
    pub on_curve: bool,
}

/// Egy zárt körvonal pontjai.
pub type Contour = Vec<Point>;

// A pontok jelzőbitjei (flags)
const ON_CURVE: u8 = 0x01;
const X_SHORT: u8 = 0x02;
const Y_SHORT: u8 = 0x04;
const REPEAT: u8 = 0x08;
const X_SAME: u8 = 0x10;
const Y_SAME: u8 = 0x20;

/// A koordináták az előző ponthoz képest vannak megadva (delta), 1 vagy 2 bájton.
/// Rövid alaknál a `same` bit az előjel (1: pozitív), hosszúnál azt jelenti, hogy nincs változás.
fn read_coords(r: &mut Reader, flags: &[u8], short: u8, same: u8) -> Option<Vec<i32>> {
    let mut value = 0;
    let mut out = Vec::with_capacity(flags.len());
    for &flag in flags {
        if flag & short != 0 {
            let delta = r.u8()? as i32;
            value += if flag & same != 0 { delta } else { -delta };
        } else if flag & same == 0 {
            value += r.i16()? as i32;
        }
        out.push(value);
    }
    Some(out)
}

/// Egyszerű glif: kontúrok végpontjai, utasítások (átugorjuk), jelzők, x-ek, y-ok.
fn parse_simple(data: &[u8], num_contours: usize) -> Option<Vec<Contour>> {
    let mut r = Reader::at(data, 10);
    let mut ends = Vec::with_capacity(num_contours);
    for _ in 0..num_contours {
        ends.push(r.u16()? as usize);
    }
    let num_points = ends.last().map_or(0, |&end| end + 1);
    let instructions = r.u16()? as usize;
    r.skip(instructions);

    let mut flags = Vec::with_capacity(num_points);
    while flags.len() < num_points {
        let flag = r.u8()?;
        flags.push(flag);
        if flag & REPEAT != 0 {
            for _ in 0..r.u8()? {
                flags.push(flag);
            }
        }
    }
    flags.truncate(num_points);
    let xs = read_coords(&mut r, &flags, X_SHORT, X_SAME)?;
    let ys = read_coords(&mut r, &flags, Y_SHORT, Y_SAME)?;

    let mut contours = Vec::with_capacity(num_contours);
    let mut start = 0;
    for end in ends {
        if end < start || end >= num_points {
            return None;
        }
        let contour = (start..=end)
            .map(|i| Point {
                x: xs[i] as f32,
                y: ys[i] as f32,
                on_curve: flags[i] & ON_CURVE != 0,
            })
            .collect();
        contours.push(contour);
        start = end + 1;
    }
    Some(contours)
}

impl Font<'_> {
    /// Egy glif adatai a `glyf` táblából. Az üres glif (pl. a szóköz) üres szelet.
    pub fn glyph_data(&self, glyph: u16) -> Option<&[u8]> {
        if glyph >= self.num_glyphs {
            return None;
        }
        let i = glyph as usize;
        let (start, end) = if self.loca_long {
            let mut r = Reader::at(self.data, self.loca.offset + 4 * i);
            (r.u32()? as usize, r.u32()? as usize)
        } else {
            // a rövid alakban a hely fele van tárolva, hogy elférjen 16 biten
            let mut r = Reader::at(self.data, self.loca.offset + 2 * i);
            (2 * r.u16()? as usize, 2 * r.u16()? as usize)
        };
        if start > end || end > self.glyf.len {
            return None;
        }
        self.data
            .get(self.glyf.offset + start..self.glyf.offset + end)
    }

    /// Egy glif kontúrjai font-egységben. Üres glifnél üres a lista.
    pub fn outline(&self, glyph: u16) -> Option<Vec<Contour>> {
        let data = self.glyph_data(glyph)?;
        if data.is_empty() {
            return Some(Vec::new());
        }
        let num_contours = Reader::new(data).i16()?;
        if num_contours >= 0 {
            parse_simple(data, num_contours as usize)
        } else {
            None // összetett glif (pl. az á): a 07-07-ben
        }
    }
}
```

@@ C++

@@ Python

A `glyf.rs` a `Font` privát mezőit (`data`, `loca`, `glyf`) is látja, mert ugyanabban a crate-ben van, és a `lib.rs` (a szülőmodul) definiálja őket. A Rustban a láthatóság **modul**alapú: a privát elem a saját moduljában és annak almoduljaiban látszik.

:::why Mélyvíz: hinting
Egy 2048 egységes em-ben a pontok 1/128 pixel pontosságúak 16px-en. Ha egy függőleges szár épp két pixel határára esik, mindkét pixel félig szürke lesz, és a betű elmosódik. A **hinting** erre egy megoldás: a fontba írt kis program (a TrueType-utasítások, egy veremgépre írt bájtkód) méret szerint elmozgatja a pontokat, hogy a szárak egész pixelekre essenek.

A TrueType-utasítások értelmezője egy teljes virtuális gép, több mint 200 utasítással. A FreeType-ban ez több ezer sor. A modern rendszerek (macOS, és egyre inkább a Windows és a Linux is) a nagy felbontású kijelzők miatt sokszor ki se kapcsolják a hintinget, vagy csak függőlegesen alkalmazzák. Mi kihagyjuk: a betűink kicsit lágyabbak lesznek, de helyesek.
