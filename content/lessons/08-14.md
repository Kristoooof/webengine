## Még egy kapcsoló: `--halo`

A parser, a stílusmotor és a layout mögött is egy trait áll a core-ban, és egy kapcsoló választ a saját és a profi között. A hálózat ugyanígy kap egyet:

```rust
pub trait Fetcher {
    fn name(&self) -> &'static str;
    fn load(&mut self, url: &str) -> Result<Resource, String>;
}
```

A saját oldalon a `Client` valósítja meg, a profi oldalon a 16. modulban a `reqwest` crate fogja. A böngésző csak a traitet látja: `Box<dyn Fetcher>`. Miért `&mut self`? Mert a kliens a sütiket tárolja, és minden letöltés írhat a süti-tárolóba. Ezért a böngésző **egyetlen** klienst tart meg a program végéig: így a sütik megmaradnak az oldalak között.

## A végső cím

A 06-06-ban a linkek fájlútvonalak voltak, az aktuális fájl mappájához képest. Most az oldalnak **címe** van, és a linkek ehhez képest oldódnak fel, a `Url::join`-nal (08-03). De melyik címhez? Ha a `http://pelda.hu/regi` egy átirányítással a `http://pelda.hu/cikkek/vegso.html`-re visz, egy `kep.html` link a `http://pelda.hu/cikkek/kep.html`, nem a `http://pelda.hu/kep.html`. Ezért adja a `Resource` a **végső** címet, és ezt jegyzi meg a `Page`.

## A parancssor: cím vagy fájl

A böngésző eddig egy fájlútvonalat kapott. Most egy címet is kaphat: `http://…`, `data:…`, `file:…`. A fájlútvonal is maradjon, mert kényelmes. A kettőt úgy választjuk szét, hogy megpróbáljuk címként értelmezni, és ha nem megy, fájl. Egy csapda van benne:

```text Ábra
C:\Users\Rozsda\oldalak\pelda.html
│└──────── ez a „cím” többi része
└ séma: „c”
```

A `C:\…` a URL-parser szerint egy érvényes cím, `c` sémával! Az igazi sémák legalább két betűsek, ezért az egybetűs sémát meghajtóbetűnek vesszük, és fájlútvonalként kezeljük.

:::compare Betöltés a böngészőkben
@@ C#
A WPF/WinForms `WebBrowser` vezérlő `Navigate(uri)` metódusa ugyanígy elfogad `http:`, `file:` és `data:` címeket, és a `Navigated` eseményben a végső címet adja.
@@ C++
A Chromiumban a `NetworkService` egy külön **folyamat** (process): a böngésző egy felületen (`URLLoader`) kéri a címeket, és nem tudja, mi van mögötte. Ez a mi `Fetcher` traitünk nagyban.
@@ Python
`urllib.request.urlopen(cím)` ugyanígy kezel minden sémát, és a `response.url` a végső cím az átirányítások után.
@@ Érettségi
A böngésző címsorába írt cím feldolgozása (séma, gép, útvonal) és a relatív linkek feloldása a HTML-feladatoknál is előjön: a `<a href="../index.html">` a mappaszerkezethez képest értendő.
:::

```rust
    /// Egy cím betöltése (`http:`, `file:`, `data:`) a hálózaton keresztül.
    pub fn open(
        engines: &Engines,
        net: &mut dyn Fetcher,
        url: &Url,
        width: f32,
    ) -> Result<Page, String> {
        let resource = net.load(&url.to_string())?;
        // Egyelőre minden oldalt UTF-8-nak veszünk; a hibás bájtok helyére � kerül.
        let source = String::from_utf8_lossy(&resource.body);
        let mut page = Page::load(engines, &source, width)?;
        page.url = Url::parse(&resource.url).map_err(|e| e.to_string())?;
        Ok(page)
    }

    /// Egy link célja az oldal címéhez képest. Az oldalon belüli ugrásokat (`#…`) még nem követjük.
    pub fn link_target(&self, href: &str) -> Option<Url> {
        if href.starts_with('#') {
            return None;
        }
        self.url.join(href).ok()
    }
```

:::exercise Vissza és előre
@@ feladat
A böngészők előzménye két verem: a **vissza** (back) és az **előre** (forward). Szimuláld! Az oldal a `start` címen kezdődik. Minden lépés egy cím (oda megyünk), vagy `"vissza"`, vagy `"elore"`.

- Egy új címre lépve a jelenlegi oldal a vissza-verembe kerül, és az előre-verem **kiürül**.
- A `"vissza"` a jelenlegit az előre-verembe teszi, és a vissza-verem tetejére lép. Ha üres a vissza-verem, nem történik semmi.
- Az `"elore"` ugyanez, fordítva.

Add vissza a jelenlegi címet, és a két verem méretét.
@@ kód

@@ megoldás
```rust
fn browse(start: &str, steps: &[&str]) -> (String, usize, usize) {
    let mut current = start.to_string();
    let mut back: Vec<String> = Vec::new();
    let mut forward: Vec<String> = Vec::new();
    for &step in steps {
        match step {
            "vissza" => {
                if let Some(previous) = back.pop() {
                    forward.push(std::mem::replace(&mut current, previous));
                }
            }
            "elore" => {
                if let Some(next) = forward.pop() {
                    back.push(std::mem::replace(&mut current, next));
                }
            }
            url => {
                back.push(std::mem::replace(&mut current, url.to_string()));
                forward.clear();
            }
        }
    }
    (current, back.len(), forward.len())
}
```

```rust
    let mut current = start.to_string();

    let mut forward: Vec<String> = Vec::new();
```
