:::goal
A glif pontjaiból egyenes szakaszok listáját készíted, pixelben. A görbék **másodfokú Bézier-görbék**, és ezeket sok rövid egyenessel közelíted, olyan finoman, hogy a hiba legfeljebb negyed pixel legyen. A lecke végén egy „kör” négy vezérlőpontjából egy sima, zárt sokszög lesz.
:::

## Görbe három pontból

Egy TrueType-görbét három pont ad meg: a két végpont (`p0`, `p1`) a görbén van, a köztük lévő **vezérlőpont** (`c`, control point) nincs rajta, csak „magához húzza” a görbét. A görbe pontjai a `t` paraméterrel (0-tól 1-ig):

```text Képlet
B(t) = (1 − t)² · p0  +  2 · (1 − t) · t · c  +  t² · p1
```

`t = 0`-nál `B = p0`, `t = 1`-nél `B = p1`, közben a görbe a `c` felé hajlik, de sosem éri el.

Van egy szemléletes szerkesztés is (**de Casteljau-algoritmus**): a `p0→c` és a `c→p1` szakaszon is menj el `t` arányban, aztán a két kapott pontot összekötő szakaszon is `t` arányban. Ahová érsz, az a görbe pontja.

```text Ábra
                c
               ╱ ╲              t = 0,5-nél:
              ╱   ╲             a = p0 és c közepe
           a ●─────● b          b = c és p1 közepe
            ╱  ●    ╲           a görbe pontja: a és b közepe (●)
           ╱ ╱   ╲   ╲
          ╱╱       ╲  ╲
      p0 ●           ╲─● p1
```

A képlet a másodfokú (quadratic) Bézier-görbe. A TrueType csak ilyet használ. A CFF-fontok, az SVG és a CSS `path()` **harmadfokú** (cubic) görbét is ismer, két vezérlőponttal. Ugyanaz az elv, csak egy taggal több.

@@ C#

@@ C++

@@ Python

@@ Érettségi

:::

## A kimondatlan pontok

A TrueType egy trükkel spórol: ha két **vezérlőpont** követi egymást, a kettő **felezőpontja** is a görbén van, csak nincs leírva. Így egy kör négy vezérlőpontból áll, a négy görbén lévő pont „kimondatlan”.

```text Ábra
     ○ ─ ─ ─ ● ─ ─ ─ ○          ○ leírt vezérlőpont
     ╎    ╱     ╲    ╎          ● kimondatlan pont: két ○ felezőpontja
     ╎  ╱         ╲  ╎
     ● ╱           ╲ ●
     ╎╲           ╱  ╎
     ╎  ╲       ╱    ╎
     ○ ─ ─ ─ ● ─ ─ ─ ○
```

Egy kontúr bejárásakor tehát négy eset van, attól függően, hogy az aktuális pont a görbén van-e, és van-e függőben lévő vezérlőpontunk:

| Aktuális pont | Függő vezérlőpont | Teendő |
|---|---|---|
| görbén | nincs | egyenes a tolltól idáig |
| görbén | van (`c`) | görbe a tolltól idáig, `c`-vel |
| vezérlő | nincs | megjegyezzük |
| vezérlő | van (`c`) | görbe a tolltól `c` és az új pont **felezőjéig**, az új pont lesz a függő |

A bejárást egy görbén lévő pontról kezdjük. Ha egy sincs (mint a körnél), az utolsó és az első pont felezőpontjáról. A kontúr zárt: a végén vissza kell érni a kezdőpontba.

## Görbéből egyenesek

A raszterizáló (07-05) csak egyenes szakaszokat ismer. A görbét ezért `n` darab rövid egyenessel közelítjük (**flattening**): kiszámoljuk a `B(1/n)`, `B(2/n)` … pontokat, és összekötjük őket.

De mennyi legyen az `n`? Kevés darabtól szögletes lesz a betű, sok darab lassú. Van erre egy szép képlet. A görbe legfeljebb `|p0 − 2c + p1| / 4` távolságra tér el a húrjától (a `p0–p1` szakasztól), és ha `n` darabra vágjuk, minden darab eltérése az `n²`-ed részére csökken. Ha a hibát negyed pixelben maximáljuk:

```text Képlet
|p0 − 2c + p1| / (4 · n²)  ≤  1/4      ⟹      n = ⌈√|p0 − 2c + p1|⌉
```

Egy egyenes „görbénél” (`c` épp középen) `|p0 − 2c + p1| = 0`, és egy darab elég. Egy 16px-es „o” negyedkörei 2-2 darabot kapnak, egy 200 pixelesé 5-öt: a felbontás magától a mérethez igazodik.

## Font-egységből pixel

A pontok font-egységben vannak, a raszterizáló pixelben dolgozik. Az átváltás egy nagyítás és egy eltolás. Van még egy csavar: a fontban az **y felfelé** nő (a matematikában megszokott módon), a képernyőn **lefelé**. Ezért az y-t meg kell fordítani:

```rust
    pub fn apply(&self, p: Point) -> (f32, f32) {
        (p.x * self.scale + self.dx, self.dy - p.y * self.scale)
    }
```

A `scale` 16px-es betűnél 16 / 2048 = 0,0078125, a `dy` pedig az, ahová a font y = 0 (az alapvonal) kerül a képen.


A kezdőpont: `points.iter().position(|&(_, on)| on)` megkeresi az első görbén lévőt. Ha van, onnan indulsz, és a **következő** ponttól jársz körbe. Ha nincs, az utolsó és az első felezőpontjáról, és a 0. ponttól.
---

:::solution
```rust
//! Kontúrokból egyenes szakaszok, pixelben: a görbéket sok rövid egyenessel közelítjük.

use crate::glyf::{Contour, Point};

/// Egy egyenes szakasz pixel-koordinátákban (az y lefelé nő).
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Line {
    pub x0: f32,
    pub y0: f32,
    pub x1: f32,
    pub y1: f32,
}

impl Line {
    fn new(a: (f32, f32), b: (f32, f32)) -> Line {
        Line {
            x0: a.0,
            y0: a.1,
            x1: b.0,
            y1: b.1,
        }
    }
}

/// Font-egységből pixelbe: nagyítás, eltolás, és az y tengely megfordítása
/// (a fontban az y felfelé nő, a képernyőn lefelé).
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Transform {
    pub scale: f32,
    pub dx: f32,
    pub dy: f32,
}

impl Transform {
    pub fn apply(&self, p: Point) -> (f32, f32) {
        (p.x * self.scale + self.dx, self.dy - p.y * self.scale)
    }
}

fn mid(a: (f32, f32), b: (f32, f32)) -> (f32, f32) {
    ((a.0 + b.0) / 2.0, (a.1 + b.1) / 2.0)
}

/// Egy pont a másodfokú Bézier-görbén: (1−t)²·p0 + 2(1−t)t·c + t²·p1.
pub fn quad_point(p0: (f32, f32), c: (f32, f32), p1: (f32, f32), t: f32) -> (f32, f32) {
    let u = 1.0 - t;
    (
        u * u * p0.0 + 2.0 * u * t * c.0 + t * t * p1.0,
        u * u * p0.1 + 2.0 * u * t * c.1 + t * t * p1.1,
    )
}

/// Egy másodfokú görbe egyenesekre bontva. A görbe legfeljebb |p0 − 2c + p1| / 4 távolságra
/// tér el a húrjától, és n darabra vágva ennek az n²-ed részére. n = ⌈√|p0 − 2c + p1|⌉ darabbal
/// a hiba legfeljebb negyed pixel.
pub fn flatten_quad(out: &mut Vec<Line>, p0: (f32, f32), c: (f32, f32), p1: (f32, f32)) {
    let dx = p0.0 - 2.0 * c.0 + p1.0;
    let dy = p0.1 - 2.0 * c.1 + p1.1;
    let n = dx.hypot(dy).sqrt().ceil().max(1.0) as usize;
    let mut prev = p0;
    for i in 1..=n {
        let p = quad_point(p0, c, p1, i as f32 / n as f32);
        out.push(Line::new(prev, p));
        prev = p;
    }
}

/// Egy kontúr bejárása. A görbén lévő pontok között egyenes van, a görbén kívüli pont egy
/// görbe vezérlőpontja. Két egymás utáni görbén kívüli pont felezőpontja egy „kimondatlan”,
/// görbén lévő pont: így spórol a TrueType a pontokkal.
pub fn contour_lines(contour: &[Point], t: Transform, out: &mut Vec<Line>) {
    let points: Vec<((f32, f32), bool)> =
        contour.iter().map(|&p| (t.apply(p), p.on_curve)).collect();
    if points.len() < 2 {
        return;
    }
    // Az első görbén lévő pontról indulunk. Ha nincs ilyen, az utolsó és az első felezőpontjáról.
    let (start, first) = match points.iter().position(|&(_, on)| on) {
        Some(i) => (points[i].0, i + 1),
        None => (mid(points[points.len() - 1].0, points[0].0), 0),
    };
    let mut pen = start;
    let mut control: Option<(f32, f32)> = None;
    for k in 0..points.len() {
        let (p, on_curve) = points[(first + k) % points.len()];
        match (on_curve, control) {
            (true, None) => {
                out.push(Line::new(pen, p));
                pen = p;
            }
            (true, Some(c)) => {
                flatten_quad(out, pen, c, p);
                pen = p;
                control = None;
            }
            (false, None) => control = Some(p),
            (false, Some(c)) => {
                let m = mid(c, p);
                flatten_quad(out, pen, c, m);
                pen = m;
                control = Some(p);
            }
        }
    }
    if let Some(c) = control {
        flatten_quad(out, pen, c, start);
    }
}

/// Az összes kontúr egyenesei.
pub fn to_lines(contours: &[Contour], t: Transform) -> Vec<Line> {
    let mut out = Vec::new();
    for contour in contours {
        contour_lines(contour, t, &mut out);
    }
    out
}
```
:::

A `match (on_curve, control)` egy **párra** illeszt: egyszerre két érték mintáját vizsgálja. A négy ág pontosan a táblázat négy sora, és ha valamelyik hiányozna, a fordító szólna („non-exhaustive patterns”).

:::why Mélyvíz: miért pont ⌈√d⌉?
Írjuk fel a görbét a húrjához képest. A `B(t) − ((1 − t)·p0 + t·p1)` különbség `t(1 − t)·(2c − p0 − p1)`. Ennek a `t(1 − t)` tényezője `t = 1/2`-nél a legnagyobb, `1/4`. A legnagyobb eltérés tehát `|p0 − 2c + p1| / 4`.

Ha a görbét `n` egyenlő részre vágjuk, minden darab maga is egy másodfokú Bézier-görbe, és a „`p0 − 2c + p1`” mennyisége az `n²`-ed részére csökken (mert a második derivált `t` szerint állandó, és a darabok `t`-ben `1/n` hosszúak). A hiba így `d / (4n²)`, ami `n = √d`-nél épp `1/4` pixel.

A FreeType és a font-rs (egy gyors, Rustban írt raszterizáló) is ezt a becslést használja. Harmadfokú görbéknél a képlet hasonló, csak a harmadik derivált is beszól.
