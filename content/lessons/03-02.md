## Az állapotgép, újra

Az 1. modul `CursorTokenizer`-e már egy kicsi állapotgép volt, csak „rejtve”: hogy hol tartunk, az a kód szerkezetéből derült ki (épp melyik ciklusban vagyunk). A szabvány ezzel szemben **kimondott** állapotokkal dolgozik: van egy `state` változó, és minden karakternél az dönti el, mi történjen.

```text Ábra
            '<'                 betű
  ┌──────┐ ─────► ┌─────────┐ ─────► ┌─────────┐
  │ Data │        │ TagOpen │        │ TagName │ ...
  └──────┘ ◄───── └─────────┘        └─────────┘
      ▲   bármi más: a '<' szöveg lesz,
      │   és a karaktert a Data újra feldolgozza
      └── minden más karakter: szöveg
```

A nagy előny: az állapotgép **soha nem akad el**. Minden állapotban, minden karakterre (és a bemenet végére is) van szabály. A hibás HTML is csak egy út az állapotok között.

## A motor részei

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
enum State {
    Data,
    TagOpen,
}

pub struct Tokenizer {
    input: Vec<char>,
    pos: usize,
    state: State,
    tokens: Vec<Token>,
    text: String,
}
```

- `input`, `pos`: ugyanaz a trükk, mint a `Cursor`-ban: karaktervektor és pozíció.
- `state`: hol tartunk.
- `tokens`: a kimenet.
- `text`: az épp gyűlő szöveg. Csak akkor lesz belőle `Token::Text`, amikor valami más token jön (ezt hívjuk *flush*-nak).

### Két apró, de fontos segédfüggvény

```rust
/// A következő karakter. A pozíció a bemenet végén is nő, így a reconsume mindig működik.
fn next_char(&mut self) -> Option<char> {
    let c = self.input.get(self.pos).copied();
    self.pos += 1;
    c
}

fn reconsume(&mut self) {
    self.pos -= 1;
}
```

Figyeld meg: a `next_char` akkor is növeli a `pos`-t, ha `None`-t ad. Ettől lesz a `reconsume` mindig egyszerű visszalépés, akkor is, ha a fájl végén kell újra „elolvasni” az EOF-ot.

### A fő ciklus

```rust
pub fn run(mut self) -> Vec<Token> {
    loop {
        let c = self.next_char();
        match self.state {
            State::Data => match c {
                Some('<') => self.state = State::TagOpen,
                Some(c) => self.text.push(c),
                None => break,
            },
            State::TagOpen => match c {
                // ...
            },
        }
    }
    self.emit_eof();
    self.tokens
}
```

Egy `match` a `match`-ben: a külső az állapotot, a belső a karaktert vizsgálja. Ez szó szerint a szabvány szerkezete. Ha a fordító szól, hogy egy állapotot nem kezeltél, akkor egy szabványrészlet hiányzik.

:::note Miért run(mut self), és miért nem &mut self?
A `run` **elfogyasztja** a tokenizert (`self` érték szerint). A tokenizálás egyszer fut le, utána a tokenizerre már nincs szükség, ezért a `tokens` vektort move-val visszaadhatjuk, másolás nélkül. Ez az ownership gyakorlati haszna: a típusrendszer kifejezi, hogy „ezt csak egyszer lehet lefuttatni”.
:::

## A TagOpen állapot

A szabvány szerint (13.2.5.6, egyszerűsítve):

> **Tag nyitása állapot.** Fogyaszd el a következő karaktert:
> - **`!`** → válts a markup-deklaráció állapotra *(03-05)*
> - **`/`** → válts a zárótag-nyitás állapotra *(03-03)*
> - **ASCII-betű** → hozz létre egy új kezdőtag-tokent, és dolgozd fel újra (reconsume) a tagnév állapotban *(03-03)*
> - **`?`** → parse error, hamis komment *(03-05)*
> - **EOF** → parse error. Bocsáss ki egy `<` karaktert és egy EOF-tokent.
> - **Bármi más** → parse error. Bocsáss ki egy `<` karaktert, és dolgozd fel újra az adat állapotban.

Ezért szöveg a `<3`: a `<` után nem betű jön, tehát a `<` csak egy kisebb-jel. Ma a két utolsó szabályt írod meg. A betűs ágat egy `todo!()` jelöli. Ez a makró lefordul, de ha a program odaér, pánikol egy üzenettel. Kiváló „ide még jön valami” jelző.

        assert_eq!(tokenize("a < b"), vec![text("a < b"), Token::Eof]);

:::hint
A `std::mem::take(&mut x)` kiveszi `x` értékét, és egy alapértéket (üres `String`-et) hagy a helyén. Így tudsz egy mezőből értéket „kimozgatni” úgy, hogy a struct érvényes marad. Egy `&mut self` metódusban a `self.text`-et nem lehet egyszerűen move-olni, mert akkor a struct „lyukas” lenne.
---
A `TagOpen` „bármi más” ága három lépés: `self.text.push('<')`, aztán `self.reconsume()`, aztán `self.state = State::Data`. Az EOF ágban nincs reconsume, csak a `<`, aztán `break`.
---
Az `a < b` esetén: `a`, szóköz (Data) → `<` (TagOpen-be vált) → szóköz: „bármi más”, tehát a `<` szöveg lesz, és a szóközt a Data újra feldolgozza → `b`. A vége: `"a < b"`, egyetlen szövegtoken.
:::

:::solution
```rust
#[derive(Debug, Clone, Copy, PartialEq)]
enum State {
    Data,
    TagOpen,
}

pub struct Tokenizer {
    input: Vec<char>,
    pos: usize,
    state: State,
    tokens: Vec<Token>,
    text: String,
}

pub fn tokenize(input: &str) -> Vec<Token> {
    Tokenizer::new(input).run()
}

impl Tokenizer {
    pub fn new(input: &str) -> Tokenizer {
        Tokenizer {
            input: preprocess(input).chars().collect(),
            pos: 0,
            state: State::Data,
            tokens: Vec::new(),
            text: String::new(),
        }
    }

    fn next_char(&mut self) -> Option<char> {
        let c = self.input.get(self.pos).copied();
        self.pos += 1;
        c
    }

    fn reconsume(&mut self) {
        self.pos -= 1;
    }

    fn flush_text(&mut self) {
        if !self.text.is_empty() {
            self.tokens.push(Token::Text(std::mem::take(&mut self.text)));
        }
    }

    fn emit(&mut self, token: Token) {
        self.flush_text();
        self.tokens.push(token);
    }

    fn emit_eof(&mut self) {
        self.emit(Token::Eof);
    }

    pub fn run(mut self) -> Vec<Token> {
        loop {
            let c = self.next_char();
            match self.state {
                State::Data => match c {
                    Some('<') => self.state = State::TagOpen,
                    Some(c) => self.text.push(c),
                    None => break,
                },
                State::TagOpen => match c {
                    Some(c) if c.is_ascii_alphabetic() => todo!("03-03: tagnév"),
                    Some(_) => {
                        self.text.push('<');
                        self.reconsume();
                        self.state = State::Data;
                    }
                    None => {
                        self.text.push('<');
                        break;
                    }
                },
            }
        }
        self.emit_eof();
        self.tokens
    }
}
```

:::why Miért nem reguláris kifejezés?
Egyszerű feladatokra a regex kényelmes, de a HTML-hez nem elég. A HTML nem „reguláris nyelv” (az egymásba ágyazás miatt), és a szabvány hibakezelése állapotfüggő: ugyanaz a karakter mást jelent egy attribútumértékben, egy kommentben és egy `<script>`-ben. Az állapotgép ráadásul gyors (minden karaktert egyszer néz meg), és pontosan megfeleltethető a szabvány szövegének. Van egy híres Stack Overflow-válasz arról, mi történik azzal, aki regexszel próbál HTML-t parse-olni. Érdemes megkeresni. 😄
