## Függvények

```rust
fn start_tag_len(name: &str) -> usize {
    name.len() + 2
}
```

- `fn`: függvény.
- `name: &str`: a paraméter neve és típusa. A típust **mindig** ki kell írni.
- `-> usize`: a visszatérési típus.
- `name.len() + 2`: **nincs a végén pontosvessző**, és ez nem elírás!

### Kifejezések és utasítások

Rustban szinte minden **kifejezés** (expression), vagyis értéke van. Egy blokk (`{ ... }`) értéke az utolsó kifejezése, **ha az nem pontosvesszővel végződik**. Ezért nem kell `return`:

```rust
fn end_tag_len(name: &str) -> usize {
    name.len() + 3      // ez a visszatérési érték
}
```

Ha pontosvesszőt teszel a végére, az már **utasítás** lesz, aminek nincs értéke (pontosabban `()`, a „unit”, ami kb. a `void`):

```text
error[E0308]: mismatched types
 --> src/main.rs:1:31
  |
1 | fn end_tag_len(name: &str) -> usize {
  |    -----------                ^^^^^ expected `usize`, found `()`
2 |     name.len() + 3;
  |                   - help: remove this semicolon to return this value
```

Megint: a fordító pontosan megmondja, mit törölj.

A `return` is létezik. Korai kilépésre használjuk, például ha egy feltétel már az elején eldönti az eredményt.

:::compare
@@ C#
```csharp
static int StartTagLen(string name) {
    return name.Length + 2;
}
// vagy expression-bodied member:
static int StartTagLen(string name) => name.Length + 2;
```
@@ Rust
```rust
fn start_tag_len(name: &str) -> usize {
    name.len() + 2
}
```
A Rust minden blokkja úgy viselkedik, mint a C#-os `=>` kifejezés-törzs.
@@ Python
```python
def start_tag_len(name: str) -> int:
    return len(name) + 2
```
A Python típusjelölése csak tipp. A Rusté kötelező, és a fordító ellenőrzi.
:::

:::note A `&str` paraméterről
A `name: &str` azt jelenti, hogy a függvény **kölcsönkap** egy szöveget, de nem lesz a tulajdonosa. Hogy pontosan mit jelent a `&`, azt a 01-04-es és a 01-05-ös lecke magyarázza el. Addig elég annyi, hogy **szöveg-paraméternek `&str`-t írunk**.
:::

## Tesztek

A Rustban a tesztek a kód mellett laknak, ugyanabban a fájlban. Írd a `main.rs` **aljára**:

```rust test
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn tag_lengths() {
        assert_eq!(start_tag_len("p"), 3);
        assert_eq!(start_tag_len("div"), 5);
        assert_eq!(end_tag_len("div"), 6);
    }
}
```

- `#[cfg(test)]`: ez a rész csak teszteléskor fordul le, a kész programba nem kerül bele.
- `mod tests`: egy belső modul a teszteknek.
- `use super::*;`: behúzza a fájl összes függvényét a tesztmodulba.
- `#[test]`: ez a függvény egy teszt.
- `assert_eq!(a, b)`: ha `a != b`, a teszt elbukik, és kiírja mindkét értéket.
- `assert!(feltétel)`: ha a feltétel hamis, a teszt elbukik.

Futtasd:

```powershell
cargo test
```

```text
running 1 test
test tests::tag_lengths ... ok

test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

:::note „function is never used” figyelmeztetés
Ha a `cargo run` sárga figyelmeztetést ír (`warning: function ... is never used`), az csak annyit jelent, hogy a `main` nem hívja a függvényt, csak a teszt. Ez figyelmeztetés, nem hiba. A 01-11-es leckében, amikor könyvtárrá (library) alakítjuk a gyakorlót, magától eltűnik.
:::

A tesztek azonnali, pontos visszajelzést adnak: piros, piros, piros… **zöld**. Ez az ADHD-s agynak kifejezetten jó érzés, használd ki! A kurzusban sokszor kész teszteket kapsz (ezeket bemásolhatod), és neked kell megírnod a kódot, amitől zöldek lesznek. Ezt hívják **tesztvezérelt fejlesztésnek** (TDD).

## Te jössz: HTML-szóközök és betűk

A HTML-szabvány pontosan megmondja, mi számít szóköznek (*ASCII whitespace*): **szóköz**, **tabulátor** (`'\t'`), **soremelés** (`'\n'`), **kocsi vissza** (`'\r'`) és **lapdobás** (form feed, `'\u{000C}'`). A tokenizer később ezzel dönti el, hol ér véget egy tagnév vagy attribútum.

:::task
Írd meg ezt a két függvényt a `main.rs`-be:

1. `fn is_html_whitespace(c: char) -> bool`, ami igazat ad vissza, ha `c` a fenti öt karakter egyike.
2. `fn is_ascii_letter(c: char) -> bool`, ami igazat ad vissza, ha `c` az angol ábécé egy kis- vagy nagybetűje (`a`–`z`, `A`–`Z`). Az ékezetes betűk **nem** számítanak bele: a HTML-tagnevek csak ASCII-betűvel kezdődhetnek.

Másold be ezeket a teszteket is a `tests` modulba, és addig dolgozz, amíg mind zöld nem lesz:
:::

```rust test
    #[test]
    fn whitespace() {
        assert!(is_html_whitespace(' '));
        assert!(is_html_whitespace('\t'));
        assert!(is_html_whitespace('\n'));
        assert!(is_html_whitespace('\r'));
        assert!(is_html_whitespace('\u{000C}'));
        assert!(!is_html_whitespace('a'));
        assert!(!is_html_whitespace('<'));
    }

    #[test]
    fn letters() {
        assert!(is_ascii_letter('a'));
        assert!(is_ascii_letter('Z'));
        assert!(!is_ascii_letter('1'));
        assert!(!is_ascii_letter('á'));
        assert!(!is_ascii_letter('-'));
    }
```

:::hint
A `char` értékeket `==`-vel hasonlíthatod össze, a feltételeket pedig `||`-gyel (vagy) és `&&`-sel (és) kötheted össze, ugyanúgy, mint C#-ban vagy C++-ban.
---
A karakterek sorba rendezhetők, ezért a `c >= 'a' && c <= 'z'` működik. Az `is_ascii_letter`-nél két ilyen tartományt kell „vagy”-gyal összekötni.
---
Az `is_html_whitespace` törzse egyetlen kifejezés lehet: `c == ' ' || c == '\t' || ...`. Nem kell hozzá `if`, mert a `==` eredménye már maga `bool`.
:::

:::solution
```rust
fn is_html_whitespace(c: char) -> bool {
    c == ' ' || c == '\t' || c == '\n' || c == '\r' || c == '\u{000C}'
}

fn is_ascii_letter(c: char) -> bool {
    (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')
}
```
:::

:::tip Clippy, a jóindulatú kritikus
Futtasd: `cargo clippy`. A Clippy a Rust „lintere”, több száz tippje van. Az `is_ascii_letter`-nél valószínűleg azt fogja javasolni, hogy a standard könyvtárban már van erre egy kész metódus: **`c.is_ascii_alphabetic()`**. Ez nem jelenti azt, hogy a te megoldásod rossz volt! Kiderült viszont, hogy a `char` típusnak egy csomó hasznos metódusa van (`is_ascii_digit`, `is_alphanumeric`, `to_ascii_lowercase`…). A [dokumentációban](https://doc.rust-lang.org/std/primitive.char.html) mindet megtalálod.
:::

:::why Miért pont ez az öt karakter?
A HTML-szabvány „ASCII whitespace” definíciója a U+0009 TAB, U+000A LF, U+000C FF, U+000D CR és U+0020 SPACE karaktereket sorolja fel. A Unicode-ban sok más „szóköz” is van (pl. a nem törő szóköz, U+00A0, `&nbsp;`), de ezek a HTML szintaxisában **nem** választanak el semmit. Ezért nem jó itt a Rust `char::is_whitespace()` metódusa: az a Unicode-definíciót követi, és az U+00A0-ra is igazat ad. Ilyen apróságokon múlik, hogy egy böngésző a szabványnak megfelelően működik-e.
:::
