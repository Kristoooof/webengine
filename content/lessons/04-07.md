:::goal
Megtanulod, mi a **specificitás**: az a pontszám, ami eldönti, melyik szabály nyer, ha több is illik ugyanarra az elemre. A lecke végére minden `Selector` ki tudja számolni a sajátját, és két specificitás összehasonlítása egyetlen `>` jel lesz.
:::

## A kérdés

```html
<p id="fo" class="intro">Szia!</p>
```
```css
#fo     { color: red; }
.intro  { color: green; }
p       { color: blue; }
```

Mindhárom szabály illik a bekezdésre. Milyen színű lesz? **Piros.** És ha megfordítod a három szabály sorrendjét? Akkor is piros. A sorrendnél erősebb szempont, hogy melyik szelektor a **specifikusabb**, vagyis melyik írja le pontosabban az elemet.

## A pontszám

A specificitás három szám, és mindig ebben a sorrendben írjuk: **(id-k, osztályok, tagek)**.

| Szelektor | id | osztály | tag | Specificitás |
|---|---|---|---|---|
| `*` | 0 | 0 | 0 | (0, 0, 0) |
| `p` | 0 | 0 | 1 | (0, 0, 1) |
| `ul li` | 0 | 0 | 2 | (0, 0, 2) |
| `.intro` | 0 | 1 | 0 | (0, 1, 0) |
| `p.intro.fontos` | 0 | 2 | 1 | (0, 2, 1) |
| `#fo` | 1 | 0 | 0 | (1, 0, 0) |
| `ul#nav li.aktiv a` | 1 | 1 | 3 | (1, 1, 3) |

Két specificitást **balról jobbra** hasonlítunk: először az id-k számát. Ha az egyenlő, az osztályokét. Ha az is, a tagekét. A kombinátorok (szóköz, `>`) és a `*` nem számítanak.

:::warn Nem százas számrendszer!
Gyakori tévhit, hogy a specificitás egy szám: id = 100, osztály = 10, tag = 1. **Nem az.** A `(0, 11, 0)` (tizenegy osztály) **kisebb**, mint az `(1, 0, 0)` (egy id), pedig 110 > 100. Nincs „átvitel”: egyetlen id több, mint akárhány osztály.
:::

:::compare Több szempont szerinti rendezés
@@ Érettségi
Ez pontosan az a feladat, amikor „rendezd a versenyzőket pontszám szerint, egyenlőség esetén név szerint”. Az első szempont dönt, a második csak döntetlennél számít.
@@ Python
A tuple-ök pont így hasonlítanak: `(1, 0, 0) > (0, 10, 10)` igaz. Ezért írhatsz `sorted(lista, key=lambda x: (x.pont, x.nev))`-t.
@@ C#
A `ValueTuple` is lexikografikusan hasonlít: `(1, 0, 0).CompareTo((0, 10, 10))` = 1. LINQ-ban: `.OrderBy(x => x.Id).ThenBy(x => x.Osztaly)`.
@@ Rust
Rustban a `#[derive(PartialOrd, Ord)]` egy structra vagy tuple structra **mezőnként, a deklaráció sorrendjében** hasonlít. Ha a mezők sorrendje (id-k, osztályok, tagek), a `derive` pontosan a specificitás szabályát adja, egy sor kód nélkül.
:::

## A típus

```rust
/// (id-k, osztályok, tagek) száma. A `derive(Ord)` mezőnként, balról jobbra hasonlít.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Default)]
pub struct Specificity(pub u32, pub u32, pub u32);
```

Ez egy **tuple struct**: a mezőknek nincs nevük, csak sorszámuk (`s.0`, `s.1`, `s.2`). Kis, „számszerű” típusokhoz kényelmes. Az `Ord` miatt használhatod rá a `<`, `>`, `max()` és `sort()` műveleteket is.

Hogy egy összetett szelektor (`p.intro#fo`) egy elemre vonatkozik, az a számolást nem zavarja. Minden `Compound`-ban: ha van id, +1 az első számhoz. Ahány osztály, annyi a másodikhoz. Ha van tag, +1 a harmadikhoz.

:::note És a többi?
A teljes szabályban a pszeudo-osztályok (`:hover`) és az attribútum-szelektorok (`[href]`) az osztályokhoz, a pszeudo-elemek (`::before`) a tagekhez számítanak. A `style=""` attribútum deklarációi minden szelektornál erősebbek, az `!important` pedig egy teljesen külön szinten dolgozik. Ezt a kettőt a kaszkádnál (04-09) kezeljük.
:::

## Te jössz

:::task
A `selector.rs`-be:

1. A `Specificity` tuple struct a fenti `derive`-okkal.
2. `impl Selector { pub fn specificity(&self) -> Specificity }`: végigmegy a `compounds`-on, és összeszámolja az id-ket, az osztályokat és a tageket.
:::

A `selector.rs` tesztjei közé:

```rust test
    #[test]
    fn specificity_counts() {
        assert_eq!(sel("p").unwrap().specificity(), Specificity(0, 0, 1));
        assert_eq!(
            sel("ul#nav li.aktiv a").unwrap().specificity(),
            Specificity(1, 1, 3)
        );
        assert_eq!(sel("*").unwrap().specificity(), Specificity(0, 0, 0));
        assert_eq!(sel(".a.b.c").unwrap().specificity(), Specificity(0, 3, 0));
    }

    #[test]
    fn specificity_order() {
        assert!(Specificity(1, 0, 0) > Specificity(0, 10, 10));
        assert!(Specificity(0, 1, 0) > Specificity(0, 0, 99));
        assert!(Specificity(0, 1, 2) > Specificity(0, 1, 1));
    }
```

:::hint
Indulj egy üres pontszámból (`Specificity::default()` = `(0, 0, 0)`, a `Default` derive miatt), és legyen `mut`.
---
A ciklus: `for c in &self.compounds { … }`. A `c.id.is_some()` megmondja, van-e id, a `c.classes.len()` az osztályok számát (`usize`, ezért `as u32` kell), a `c.tag.is_some()` pedig, hogy van-e tag.
:::

:::solution
```rust
/// (id-k, osztályok, tagek) száma. A `derive(Ord)` mezőnként, balról jobbra hasonlít.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Default)]
pub struct Specificity(pub u32, pub u32, pub u32);

impl Selector {
    pub fn specificity(&self) -> Specificity {
        let mut s = Specificity::default();
        for c in &self.compounds {
            if c.id.is_some() {
                s.0 += 1;
            }
            s.1 += c.classes.len() as u32;
            if c.tag.is_some() {
                s.2 += 1;
            }
        }
        s
    }
}
```
:::

:::why Miért pont így találták ki?
A specificitás ötlete: a **pontosabb** leírás nyerjen. Egy id egyetlen elemre illik az egész oldalon, egy osztály egy csoportra, egy tag minden ilyen elemre. Aki id-vel hivatkozik egy elemre, nagyon konkrétan akar valamit, ezért erősebb. A gyakorlatban viszont a specificitás a CSS egyik legtöbb fejfájást okozó része. Ha egy `#fejlec a` szabályt felül akarsz írni, egy osztállyal soha nem fog menni. Ezért ajánlják a modern CSS-módszertanok (BEM, utility CSS), hogy szinte csak osztályokat használj: így minden szabály specificitása hasonló, és a sorrend dönt.

@@ feladat

@@ kód
```rust
fn specificity(selector: &str) -> (u32, u32, u32) {
    todo!()
}
```
@@ megoldás
```rust
fn specificity(selector: &str) -> (u32, u32, u32) {
    let mut ids = 0;
    let mut classes = 0;
    let mut tags = 0;
    let mut at_compound_start = true;
    for c in selector.chars() {
        match c {
            '#' => ids += 1,
            '.' => classes += 1,
            ' ' | '>' => {
                at_compound_start = true;
                continue;
            }
            c if at_compound_start && c.is_ascii_alphabetic() => tags += 1,
            _ => {}
        }
        at_compound_start = false;
    }
    (ids, classes, tags)
}
```
@@ magyarázat
Egyetlen menet a karaktereken, egy kis állapottal (`at_compound_start`): igaz a szöveg elején és minden kombinátor után, és hamis lesz az első nem-kombinátor karakternél. A tagot pont ott ismerjük fel, ahol egy összetett szelektor kezdődik. Nincs darabolás, nincs `Vec`, nincs új `String`.
@@ esetek

@@ teszt-rossz
```rust
fn specificity(selector: &str) -> (u32, u32, u32) {
    let mut ids = 0;
    let mut classes = 0;
    let mut tags = 0;
    for part in selector.split(' ') {
        if part.starts_with(|c: char| c.is_ascii_alphabetic()) {
            tags += 1;
        }
        ids += part.matches('#').count() as u32;
        classes += part.matches('.').count() as u32;
    }
    (ids, classes, tags)
}
```
@@ teszt-lassú
```rust
fn specificity(selector: &str) -> (u32, u32, u32) {
    let spaced = selector.replace('>', " ");
    let parts: Vec<String> = spaced.split_whitespace().map(|p| p.to_string()).collect();
    let mut ids = 0;
    let mut classes = 0;
    let mut tags = 0;
    for part in parts {
        let chars: Vec<char> = part.chars().collect();
        if chars.first().is_some_and(|c| c.is_ascii_alphabetic()) {
            tags += 1;
        }
        ids += chars.iter().filter(|&&c| c == '#').count() as u32;
        classes += chars.iter().filter(|&&c| c == '.').count() as u32;
    }
    (ids, classes, tags)
}
```
