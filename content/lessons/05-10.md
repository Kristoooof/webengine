## 1. A core: trait, és búcsú a `Page`-től

A `Page`, a `Block` és a `BlockKind` a 2. modul óta velünk van: a „lapító” ezekbe tömörítette a DOM-ot, hogy a 0.1-es rajzoló megértse. Mostantól a layout-fa (`LayoutBox`) a rajzolás bemenete, úgyhogy ezek mehetnek.

A `rozsda-core/src/lib.rs`-ben:

1. Töröld a `BlockKind`, `Block` és `Page` típust, az `impl Page`-et, és a fájl végén a `tests` modult (`plain_text_joins_blocks`, `default_page_is_empty`).
2. A stílus-import egyszerűsödik: `use style::StyleMap;`
3. Jön a harmadik trait, a `StyleEngine` mellé:

```rust
/// Bármi, ami a DOM-ból és a stílusokból elhelyezett dobozokat csinál.
pub trait LayoutEngine {
    fn name(&self) -> &'static str;
    fn layout(
        &self,
        doc: &dom::Document,
        styles: &StyleMap,
        viewport_width: f32,
    ) -> Option<layout::LayoutBox>;
}
```

Az `Option` azért kell, mert lehet, hogy semmi sem látszik (egy `html { display: none }` oldalon). A `viewport_width` az ablak szélessége: ebből lesz a `<html>` tartalmazó blokkja (05-09).

Futtass egy `cargo check`-et. A böngésző `flatten.rs`-e és `layout.rs`-e tele lesz hibával, mert a `Page`-et használják. Ez rendben van: a 4. lépésben töröljük őket.

## 3. A festő

A festés a layout-fa **bejárása**: minden dobozra, szülőtől a gyerekek felé, ebben a sorrendben:

1. **háttér** (a keretdobozra, `border_box()`)
2. **keret**: négy téglalap, a négy oldalon
3. **felsorolásjel**, ha a doboz `display: list-item`
4. a sorok **szövegdarabjai**, mindegyik a saját elemének stílusával
5. (`--keretek` esetén) egy vékony piros **körvonal**
6. a **gyerekek**, ugyanígy

Ez a **festő algoritmus** (painter's algorithm): ami később kerül a vászonra, az takarja a korábbit, mint amikor egy festő a hátteret festi meg először. Ezért kell a szülő hátterének a gyerekek előtt jönnie.

:::compare Festési sorrend
@@ CSS
A szabvány (CSS 2.1, E függelék: *Elaborate description of Stacking Contexts*) ennél részletesebb: előbb az összes blokk háttere, aztán a lebegő elemek, aztán az inline tartalom, és a `z-index` mindent felülírhat. A mi egyszerű „dobozonként minden” sorrendünk addig ugyanazt adja, amíg nincs átfedés.
@@ C#
A WinForms `OnPaint` és a WPF `OnRender` ugyanígy működik: a szülő rajzol, aztán a gyerekek a tetejére.
@@ Érettségi
Ez egy preorder fabejárás: előbb a csúcs, aztán a részfák balról jobbra.
:::

### A `<body>` háttere a vászoné

Ha a `<body>`-nak háttérszíne van, a böngésző **az egész ablakot** azzal festi ki, nem csak a `body` dobozát. A szabvány szerint a gyökér (és a `body`) háttere „továbbterjed” a vászonra. Ezt a 4. modulban a `page_background` már megcsinálta. Ezért a festő a `<html>` és a `<body>` hátterét **nem** rajzolja ki még egyszer a saját dobozára. Ha kirajzolná, a `body` 8px-es margója egy keskeny fehér keretként látszana.

### A keret: négy téglalap

A `Rect` struct update szintaxisával (05-05) egy oldal egy sor:

```rust
let r = b.dimensions.border_box();
let w = b.dimensions.border;
fill(canvas, Rect { height: w.top, ..r }, scroll, color);
```

„Olyan, mint a keretdoboz, csak `w.top` magas”: ez a felső keret. A többi oldalé hasonló.

### A szöveg

A darabok (05-08) már a helyükön vannak, a festőnek csak ki kell rajzolnia őket. A betű 8 pixel magas (nagyítva `8 * scale`), a sor ennél magasabb, ezért a betűt **függőlegesen középre** tesszük a darab téglalapjában. A félkövér maradt a 0.1-es trükk: még egyszer, egy pixellel jobbra.

### A felsorolásjel

A `li` tartalma előtt, a `ul` 40px-es bal kitöltésében (05-03) van hely a jelnek. A `»` jelet használjuk, mert a 8×8-as betűkészletünkben benne van (a `•` nincs).

```rust
//! Rajzolás: a layout-fa dobozaiból és soraiból pixelek.

use crate::canvas::Canvas;
use crate::text::{GLYPH, draw_text};
use rozsda_core::dom::Document;
use rozsda_core::layout::{BoxKind, LayoutBox, Rect};
use rozsda_core::style::{ComputedStyle, Display, StyleMap};
use rozsda_layout::text::{char_width, glyph_scale, line_height};

/// A `--keretek` hibakereső körvonalainak színe.
const OUTLINE: u32 = 0xE11D48;

pub fn fill(canvas: &mut Canvas, r: Rect, scroll: i32, color: u32) {
    canvas.fill_rect(
        r.x.round() as i32,
        r.y.round() as i32 - scroll,
        r.width.round() as i32,
        r.height.round() as i32,
        color,
    );
}

/// A `<html>` és a `<body>` háttere a vászoné lesz (a szabvány szerint „továbbterjed”),
/// ezért a saját dobozukra nem rajzoljuk ki még egyszer.
fn paints_own_background(doc: &Document, b: &LayoutBox) -> bool {
    match b.kind {
        BoxKind::Block(id) => !matches!(doc.tag_name(id), Some("html" | "body")),
        BoxKind::Anonymous => true,
    }
}

fn outline(canvas: &mut Canvas, r: Rect, scroll: i32) {
    fill(canvas, Rect { height: 1.0, ..r }, scroll, OUTLINE);
    fill(
        canvas,
        Rect {
            y: r.bottom() - 1.0,
            height: 1.0,
            ..r
        },
        scroll,
        OUTLINE,
    );
    fill(canvas, Rect { width: 1.0, ..r }, scroll, OUTLINE);
    fill(
        canvas,
        Rect {
            x: r.right() - 1.0,
            width: 1.0,
            ..r
        },
        scroll,
        OUTLINE,
    );
}

/// Szöveg a sor közepére igazítva. A félkövér: még egyszer, egy pixellel jobbra.
fn paint_text(canvas: &mut Canvas, style: &ComputedStyle, rect: Rect, text: &str, scroll: i32) {
    let scale = glyph_scale(style) as i32;
    let x = rect.x.round() as i32;
    let y = (rect.y + (rect.height - (GLYPH * scale) as f32) / 2.0).round() as i32 - scroll;
    let color = style.color.to_u32();
    draw_text(canvas, x, y, text, scale, color);
    if style.font_weight >= 600 {
        draw_text(canvas, x + 1, y, text, scale, color);
    }
}

/// A felsorolásjel a tartalom bal széle előtt, a kitöltésben (az `ul` 40px-es bal kitöltése miatt fér el).
fn paint_marker(canvas: &mut Canvas, b: &LayoutBox, scroll: i32) {
    let s = &b.style;
    let c = b.dimensions.content;
    let rect = Rect {
        x: c.x - 2.0 * char_width(s),
        y: c.y,
        width: char_width(s),
        height: line_height(s),
    };
    paint_text(canvas, s, rect, "»", scroll);
}
```

:::solution
```rust
fn paint_borders(canvas: &mut Canvas, b: &LayoutBox, scroll: i32) {
    let r = b.dimensions.border_box();
    let w = b.dimensions.border;
    let color = b.style.border_color.to_u32();
    fill(canvas, Rect { height: w.top, ..r }, scroll, color);
    let bottom = Rect {
        y: r.bottom() - w.bottom,
        height: w.bottom,
        ..r
    };
    fill(canvas, bottom, scroll, color);
    fill(canvas, Rect { width: w.left, ..r }, scroll, color);
    let right = Rect {
        x: r.right() - w.right,
        width: w.right,
        ..r
    };
    fill(canvas, right, scroll, color);
}

pub fn paint(
    canvas: &mut Canvas,
    doc: &Document,
    styles: &StyleMap,
    b: &LayoutBox,
    scroll: i32,
    outlines: bool,
) {
    let background = b.style.background_color;
    if background.a > 0 && paints_own_background(doc, b) {
        fill(
            canvas,
            b.dimensions.border_box(),
            scroll,
            background.to_u32(),
        );
    }
    paint_borders(canvas, b, scroll);
    if b.style.display == Display::ListItem {
        paint_marker(canvas, b, scroll);
    }
    for line in &b.lines {
        for f in &line.fragments {
            let style = styles.get(f.node).unwrap_or(&b.style);
            paint_text(canvas, style, f.rect, &f.text, scroll);
        }
    }
    if outlines {
        outline(canvas, b.dimensions.border_box(), scroll);
    }
    for child in &b.children {
        paint(canvas, doc, styles, child, scroll, outlines);
    }
}
```

```rust
    let mut path = None;
    let mut html = Implementation::Own;
    let mut css = Implementation::Own;
    let mut layout = Implementation::Own;

    let mut dump_boxes = false;
    let mut outlines = false;
    for arg in std::env::args().skip(1) {
        match arg.as_str() {
            "--html=sajat" => html = Implementation::Own,
            "--html=profi" => html = Implementation::Pro,
            "--css=sajat" => css = Implementation::Own,

        path,
        html,
        css,
        layout,
        dump_dom,
        dump_styles,
        dump_boxes,
        outlines,
    })
```

:::card
K: Mi a festő algoritmus (painter's algorithm)?
V: A rajzolás hátulról előre halad: ami később kerül a vászonra, az takarja a korábbit. A Rozsdában dobozonként: háttér, keret, jel, szöveg, aztán a gyerekek.
:::

:::card
K: Mit csinál a `--dobozok` és a `--keretek` kapcsoló?
V: A `--dobozok` kiírja a layout-fát (dobozok, sorok, darabok helyükkel és méretükkel), a `--keretek` minden doboz köré egy vékony piros körvonalat rajzol.
:::

:::card
K: Mi a `LayoutEngine` trait?
V: A saját–profi kapcsoló harmadik eleme: a DOM-ból és a stílusokból egy elhelyezett layout-fát csinál. A saját: `OwnLayoutEngine`; a profi a 16. modulban a Taffy lesz.
:::
