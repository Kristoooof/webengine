## Miért kell kiírás?

Képzeld el, hogy a fa-építő tesztjében ezt kell ellenőrizni: `<p>Egy <b>kettő</b></p>`. Egyenként, `assert`-ekkel:

```rust
let html = doc.children(doc.root())[0];
let body = doc.children(html)[1];
let p = doc.children(body)[0];
assert_eq!(doc.tag_name(p), Some("p"));
let b = doc.children(p)[1];
// ... és még tíz sor
```

Ez fárasztó és olvashatatlan. Ehelyett kiírjuk a fát szövegként, és **egy** összehasonlítás ellenőrzi az egészet:

```text
| <html>
|   <head>
|   <body>
|     <p>
|       "Egy "
|       <b>
|         "kettő"
```

Ezt hívják **snapshot tesztnek**: a várt kimenet egy „pillanatkép”, amihez a valódit hasonlítjuk. Ha elbukik, az `assert_eq!` megmutatja mindkét szöveget, és azonnal látszik, hol a különbség.

## A html5lib formátum

A html5lib-tests a böngészők közös tesztcsomagja. A Chrome, a Firefox, a Servo és a Ladybird is használja. A fákat ebben a formátumban írja le:

| Csomópont | Formátum |
|---|---|
| Elem | `<név>` |
| Attribútum | az elem alatt egy szinttel beljebb: `név="érték"`, **ábécérendben** |
| Szöveg | `"szöveg"` |
| Komment | `<!-- szöveg -->` |
| DOCTYPE | `<!DOCTYPE név>` |

Minden sor `| `-vel kezdődik, és minden mélységi szint két szóköz behúzás. Magát a `Document` gyökeret nem írjuk ki, a gyerekei a 0. szinten vannak.

:::tip Hasonlítsd össze a böngésződdel!
A Chrome DevTools **Elements** panelje (`F12`) ugyanezt a fát mutatja, csak szebben. Ha a Rozsda és a Chrome fája eltér, a Chrome-nak van igaza. 🙂 Ezzel a formátummal a különbség könnyen megtalálható.
:::

## Többsoros szöveg a tesztekben

A várt kimenet több sor, ezért egy hasznos Rust-szintaxist fogunk használni:

```rust
let expected = "\
| <html>
|   <p>
";
```

A nyitó idézőjel után álló `\` azt jelenti: *„az ezt követő sortörés nem része a szövegnek”*. Így az első sor szépen a második sorban kezdődhet, a többi sortörés viszont megmarad. A záró `"` előtti utolsó sortörés is a szöveg része, pont úgy, ahogy a `dump` minden sor végére tesz egy `\n`-t.

## Te jössz

:::task
A `dom.rs`-be írd meg:

1. `pub fn dump(&self) -> String`: végigmegy a gyökér gyerekein, és mindegyikre meghívja a `dump_node`-ot 0 mélységgel.
2. `fn dump_node(&self, id: NodeId, depth: usize, out: &mut String)`:
   - behúzás: `"  ".repeat(depth)`
   - a csomópont sora a fenti táblázat szerint
   - elemnél az attribútumok **rendezve** (`sort()`), egy szinttel beljebb
   - végül rekurzívan a gyerekek, `depth + 1`-gyel
:::

```rust test
    #[test]
    fn dump_format() {
        let (mut doc, _, _) = sample();
        let c = doc.create(NodeData::Comment(" vége ".into()));
        doc.append(doc.root(), c);
        let expected = "\
| <html>
|   <p>
|     class=\"intro fontos\"
|     \"Szia, \"
|     <b>
|       \"Rozsda\"
|     \"!\"
| <!--  vége  -->
";
        assert_eq!(doc.dump(), expected);
    }
```

(A `sample()` segédfüggvény az előző lecke tesztjei között van. Ezt a tesztet is oda tedd.)

:::hint
A `format!` és a `push_str` együtt jól megy: `out.push_str(&format!("| {indent}<{}>\n", e.name));`. A `{indent}` a változót közvetlenül a formátum-szövegbe illeszti.
---
Az attribútumok rendezése: gyűjtsd össze őket referenciaként egy vektorba, és rendezd. A tuple-ök (`(String, String)`) rendezhetők: előbb az első elem szerint, egyezés esetén a második szerint.
```rust
let mut attrs: Vec<&(String, String)> = e.attrs.iter().collect();
attrs.sort();
```
---
A komment formátuma `<!-- {c} -->`. A szóközök a formátum részei, ezért a `" vége "` kommentből `<!--  vége  -->` lesz, két-két szóközzel. Ez nem hiba, a html5lib is így írja.
:::

:::solution
```rust
/// A fa kiírása a html5lib-tesztek formátumában.
pub fn dump(&self) -> String {
    let mut out = String::new();
    for &child in self.children(self.root()) {
        self.dump_node(child, 0, &mut out);
    }
    out
}

fn dump_node(&self, id: NodeId, depth: usize, out: &mut String) {
    let indent = "  ".repeat(depth);
    match &self.nodes[id.0].data {
        NodeData::Document => {}
        NodeData::Doctype(name) => out.push_str(&format!("| {indent}<!DOCTYPE {name}>\n")),
        NodeData::Comment(c) => out.push_str(&format!("| {indent}<!-- {c} -->\n")),
        NodeData::Text(t) => out.push_str(&format!("| {indent}\"{t}\"\n")),
        NodeData::Element(e) => {
            out.push_str(&format!("| {indent}<{}>\n", e.name));
            let mut attrs: Vec<&(String, String)> = e.attrs.iter().collect();
            attrs.sort();
            for (name, value) in attrs {
                out.push_str(&format!("| {indent}  {name}=\"{value}\"\n"));
            }
        }
    }
    for &child in self.children(id) {
        self.dump_node(child, depth + 1, out);
    }
}
```
:::

:::why Mitől jó egy snapshot teszt, és mitől veszélyes?
**Jó**, mert rövid, olvasható, és egy egész struktúrát ellenőriz. A hiba helye ránézésre látszik. **Veszélyes**, mert könnyű „rossz” pillanatképet elfogadni. Ha a kimenet hibás, és te egyszerűen bemásolod a tesztbe várt értékként, a teszt a hibát fogja „védeni”. Ezért a várt kimenetet mindig gondold végig fejben (vagy hasonlítsd össze a Chrome-mal), mielőtt elfogadod. Nagyobb projektekben az [insta](https://insta.rs) crate kezeli a pillanatképeket fájlokban, és interaktívan kérdezi meg, elfogadod-e a változást.
