## Egy CSS-szabály anatómiája

```css
/* a címsorok legyenek narancssárgák */
h1, h2.fontos {
  color: #c2410c;
  font-size: 2em !important;
}
```

```text Ábra
h1, h2.fontos {  color: #c2410c;  font-size: 2em !important;  }
└─────┬─────┘ │  └──────┬──────┘  └───────────┬────────────┘  │
 szelektor-   │    deklaráció       deklaráció, „fontos”      │
   lista      └────────────── deklarációs blokk ──────────────┘
└────────────────────── szabály (rule) ───────────────────────┘
```

| Szó | Angolul | Példa |
|---|---|---|
| Szabály | rule | az egész fenti rész |
| Szelektor | selector | `h1`, `h2.fontos`: *melyik* elemekre vonatkozik |
| Deklaráció | declaration | `color: #c2410c`: egy tulajdonság és az értéke |
| Tulajdonság | property | `color`, `font-size` |
| Érték | value | `#c2410c`, `2em` |
| At-szabály | at-rule | `@media print { … }`, `@import "x.css";` |

A kommentet (`/* … */`) a böngésző egyszerűen kihagyja.

Ismerős? Az első két lépés ugyanaz, mint a HTML-nél: előbb **tokenekre** bontjuk a szöveget, aztán a tokenekből **szerkezetet** építünk. A CSS nyelvtana viszont sokkal barátságosabb. A CSS-tokenizálást a **CSS Syntax Level 3** szabvány írja le, és nincs benne 80 állapot, mint a HTML-ben: egy egyszerű „nézd meg a következő karaktert, és döntsd el, mi jön” algoritmus.

:::compare Ezt már láttad
@@ C#
A C#-fordító (Roslyn) is így kezdi: a forráskódból egy `SyntaxToken`-sorozat lesz (`IdentifierToken`, `NumericLiteralToken`, `OpenBraceToken`…), és csak utána épül fa. A mi `Token` enumunk ugyanez, kicsiben.
@@ Python
A Python beépített `tokenize` modulja pontosan ezt csinálja Python-kódra. Próbáld ki: `python -m tokenize valami.py`. Látni fogod a `NAME`, `NUMBER`, `OP` tokeneket.
@@ C++
Egy C++-fordító előfeldolgozó és lexer fázisa is tokeneket gyárt. A különbség: a CSS-ben egy hibás token sem állítja meg a feldolgozást.
@@ Érettségi
Emelt infón sokszor bontottál sort darabokra `split`-tel. A tokenizer egy okosabb `split`: nem csak szóközöknél vág, hanem tudja, hogy a `12px` egy darab, a `:` meg egy másik.
:::

## A CSS-tokenek

| Token | Mit jelent | Példa |
|---|---|---|
| `Ident(String)` | név (azonosító) | `color`, `h1`, `red`, `-webkit-box` |
| `Function(String)` | név, rögtön utána `(` | `rgb(` → `Function("rgb")` |
| `AtKeyword(String)` | `@` és egy név | `@media` → `AtKeyword("media")` |
| `Hash(String)` | `#` és egy név | `#fff`, `#fo` |
| `Str(String)` | idézőjeles szöveg | `"Comic Sans"` |
| `Number(f32)` | szám | `0`, `1.5`, `-3` |
| `Percentage(f32)` | szám és `%` | `50%` |
| `Dimension(f32, String)` | szám és mértékegység | `12px` → `Dimension(12.0, "px")` |
| `Whitespace` | egy vagy több szóköz, tab, sortörés | |
| `Colon`, `Semicolon`, `Comma` | `:` `;` `,` | |
| `LeftBrace`, `RightBrace` | `{` `}` | |
| `LeftParen`, `RightParen` | `(` `)` | |
| `Delim(char)` | bármi más, egyetlen karakter | `.`, `>`, `*`, `!` |

:::note Miért `Str` és nem `String`?
Egy enum-változat neve lehetne `String` is, de akkor a `Token::String(String)` sorban kétszer szerepelne ugyanaz a szó két jelentéssel. A `Str` rövidebb, és nem keveredik össze a Rust `String` típusával.
:::

Figyeld meg, hogy a `#fff` és a `#fo` is `Hash`: a tokenizer még nem tudja, hogy az egyik szín, a másik id-szelektor. Ezt csak a parser dönti el, a környezet alapján. Ugyanígy a `.intro` két token: `Delim('.')` és `Ident("intro")`.

## Mi számít névnek?

A tokenizernek folyton azt kell eldöntenie, hogy egy karakter lehet-e egy név része. A szabvány szerint (egyszerűsítve):

- **névkezdő** (*ident-start*): betű (`a–z`, `A–Z`), aláhúzás `_`, vagy bármilyen nem-ASCII karakter (pl. `é`)
- **névkarakter** (*ident char*): névkezdő, számjegy vagy kötőjel `-`
- **szóköz** (*whitespace*): szóköz, tab, `\n`, `\r` és a lapdobás (`\u{000C}`)

Ezért lehet osztályneved `.főcím`, és ezért nem kezdődhet számmal: a `.1abc` nem érvényes osztály-szelektor.

A `char`-nak sok hasznos metódusa van: `is_ascii_alphabetic()`, `is_ascii_digit()`, `is_ascii()`. Nem-ASCII karakter az, amire az `is_ascii()` hamis.
---
Az `is_name_char` felhasználhatja az `is_name_start`-ot: „névkezdő, **vagy** számjegy, **vagy** kötőjel”.
---
Az `is_whitespace`-hez a `matches!` makró a legrövidebb: `matches!(c, ' ' | '\t' | …)`. Ne a `char::is_whitespace()`-t használd: az a Unicode összes szóközét elfogadja, a CSS csak ezt az ötöt.

:::solution
```rust
//! CSS-tokenizer a CSS Syntax Level 3 szabvány alapján (egyszerűsítve).

#[derive(Debug, Clone, PartialEq)]
pub enum Token {
    Ident(String),
    Function(String),
    AtKeyword(String),
    Hash(String),
    Str(String),
    Number(f32),
    Percentage(f32),
    Dimension(f32, String),
    Whitespace,
    Colon,
    Semicolon,
    Comma,
    LeftBrace,
    RightBrace,
    LeftParen,
    RightParen,
    Delim(char),
}

/// Kezdődhet-e ezzel a karakterrel egy név (ident)?
pub fn is_name_start(c: char) -> bool {
    c.is_ascii_alphabetic() || c == '_' || !c.is_ascii()
}

/// Lehet-e ez a karakter egy név belsejében?
pub fn is_name_char(c: char) -> bool {
    is_name_start(c) || c.is_ascii_digit() || c == '-'
}

/// A CSS szóköz-karakterei.
pub fn is_whitespace(c: char) -> bool {
    matches!(c, ' ' | '\t' | '\n' | '\r' | '\u{000C}')
}
```
:::

:::why Miért `f32` a számoknak?
A CSS-ben minden szám lehet tört (`1.5em`, `0.83em`), ezért lebegőpontos típus kell. Az `f32` 7 értékes jegyre pontos, ami bőven elég képernyőpixelekhez. A Firefox stílusmotorja (Stylo) is `f32`-t használ a CSS-számokra. Egy csapda: az `f32` nem tud `Eq`-t és `Hash`-t (a `NaN` miatt), ezért a `Token` is csak `PartialEq`.
:::

@@ megoldás
```rust
fn count_rules(css: &str) -> usize {
    let mut depth = 0;
    let mut count = 0;
    for c in css.chars() {
        match c {
            '{' => {
                if depth == 0 {
                    count += 1;
                }
                depth += 1;
            }
            '}' if depth > 0 => depth -= 1,
            _ => {}
        }
    }
    count
}
```
@@ magyarázat
Egy számláló a mélységre: a `{` növeli, a `}` csökkenti. Csak akkor számolunk, amikor 0-s mélységben nyílik egy blokk. Egy menet, semmi `Vec`, semmi új `String`: ennél gyorsabb nem nagyon lehet.
@@ esetek

```rust
count_rules("p { a { b { } } }")
count_rules("} p { }")
count_rules("nincs blokk")
```

```rust
fn count_rules(css: &str) -> usize {
    let chars: Vec<String> = css.chars().map(|c| c.to_string()).collect();
    let mut depth = 0;
    let mut count = 0;
    for c in &chars {
        if c == "{" {
            if depth == 0 {
                count += 1;
            }
            depth += 1;
        } else if c == "}" && depth > 0 {
            depth -= 1;
        }
    }
    count
}
```
