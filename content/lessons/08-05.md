## UDP: egy levél, válasz nélkül

A DNS a **UDP**-t (User Datagram Protocol) használja, nem a TCP-t. A különbség:

| | TCP | UDP |
|---|---|---|
| Kapcsolat | előbb felépül (kézfogás), utána folyam | nincs: minden csomag önálló „levél” |
| Megbízhatóság | ami elmegy, megérkezik, sorrendben | elveszhet, megduplázódhat, felcserélődhet |
| Gyorsaság | a kézfogás egy oda-vissza utat vesz el | azonnal indul |
| Kinek jó | weboldalak, fájlok | rövid kérdés-válasz (DNS), játékok, videóhívás |

Egy DNS-kérdés és -válasz egyetlen kis csomag. A TCP kézfogása tovább tartana, mint maga a kérdés, ezért éri meg az UDP. Cserébe nekünk kell kezelni, ha a csomag elveszik: ha nem jön válasz időben, hibát adunk (a profi kliensek ilyenkor újra próbálják, vagy egy másik szervert kérdeznek).

```text Ábra
 a gépem (0.0.0.0:51234)                    DNS-szerver (1.1.1.1:53)
     │  ── kérdés: ID=0x5A3C, „pelda.hu, A?” ──►  │
     │                                            │
     │  ◄── válasz: ID=0x5A3C, „93.184.215.14” ── │
```

A Rustban a `UdpSocket` adja ezt:

- `UdpSocket::bind("0.0.0.0:0")`: egy foglalat (socket) a gépünkön. A 0-s port azt jelenti: „adj egy szabadat”.
- `send_to(&csomag, cím)`: egy levél elküldése.
- `recv_from(&mut buf)`: várakozás egy levélre. Visszaadja, hány bájt jött, és **kitől**.
- `set_read_timeout(Some(Duration::from_secs(3)))`: a várakozás felső határa. Ha letelik, a `recv_from` hibát ad (`WouldBlock` vagy `TimedOut`, a rendszertől függően).

## Kinek a levele?

Az UDP-foglalatra bárki küldhet csomagot. Egy támadó (vagy egy késve érkező régi válasz) is. Ezért két dolgot ellenőrzünk:

1. A csomag attól a szervertől jött-e, akit kérdeztünk.
2. Az azonosítója (ID) egyezik-e a kérdésünkével.

Ha valamelyik nem stimmel, eldobjuk, és várunk tovább. A kérdés azonosítóját az órából keverjük ki. Ez a tanuláshoz elég, de egy éles kliensben kriptográfiailag erős véletlen kell (lásd a 08-04 mélyvizét).

:::compare UDP máshol
@@ C#
`var udp = new UdpClient(); udp.Send(bytes, bytes.Length, "1.1.1.1", 53); var answer = udp.Receive(ref from);` Az időkorlát: `udp.Client.ReceiveTimeout = 3000;`.
@@ C++
`socket(AF_INET, SOCK_DGRAM, 0)`, `sendto`, `recvfrom`, és az időkorlát a `setsockopt(SO_RCVTIMEO)`-val. A Rust `UdpSocket`-je pontosan ezeket hívja.
@@ Python
`s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM); s.settimeout(3); s.sendto(q, ("1.1.1.1", 53)); data, addr = s.recvfrom(512)`.
@@ Érettségi
A TCP és az UDP különbsége (kapcsolatorientált és kapcsolat nélküli) klasszikus hálózati kérdés. A port a „lakásszám” egy IP-címen belül: a 53-as a DNS-é.

## Te jössz

:::task
A `dns.rs`-ben:

1. `pub const DEFAULT_DNS: SocketAddr`: a `1.1.1.1:53` (egy `const`-ban `SocketAddr::new(IpAddr::V4(Ipv4Addr::new(1, 1, 1, 1)), 53)`).
2. `fn query_id() -> u16`: az aktuális idő nanoszekundumaiból.
3. `fn invalid(e: DnsError) -> io::Error`: a DNS-hibákból `io::Error`, a `NotFound`-ból `io::ErrorKind::NotFound`, a többiből `InvalidData`.
4. `pub fn resolve(name: &str, server: SocketAddr) -> io::Result<Vec<Ipv4Addr>>`: foglalat, időkorlát, küldés, aztán egy ciklus, ami eldobja az idegen és a hibás csomagokat. A válaszkód szerint: 0 → a címek (ha üres, `NotFound`), 3 → `NotFound`, más → `ServerFailure`.
:::

Miért `io::Result`, és nem saját hibatípus? Mert a hibák nagy része úgyis a hálózatból jön (`io::Error`), és az `io::Error::new(kind, hiba)` bármilyen saját hibát be tud csomagolni. Így a hívó egyetlen hibatípust kap, és a `?` mindenhol működik.

```rust test
    // 08-05
    #[test]
    fn asking_a_local_server() {
        // egy „DNS-szerver” a saját gépen: a kérdés azonosítójával válaszol
        let server = UdpSocket::bind("127.0.0.1:0").unwrap();
        let addr = server.local_addr().unwrap();
        let thread = std::thread::spawn(move || {
            let mut buf = [0u8; 512];
            let (n, from) = server.recv_from(&mut buf).unwrap();
            let id = u16::from_be_bytes([buf[0], buf[1]]);
            assert_eq!(&buf[12..n - 4], b"\x03www\x05pelda\x02hu\x00");
            server.send_to(&sample_response(id), from).unwrap();
        });
        let ips = resolve("www.pelda.hu", addr).unwrap();
        assert_eq!(ips, vec![Ipv4Addr::new(93, 184, 215, 14)]);
        thread.join().unwrap();
    }

    #[test]
    fn silence_is_an_error() {
        let server = UdpSocket::bind("127.0.0.1:0").unwrap(); // nem válaszol
        let error = resolve("pelda.hu", server.local_addr().unwrap()).unwrap_err();
        assert!(matches!(
            error.kind(),
            io::ErrorKind::WouldBlock | io::ErrorKind::TimedOut
        ));
    }
}
```

Az első teszt egy **szálon** (thread) indít egy „DNS-szervert” a `127.0.0.1` egy szabad portján, és az a kérdés azonosítójával visszaküldi a 08-04-es mintaválaszt. A második egy olyan szervert kérdez, ami sosem válaszol: ennek 3 másodperc után hibával kell véget érnie, nem szabad örökké várnia.

:::solution
```rust
//! Saját DNS-kliens (RFC 1035): egy kérdés egy UDP-csomagban, a válaszból IPv4-címek.

use std::fmt;
use std::io;
use std::net::{IpAddr, Ipv4Addr, SocketAddr, UdpSocket};
use std::time::{Duration, SystemTime};

/// A DNS-szerver, amit alapból kérdezünk: a Cloudflare nyilvános szervere.
pub const DEFAULT_DNS: SocketAddr = SocketAddr::new(IpAddr::V4(Ipv4Addr::new(1, 1, 1, 1)), 53);
```

```rust
/// A kérdés azonosítója: elég, ha nem mindig ugyanaz. A valódi kliensek kriptográfiailag
/// erős véletlent használnak, hogy egy támadó ne tudja kitalálni (DNS-mérgezés ellen).
fn query_id() -> u16 {
    let nanos = SystemTime::now()
        .duration_since(SystemTime::UNIX_EPOCH)
        .map_or(0, |d| d.subsec_nanos());
    (nanos ^ (nanos >> 16)) as u16
}

fn invalid(e: DnsError) -> io::Error {
    let kind = match e {
        DnsError::NotFound => io::ErrorKind::NotFound,
        _ => io::ErrorKind::InvalidData,
    };
    io::Error::new(kind, e)
}

/// Egy név IPv4-címei egy DNS-szervertől, UDP-n. Ha 3 másodperc alatt nincs válasz, hiba.
pub fn resolve(name: &str, server: SocketAddr) -> io::Result<Vec<Ipv4Addr>> {
    let id = query_id();
    let query = build_query(id, name).ok_or_else(|| invalid(DnsError::BadName))?;
    let socket = UdpSocket::bind(if server.is_ipv4() {
        "0.0.0.0:0"
    } else {
        "[::]:0"
    })?;
    socket.set_read_timeout(Some(Duration::from_secs(3)))?;
    socket.send_to(&query, server)?;
    let mut buf = [0u8; 512];
    loop {
        let (n, from) = socket.recv_from(&mut buf)?;
        let Ok(response) = parse_response(&buf[..n]) else {
            continue; // szemét: várunk tovább
        };
        // csak a mi szerverünk válasza a mi kérdésünkre számít
        if from != server || response.id != id {
            continue;
        }
        return match response.rcode {
            0 => {
                let ips = addresses(&response, name);
                if ips.is_empty() {
                    Err(invalid(DnsError::NotFound))
                } else {
                    Ok(ips)
                }
            }
            3 => Err(invalid(DnsError::NotFound)),
            code => Err(invalid(DnsError::ServerFailure(code))),
        };
    }
}
```

## Kérdezd meg az internetet!

Egy kis program, amivel kipróbálhatod: `crates/rozsda-net/examples/dns.rs`. Az `examples` mappa programjai a crate könyvtárát használják, és a `cargo run --example` futtatja őket.

```rust
//! Egy név IPv4-címei a saját DNS-kliensünkkel.
//! `cargo run -p rozsda-net --example dns -- pelda.hu [1.1.1.1:53]`

use rozsda_net::dns::{DEFAULT_DNS, resolve};

fn main() {
    let mut args = std::env::args().skip(1);
    let Some(name) = args.next() else {
        eprintln!("használat: dns <név> [szerver:port]");
        std::process::exit(2);
    };
    let server = match args.next() {
        Some(s) => s.parse().expect("a szerver alakja: 1.1.1.1:53"),
        None => DEFAULT_DNS,
    };
    match resolve(&name, server) {
        Ok(ips) => {
            for ip in ips {
                println!("{name} → {ip}");
            }
        }
        Err(e) => {
            eprintln!("Hiba: {e}");
            std::process::exit(1);
        }
    }
}
```

:::card
K: Mi a különbség a TCP és az UDP között?
V: A TCP kapcsolatot épít, és megbízható, sorrendhelyes bájtfolyamot ad. Az UDP önálló csomagokat küld kapcsolat nélkül: gyors, de a csomag elveszhet. A DNS UDP-t használ.
:::

:::card
K: Miért kell időkorlát a `recv_from`-ra?
V: Mert az UDP-csomag elveszhet, és ha a válasz sosem jön meg, a program örökké várna. Időkorláttal a `recv_from` hibát ad, és a hívó dönthet: újrapróbálja, vagy feladja.
:::
