## Hét szám, egy egyenlet

Egy blokkszintű doboz vízszintesen hét részből áll: bal margó, bal keret, bal kitöltés, **tartalom**, jobb kitöltés, jobb keret, jobb margó. A szabvány egyetlen egyenletet ír elő:

```text Ábra
margin-left + border-left + padding-left + width + padding-right + border-right + margin-right
                                    =
                     a tartalmazó blokk szélessége
```

A **tartalmazó blokk** (containing block) a szülő doboz **tartalomterülete**. A `<body>` tartalmazó blokkja a `<html>` tartalma, a `<html>`-é pedig maga az ablak (viewport).

A hét szám közül a keret és a kitöltés mindig ismert (pixel vagy százalék). A `width` és a két margó viszont lehet `auto`. A szabály: **az `auto` értékek veszik fel a különbséget**, hogy az egyenlet kijöjjön.

## Az esetek

Számoljuk ki először a „biztos” részeket: a keretet, a kitöltést, és a nem-`auto` értékeket (az `auto`-t egyelőre 0-nak véve). A különbség a tartalmazó blokk szélességétől: `underflow = cb_width − total`. Ezután:

| `width` | bal margó | jobb margó | Mi történik |
|---|---|---|---|
| `auto` | bármi | bármi | a `width` kapja a különbséget, az `auto` margók 0-k |
| adott | adott | `auto` | a jobb margó kapja a különbséget |
| adott | `auto` | adott | a bal margó kapja (jobbra igazított doboz) |
| adott | `auto` | `auto` | mindkét margó a fele: **középre igazítás** |
| adott | adott | adott | „túlhatározott”: a jobb margót felülírjuk |

Egy különleges szabály: ha a `width` adott, és a doboz **már így is szélesebb** a helynél, az `auto` margók 0-k lesznek (nem mehetnek negatívba, hogy középre tegyék). Ilyenkor a doboz kilóg jobbra, és a jobb margó negatív lesz.

:::compare Példák egy 500px-es szülőben
@@ CSS
```css
div { padding: 10px; border: 2px solid; }
/* width: auto → 500 − 2·10 − 2·2 = 476px a tartalom */

.kartya { width: 300px; margin: 0 auto; }
/* (500 − 300) / 2 = 100px margó mindkét oldalon */

.jobbra { width: 50%; margin-left: auto; margin-right: 20px; }
/* 50% = 250px helyett most 400px-es szülőben: 200px, és a bal margó 400 − 200 − 20 = 180px */
```
@@ Érettségi
Ez egy egyismeretlenes egyenlet (vagy kétismeretlenes, egy plusz feltétellel: a két margó egyenlő). Az algoritmus pont azt csinálja, amit papíron: összeadja az ismert tagokat, és a maradék az ismeretlené.
:::

:::note Miért a jobb margó?
Balról jobbra író nyelveknél a doboz a bal szélhez „tapad”, ezért a jobb margó enged. Jobbról balra író nyelveknél (`direction: rtl`, pl. arab, héber) épp fordítva: ott a bal margót írná felül a böngésző. A Rozsda egyelőre csak balról jobbra ír.
:::

## Megvalósítás `Option`-ökkel

Az `auto`-t a Rust természetes módon írja le: `Option<f32>`, ahol a `None` az `auto`. A 05-02-es `Size::resolve` pont ezt adja. Az esetszétválasztás pedig egy `match` a három `Option` hármasán:

```rust
match (width, margin_left, margin_right) {
    (Some(w), Some(l), Some(r)) => …, // túlhatározott
    (Some(w), Some(l), None) => …,
    (Some(w), None, Some(r)) => …,
    (Some(w), None, None) => …,       // középre
    (None, l, r) => …,                // auto szélesség
}
```

A fordító ellenőrzi, hogy mind a 8 kombinációt lefedted: az utolsó ág (`None, l, r`) négyet fog meg egyszerre.

mod tests {
    use super::*;
    use rozsda_core::layout::{BoxKind, Sides};
    use rozsda_core::style::{ComputedStyle, Size};

    fn boxed(style: ComputedStyle) -> LayoutBox {

Az első lépés csupa egysoros kiolvasás:

A margók `mut`-ok, mert a 3. lépésben változhatnak.
---
Az `Option::or` egy alternatívát ad, ha `None`: a `margin_left.or(Some(0.0))` a meglévő értéket megtartja, az `auto`-ból pedig 0-t csinál. A `total`:
```rust
let total = fixed + width.unwrap_or(0.0) + margin_left.unwrap_or(0.0) + margin_right.unwrap_or(0.0);
```
---
A `match` egy hármast ad vissza, és ugyanazokba a nevekbe érdemes kicsomagolni:
```rust
let (width, margin_left, margin_right) = match (width, margin_left, margin_right) { … };
```
Ez az **árnyékolás** (shadowing, 01-01): az új `width` egy `f32`, és eltakarja a régit, ami még `Option<f32>` volt. Így nem kell kitalálni egy `final_width` nevet. A `b.style` (olvasás) és a `b.dimensions` (írás) közben egyszerre is kölcsönözhető, mert a struct két **különböző mezője**: a borrow checker ezt tudja.

:::solution
```rust
//! Blokk-layout: szélesség (CSS 2.1, 10.3.3), pozíció és magasság (10.6.3).

use rozsda_core::layout::LayoutBox;

/// A vízszintes méretek: margók, keretek, kitöltés és a tartalom szélessége.
/// Az összegük mindig pontosan a tartalmazó blokk szélessége (`cb_width`).
pub fn calculate_width(b: &mut LayoutBox, cb_width: f32) {
    let s = &b.style;
    let width = s.width.resolve(cb_width);
    let mut margin_left = s.margin.left.resolve(cb_width);
    let mut margin_right = s.margin.right.resolve(cb_width);
    let padding_left = s.padding.left.resolve(cb_width).unwrap_or(0.0);
    let padding_right = s.padding.right.resolve(cb_width).unwrap_or(0.0);
    let border_left = s.border_width.left;
    let border_right = s.border_width.right;

    let fixed = padding_left + padding_right + border_left + border_right;
    let total =
        fixed + width.unwrap_or(0.0) + margin_left.unwrap_or(0.0) + margin_right.unwrap_or(0.0);

    // Ha a szélesség meg van adva, és már így is túl széles, az auto margók 0-k.
    if width.is_some() && total > cb_width {
        margin_left = margin_left.or(Some(0.0));
        margin_right = margin_right.or(Some(0.0));
    }

    let underflow = cb_width - total;
    let (width, margin_left, margin_right) = match (width, margin_left, margin_right) {
        // Túlhatározott: a jobb margó enged.
        (Some(w), Some(l), Some(r)) => (w, l, r + underflow),
        (Some(w), Some(l), None) => (w, l, underflow),
        (Some(w), None, Some(r)) => (w, underflow, r),
        // Mindkét margó auto: középre igazítás.
        (Some(w), None, None) => (w, underflow / 2.0, underflow / 2.0),
        // Auto szélesség: kitölti a helyet, az auto margók 0-k.
        (None, l, r) => {
            let (l, r) = (l.unwrap_or(0.0), r.unwrap_or(0.0));
            if underflow >= 0.0 {
                (underflow, l, r)
            } else {
                (0.0, l, r + underflow)
            }
        }
    };

    let d = &mut b.dimensions;
    d.content.width = width;
    d.margin.left = margin_left;
    d.margin.right = margin_right;
    d.padding.left = padding_left;
    d.padding.right = padding_right;
    d.border.left = border_left;
    d.border.right = border_right;
}
```

:::why Miért nem működik a `margin: auto` függőlegesen?
Mert a magasság másképp jön létre. A szélesség **kívülről befelé** számolódik: a szülő szélessége ismert, és a gyerek abból kap. A magasság viszont **belülről kifelé**: egy blokk olyan magas, mint a tartalma, és azt csak a gyerekek layoutja után tudjuk (05-06). Ezért a függőleges `auto` margó egyszerűen 0. Függőleges középre igazításhoz a flexbox vagy a grid kell (14. modul): `display: flex; align-items: center`. Ez volt a CSS legtöbbet emlegetett hiányossága egészen 2015 körülig.
:::

fn block_width(
    cb: f32,
    width: Option<f32>,
    margin_left: Option<f32>,
    margin_right: Option<f32>,
    fixed: f32,
) -> (f32, f32, f32) {
    let total = fixed + width.unwrap_or(0.0) + margin_left.unwrap_or(0.0) + margin_right.unwrap_or(0.0);
    let (ml, mr) = if width.is_some() && total > cb {
