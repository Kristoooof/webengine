## Honnan tudja a layout, milyen széles egy szó?

Az 5. modulban a `rozsda-layout/src/text.rs` a 8×8-as betűk számait ismerte: egy karakter `8 × nagyítás` széles, egy sor `12 × nagyítás` magas. A layout ezeket a függvényeket hívta közvetlenül:

```rust
use crate::text::{char_width, is_space, line_height, text_width};
```

Ez most megváltozik. A layout egy `&dyn FontMetrics`-et kap paraméterként, és mindent attól kérdez. Hogy mi van mögötte, az a hívó dolga: a böngészőben a DejaVu Sans, a tesztekben a régi 8×8-as betűk. Ez a **függőség befecskendezése** (dependency injection): a layout nem maga választja ki az eszközét, hanem megkapja.

:::compare Függőség befecskendezése
@@ C#
Mint amikor egy osztály a konstruktorában egy `IFontMetrics` interfészt kap, és a tesztekben egy egyszerű, kiszámítható „fake” megvalósítást adsz neki. Az ASP.NET Core egész szolgáltatás-rendszere erre épül.
@@ C++
Egy absztrakt osztályra mutató referencia (`const FontMetrics&`) paraméterként. A `&dyn FontMetrics` Rustban pontosan ez: egy vtáblán keresztül hívott, futásidőben eldőlő megvalósítás.
@@ Python
Egy objektum, amit paraméterként adsz át, és csak az számít, hogy legyen `text_width` metódusa (duck typing). Rustban ezt a trait garantálja fordításkor.
:::

## Alapvonal a sorban

Nézzük meg, hogyan rakta sorba az 5. modul a különböző méretű darabokat! A `finish_line` a sor magasságát a legmagasabb darabból vette, és minden darabot a sor **aljához** igazított:

```text Ábra
5. modul: a sor aljához igazítva          most: az alapvonalhoz igazítva

┌──────────────────────────────┐          ┌──────────────────────────────┐
│      ┌──────────┐            │          │      ┌──────────┐            │
│      │          │            │          │      │          │            │
│      │  nagy    │            │          │┌────┐│  nagy    │┌─────┐     │
│      │          │            │          ││Szia││          ││világ│     │
│┌────┐│──────────│┌─────┐     │  ─ ─ ─ ─ │└────┘└──────────┘└─────┘─ ─ ─ alapvonal
││Szia││          ││világ│     │          │      │ (lóg)    │            │
│└────┘└──────────┘└─────┘     │          │      └──────────┘            │
└──────────────────────────────┘          └──────────────────────────────┘
```

A sor alján a nagy betű **descentje** (az alapvonal alatti része) van, nem a betűk talpa. Ha minden darabot a sor aljához igazítunk, a kis betűk lejjebb kerülnek, mint a nagyok talpa. A 8×8-as betűknél ez alig látszott. Egy igazi betűtípusnál a „Szia” lejjebb csúszna, mint a „nagy” alapvonala.

A CSS szabálya (`vertical-align: baseline`, az alapértelmezés): a darabok **alapvonalai** egy vonalba kerülnek. A sor magassága:

```text Képlet
sor ascentje   = a darabok (és a blokk saját betűmérete) ascentjének maximuma
sor descentje  = a darabok (és a blokk saját betűmérete) descentjének maximuma
sor magassága  = ascent + descent
egy darab y-ja = a sor teteje + a sor ascentje − a darab ascentje
```

A blokk saját betűmérete a CSS **strut**-ja: egy láthatatlan, nulla széles „betű” minden sor elején. Ettől lesz egy csupa kis betűs sor is legalább akkora, mint a blokk egy sora (az 5. modulban ezt a `fold(line_height(self.block), …)` csinálta).

//! A szóköz-karakterek, és a 8×8-as bitképes betűk mértékei.

use rozsda_core::text::FontMetrics;

/// A CSS összevonható szóköz-karakterei. (A nem törő szóköz, U+00A0, nincs köztük!)
pub fn is_space(c: char) -> bool {
    matches!(c, ' ' | '\t' | '\n' | '\r' | '\u{000C}')
}

/// A 8×8-as betűk nagyítása a betűméretből: 16px → 2×, 32px → 4×.
pub fn glyph_scale(size: f32) -> f32 {
    (size / 8.0).round().max(1.0)
}

/// A 2. modul óta velünk lévő bitképes betűk mértékei: minden betű 8 egység széles,
/// egy sor 12 egység, ebből 9 az alapvonal fölött.
pub struct BitmapFont;

impl FontMetrics for BitmapFont {
    fn text_width(&self, text: &str, size: f32) -> f32 {
        text.chars().count() as f32 * 8.0 * glyph_scale(size)
    }

    fn ascent(&self, size: f32) -> f32 {
        9.0 * glyph_scale(size)
    }

    fn descent(&self, size: f32) -> f32 {
        3.0 * glyph_scale(size)
    }

    fn underline(&self, size: f32) -> (f32, f32) {
        let s = glyph_scale(size);
        (s, s)
    }
}

    styles: &'a StyleMap,
    block: &'a ComputedStyle,
    fonts: &'a dyn FontMetrics,
    x: f32,
    max_width: f32,
    top: f32,
    lines: Vec<LineBox>,
    current: Vec<TextFragment>,
    pen: f32,
}

impl LineBuilder<'_> {
    /// A betűméret egy elem stílusából (vagy a blokkéból, ha nincs saját stílusa).
    fn size(&self, node: NodeId) -> f32 {
        self.styles.get(node).unwrap_or(self.block).font_size
    }

    /// Lezárja az aktuális sort. A darabok alapvonala (baseline) egy vonalba kerül. A sor az
    /// alapvonal fölött a legmagasabb, alatta a legmélyebb darabig tart, de legalább akkora,
    /// mint a blokk egy sora.
    fn finish_line(&mut self) {
        let mut ascent = self.fonts.ascent(self.block.font_size);
        let mut descent = self.fonts.descent(self.block.font_size);
        for f in &self.current {
            let size = self.size(f.node);
            ascent = ascent.max(self.fonts.ascent(size));
            descent = descent.max(self.fonts.descent(size));
        }
        let height = ascent + descent;
        let mut fragments = std::mem::take(&mut self.current);
        for f in &mut fragments {
            f.rect.x += self.x;
            f.rect.y = self.top + ascent - self.fonts.ascent(self.size(f.node));
        }
        self.lines.push(LineBox {
            rect: Rect {
                x: self.x,
                y: self.top,
                width: self.max_width,
                height,
            },
            fragments,
        });
        self.top += height;
        self.pen = 0.0;
    }

            0.0
