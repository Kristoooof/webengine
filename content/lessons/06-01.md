:::goal
Kettévágod a rajzolást. A **festő** (painter) a layout-fából egy **rajzlistát** (display list) készít: egyszerű parancsok sorozatát, például „téglalap ide, ilyen színnel”. A **raszterizáló** (rasterizer) ezeket a parancsokat hajtja végre pixelekre. A lecke végén a `--lista` kapcsoló ki is írja a parancsokat.

## Miért kell egy köztes lépés?

Az 5. modulban a `paint.rs` egyszerre két dolgot csinált. Bejárta a layout-fát, és eldöntötte, mi kerüljön a képernyőre, közben pedig rögtön pixeleket is írt. Ez egy kis böngészőnek elég, de hamar a korlátaiba ütközünk:

- **Görgetéskor** minden képkockán újra bejártuk az egész fát, pedig az oldal nem változott, csak a helye.
- **Tesztelni** csak pixelekkel lehetett („a (191, 20)-as pont kék-e?”), ami törékeny és nehezen olvasható.
- **Kicserélni** sem lehetett a rajzolót, pedig a 16. modulban a profi oldalon egy GPU-s raszterizáló áll majd.

A megoldás egy köztes nyelv, a **rajzlista**:

```text Ábra
layout-fa ──► festő ──► rajzlista ──► raszterizáló ──► pixelek
(dobozok)     paint.rs  [téglalap,     raster.rs        Canvas
                         keret,
                         szöveg, …]
```

:::compare Rajzlista máshol
@@ C#
A WPF pontosan így működik. Az `OnRender(DrawingContext dc)` nem rajzol, csak parancsokat **rögzít** (`dc.DrawRectangle(…)`). A tényleges rajzolást később a renderelő szál végzi, akár a GPU-n.
@@ C++
A Chrome a festéskor `cc::DisplayItemList`-et, a Firefox `nsDisplayList`-et épít. A Skia (a Chrome 2D-motorja) `SkPicture` néven ugyanezt tudja: rögzített rajzparancsok, amiket bármikor újra le lehet játszani.
@@ Python
Olyan, mint amikor egy matplotlib-ábrán `ax.plot(…)` hívásokat gyűjtesz, és a kép csak a `savefig`-nél készül el.
@@ Érettségi
Ez a „parancssorozat” gondolat: mint a Logo teknőc utasításai. Előbb leírjuk, mit kell csinálni, aztán egy külön program végrehajtja.
:::

## A parancsok

Három parancs elég mindenre, amit most tudunk:

```rust
//! A rajzlista (display list): a festő kimenete és a raszterizáló bemenete.

use crate::layout::{Rect, Sides};
use crate::style::Color;

/// Egy rajzolási parancs, a lap koordinátáiban (a görgetés nélkül).
#[derive(Debug, Clone, PartialEq)]
pub enum DisplayItem {
    /// Kitöltött téglalap. A `radius` a sarkok lekerekítése (0: szögletes).
    Rect {
        rect: Rect,
        color: Color,
        radius: f32,
    },
    /// Keret a téglalap belső szélén, oldalanként más vastagsággal.
    Border {
        rect: Rect,
        widths: Sides<f32>,
        color: Color,
        radius: f32,
    },
    /// Egy darab szöveg a 8×8-as betűkkel, `scale`-szeres nagyításban.
    Text {
        rect: Rect,
        text: String,
        color: Color,
        scale: u32,
        bold: bool,
    },
}
```

Három dologra figyelj:

- A koordináták a **lapon** értendők, nem az ablakban. A görgetést majd a raszterizáló vonja le, így a lista görgetéskor nem változik.
- A szín `Color`, nem `u32`. Így megmarad az átlátszóság (`a`), ami a következő leckében kap szerepet.
- A `radius` most mindig 0. A 06-03-ban jönnek a lekerekített sarkok, és akkor már nem kell az összes parancsot átírni.

A típusok a `rozsda-core`-ba kerülnek, mert a rajzlista a közös nyelv a festő és a raszterizáló között. Később egy profi raszterizáló is ezt kapja.

```rust
//! Festés: a layout-fából rajzlista. Itt dől el, mi kerül a képernyőre, és milyen sorrendben.

use rozsda_core::display::DisplayItem;
use rozsda_core::dom::Document;
use rozsda_core::layout::{BoxKind, LayoutBox, Rect, Sides};
use rozsda_core::style::{Color, ComputedStyle, Display, StyleMap};
use rozsda_layout::dump::format_rect;
use rozsda_layout::text::{char_width, glyph_scale, line_height};

/// A `--keretek` hibakereső körvonalainak színe.
const OUTLINE: Color = Color::rgb(0xE1, 0x1D, 0x48);

/// A `<html>` és a `<body>` háttere a vászoné lesz (a szabvány szerint „továbbterjed”),
/// ezért a saját dobozukra nem rajzoljuk ki még egyszer.
fn paints_own_background(doc: &Document, b: &LayoutBox) -> bool {
    match b.kind {
        BoxKind::Block(id) => !matches!(doc.tag_name(id), Some("html" | "body")),
        BoxKind::Anonymous => true,
    }
}

fn paint_text(list: &mut Vec<DisplayItem>, style: &ComputedStyle, rect: Rect, text: &str) {
    list.push(DisplayItem::Text {
        rect,
        text: text.to_string(),
        color: style.color,
        scale: glyph_scale(style) as u32,
        bold: style.font_weight >= 600,
    });
}

/// A felsorolásjel a tartalom bal széle előtt, a kitöltésben.
fn paint_marker(list: &mut Vec<DisplayItem>, b: &LayoutBox) {
    let s = &b.style;
    let c = b.dimensions.content;
    let rect = Rect {
        x: c.x - 2.0 * char_width(s),
        y: c.y,
        width: char_width(s),
        height: line_height(s),
    };
    paint_text(list, s, rect, "»");
}
```

```rust
/// Egy doboz parancsai, aztán a gyerekeié: a festő algoritmus sorrendje.
fn paint_box(
    list: &mut Vec<DisplayItem>,
    doc: &Document,
    styles: &StyleMap,
    b: &LayoutBox,
    outlines: bool,
) {
    let border_box = b.dimensions.border_box();
    let background = b.style.background_color;
    if background.a > 0 && paints_own_background(doc, b) {
        list.push(DisplayItem::Rect {
            rect: border_box,
            color: background,
            radius: 0.0, // a 06-03-ban kap értelmet
        });
    }
    let widths = b.dimensions.border;
    if widths != Sides::all(0.0) {
        list.push(DisplayItem::Border {
            rect: border_box,
            widths,
            color: b.style.border_color,
            radius: 0.0,
        });
    }
    if b.style.display == Display::ListItem {
        paint_marker(list, b);
    }
    for line in &b.lines {
        for f in &line.fragments {
            let style = styles.get(f.node).unwrap_or(&b.style);
            paint_text(list, style, f.rect, &f.text);
        }
    }
    if outlines {
        list.push(DisplayItem::Border {
            rect: border_box,
            widths: Sides::all(1.0),
            color: OUTLINE,
            radius: 0.0,
        });
    }
    for child in &b.children {
        paint_box(list, doc, styles, child, outlines);
    }
}

pub fn build_display_list(
    doc: &Document,
    styles: &StyleMap,
    root: &LayoutBox,
    outlines: bool,
) -> Vec<DisplayItem> {
    let mut list = Vec::new();
    paint_box(&mut list, doc, styles, root, outlines);
    list
}
```

```rust
fn color_name(c: Color) -> String {
    if c.a == 255 {
        c.to_hex()
    } else {
        format!("{} {}%", c.to_hex(), (c.a as f32 / 2.55).round())
    }
}

/// A rajzlista szöveges alakja (`--lista`): soronként egy parancs.
pub fn dump_display_list(items: &[DisplayItem]) -> String {
    let mut out = String::new();
    for item in items {
        let line = match item {
            DisplayItem::Rect {
                rect,
                color,
                radius,
            } => format!(
                "téglalap {} {} r={radius}",
                format_rect(rect),
                color_name(*color)
            ),
            DisplayItem::Border {
                rect,
                widths: w,
                color,
                radius,
            } => format!(
                "keret {} {} {},{},{},{} r={radius}",
                format_rect(rect),
                color_name(*color),
                w.top,
                w.right,
                w.bottom,
                w.left
            ),
            DisplayItem::Text {
                rect,
                text,
                color,
                scale,
                bold,
            } => format!(
                "szöveg {} {} {scale}×{} {text:?}",
                format_rect(rect),
                color_name(*color),
                if *bold { " félkövér" } else { "" }
            ),
        };
        out.push_str(&line);
        out.push('\n');
    }
    out
}
```

Az új `src/raster.rs` a régi pixelrajzoló kód, egy `match`-csel a parancsokra. Gépeld be:

```rust
//! Raszterizálás: a rajzlista parancsaiból pixelek a vásznon.

use crate::canvas::Canvas;
use crate::text::{GLYPH, draw_text};
use rozsda_core::display::DisplayItem;
use rozsda_core::layout::{Rect, Sides};

fn fill(canvas: &mut Canvas, r: Rect, scroll: i32, color: u32) {
    canvas.fill_rect(
        r.x.round() as i32,
        r.y.round() as i32 - scroll,
        r.width.round() as i32,
        r.height.round() as i32,
        color,
    );
}

/// A keret négy téglalap, a doboz négy szélén.
fn border(canvas: &mut Canvas, r: Rect, w: Sides<f32>, scroll: i32, color: u32) {
    fill(canvas, Rect { height: w.top, ..r }, scroll, color);
    let bottom = Rect {
        y: r.bottom() - w.bottom,
        height: w.bottom,
        ..r
    };
    fill(canvas, bottom, scroll, color);
    fill(canvas, Rect { width: w.left, ..r }, scroll, color);
    let right = Rect {
        x: r.right() - w.right,
        width: w.right,
        ..r
    };
    fill(canvas, right, scroll, color);
}

/// Szöveg a téglalap közepére igazítva. A félkövér: még egyszer, egy pixellel jobbra.
fn text(
    canvas: &mut Canvas,
    rect: Rect,
    text: &str,
    scale: u32,
    bold: bool,
    scroll: i32,
    color: u32,
) {
    let scale = scale as i32;
    let x = rect.x.round() as i32;
    let y = (rect.y + (rect.height - (GLYPH * scale) as f32) / 2.0).round() as i32 - scroll;
    draw_text(canvas, x, y, text, scale, color);
    if bold {
        draw_text(canvas, x + 1, y, text, scale, color);
    }
}

pub fn rasterize(canvas: &mut Canvas, items: &[DisplayItem], scroll: i32) {
    for item in items {
        match item {
            DisplayItem::Rect { rect, color, .. } => fill(canvas, *rect, scroll, color.to_u32()),
            DisplayItem::Border {
                rect,
                widths,
                color,
                ..
            } => border(canvas, *rect, *widths, scroll, color.to_u32()),
            DisplayItem::Text {
                rect,
                text: t,
                color,
                scale,
                bold,
            } => text(canvas, *rect, t, *scale, *bold, scroll, color.to_u32()),
        }
    }
}
```

A `text: t` a mintában átnevezi a mezőt, mert a `text` név már foglalt: így hívják a függvényt is. A `..` a `radius`-t hagyja ki, amit még nem használunk.

:::why Miért nem a GPU rajzol?
A mai böngészők a rajzlistát nem pixelenként hajtják végre a processzoron, hanem a **GPU**-nak adják oda. A Firefox WebRendere (Rustban írták!) a teljes rajzlistát háromszögekké alakítja, és a videokártya rajzolja ki, akár 120 képkocka per másodperccel. A Chrome a lapot csempékre (tiles) osztja, és a csempéket több szálon raszterizálja.

Mi most szoftveres raszterizálót írunk, mert így minden pixelt értünk. A rajzlista miatt viszont a raszterizáló cserélhető: a 16. modulban a profi oldalon egy kész crate (`tiny-skia` vagy `vello`) kapja ugyanezt a listát.
:::

:::exercise A festés sorrendje
@@ feladat
A festő a fát **preorder** sorrendben járja be: előbb a dobozt, aztán balról jobbra a gyerekeit, mindegyiket a saját részfájával együtt. A fa itt egy `children` lista: a `children[i]` az `i`. doboz gyerekeinek sorszámai. Add vissza a dobozok festési sorrendjét a `root`-tól kezdve!
@@ kód
```rust
fn paint_order(children: &[Vec<usize>], root: usize) -> Vec<usize> {
    todo!()
}
```
@@ megoldás
```rust
fn paint_order(children: &[Vec<usize>], root: usize) -> Vec<usize> {
    fn visit(children: &[Vec<usize>], node: usize, out: &mut Vec<usize>) {
        out.push(node);
        for &child in &children[node] {
            visit(children, child, out);
        }
    }
    let mut out = Vec::new();
    visit(children, root, &mut out);
    out
}
```
@@ magyarázat
Egy rekurzív bejárás egyetlen, közös kimeneti vektorba írva, mint a `paint_box` a `list`-tel. Minden doboz pontosan egyszer kerül sorra, és nem keletkeznek ideiglenes vektorok.
@@ esetek
```rust
paint_order(&[vec![1, 2], vec![], vec![]], 0)
paint_order(&[vec![1], vec![2], vec![3], vec![]], 0)
paint_order(&[vec![1, 4], vec![2, 3], vec![], vec![], vec![5], vec![]], 0)
paint_order(&[vec![]], 0)
paint_order(&[vec![], vec![0, 2], vec![]], 1)
```
@@ mérés

@@ teszt-rossz
```rust
fn paint_order(children: &[Vec<usize>], root: usize) -> Vec<usize> {
    fn visit(children: &[Vec<usize>], node: usize, out: &mut Vec<usize>) {
        for &child in &children[node] {
            visit(children, child, out);
        }
        out.push(node);
    }
    let mut out = Vec::new();
    visit(children, root, &mut out);
    out
}
```
@@ teszt-lassú
```rust
fn paint_order(children: &[Vec<usize>], root: usize) -> Vec<usize> {
    let mut out = vec![root];
    for &child in &children[root] {
        let sub = paint_order(children, child);
        out = [out, sub].concat();
    }
    out
}
```
