## A framebuffer

A képernyő memóriabeli képe egy **pixeltömb**. Minden pixel egy szín, és a minifb (meg a legtöbb rajzolókönyvtár) `u32`-ként tárolja: `0x00RRGGBB`. Az első bájt nem használt, aztán jön a piros, a zöld és a kék, 0-tól 255-ig.

| Szín | Érték |
|---|---|
| fekete | `0x000000` |
| fehér | `0xFFFFFF` |
| Rozsda-narancs | `0xEA580C` |
| törtfehér háttér | `0xFAFAF9` |

A tömb **egydimenziós**, pedig a képernyő kétdimenziós. A pixelek soronként egymás után jönnek:

```text Képlet
index = y * szélesség + x
```

:::compare Ezt már láttad
@@ Érettségi
Ha egy 2D-s tömböt (`t[sor][oszlop]`) egyetlen hosszú tömbként akartál tárolni, pontosan ez volt a képlet: `sor * oszlopszám + oszlop`. A képernyő egy 960 oszlopos és 720 soros 2D-s tömb, ami egyetlen `Vec<u32>`-ben van.
@@ C#
```csharp
int idx = y * width + x;
pixels[idx] = 0xEA580C;
```
Teljesen ugyanaz. A különbség, hogy Rustban a túlindexelés pánikot okoz, nem csendes memóriaszemetelést.
:::

## minifb: egy ablak, ami egy pixeltömböt mutat

A **minifb** egy kicsi crate, ami pontosan annyit tud, amennyi most kell: nyit egy ablakot, megmutat benne egy pixeltömböt, és megmondja, milyen billentyűt nyomtál le. Később (a 6. modulban) erősebb eszközre cseréljük, de a 0.1-hez tökéletes.

```powershell
cd crates/rozsda-browser
cargo add minifb
cd ../..
```

:::note Saját ablak „nulláról”?
Az ablaknyitás az operációs rendszer dolga (Windowson a Win32 API, Linuxon az X11 vagy a Wayland). Ezt „nulláról” megírni nem a böngészőről szól, csak sok Windows-specifikus kódot jelentene. Ezért az ablakot és a billentyűzetet egy crate intézi. **Minden pixelt viszont te rajzolsz.**
:::

## A legkisebb ablak

```rust
use minifb::{Key, Window, WindowOptions};

const WIDTH: usize = 960;
const HEIGHT: usize = 720;

fn main() {
    let mut pixels = vec![0xFAFAF9u32; WIDTH * HEIGHT];
    let mut window = Window::new("Rozsda", WIDTH, HEIGHT, WindowOptions::default())
        .expect("nem sikerült ablakot nyitni");
    window.set_target_fps(60);

    while window.is_open() && !window.is_key_down(Key::Escape) {
        window.update_with_buffer(&pixels, WIDTH, HEIGHT).unwrap();
    }
}
```

- A `vec![érték; db]` egy `db` elemű vektort hoz létre, ahol minden elem `érték`.
- A `while` ciklus a **render loop**: minden körben (másodpercenként kb. 60-szor) kirajzolja a tömböt, és feldolgozza az eseményeket.
- Az `Esc` és az ablak bezárása kilép.

Futtasd (`cargo run -p rozsda-browser`). Egy törtfehér ablaknak kell megjelennie. **Ez a böngésződ első ablaka!** 🎉

## Canvas: a rajzolás becsomagolva

A nyers `Vec<u32>`-be rajzolni hibalehetőség: könnyű kiindexelni belőle, és a képletet mindenhol újra kell írni. Csomagoljuk be egy típusba, ami **sosem rajzol a tömbön kívülre**. Ezt hívják *clipping*-nek, vágásnak.

:::task
Hozz létre egy új modult: `crates/rozsda-browser/src/canvas.rs` (és a `main.rs` tetejére `mod canvas;`). Írd meg benne:

1. `pub const fn rgb(r: u8, g: u8, b: u8) -> u32`, ami a három csatornát egy `u32`-be csomagolja (biteltolással: `(r as u32) << 16`, …).
2. `pub struct Canvas { pub width: usize, pub height: usize, pub pixels: Vec<u32> }`
3. `Canvas::new(width, height)`, ami fekete (0) pixelekkel tölti fel.
4. `clear(&mut self, color: u32)`, ami minden pixelt átszínez.
5. `put_pixel(&mut self, x: i32, y: i32, color: u32)`, ami **nem csinál semmit**, ha a pont kívül esik.
6. `fill_rect(&mut self, x: i32, y: i32, w: i32, h: i32, color: u32)`, ami kitölt egy téglalapot, de **csak a látható részét**.
:::

```rust test
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn rgb_packs_channels() {
        assert_eq!(rgb(0xEA, 0x58, 0x0C), 0xEA580C);
        assert_eq!(rgb(0, 0, 0), 0);
    }

    #[test]
    fn put_pixel_and_bounds() {
        let mut c = Canvas::new(4, 3);
        c.put_pixel(1, 2, 7);
        assert_eq!(c.pixels[2 * 4 + 1], 7);
        c.put_pixel(-1, 0, 9);
        c.put_pixel(4, 0, 9);
        c.put_pixel(0, 3, 9);
        assert!(!c.pixels.contains(&9));
    }

    #[test]
    fn fill_rect_is_clipped() {
        let mut c = Canvas::new(4, 4);
        c.fill_rect(2, 2, 10, 10, 1);
        assert_eq!(c.pixels.iter().filter(|p| **p == 1).count(), 4);
        c.fill_rect(-5, -5, 6, 6, 2);
        assert_eq!(c.pixels[0], 2);
        assert_eq!(c.pixels.iter().filter(|p| **p == 2).count(), 1);
    }
}
```

:::note Miért i32 a koordináta, ha a méret usize?
Mert egy elem lehet **részben a képernyőn kívül**: görgetéskor egy sor teteje negatív `y`-ra kerül. Az `usize` nem lehet negatív, az `i32` igen. Ezért a koordináták `i32`-k, és csak az indexeléskor váltunk `usize`-ra, de akkor már biztosan nem negatív értékkel.
:::

:::hint
Az `rgb` egy kifejezés: `((r as u32) << 16) | ((g as u32) << 8) | (b as u32)`. A `<<` biteltolás, a `|` bitenkénti VAGY. A `const fn` azt jelenti, hogy fordítási időben is kiértékelhető, így konstansokban is használhatod: `const BG: u32 = rgb(250, 250, 249);`.
---
A `put_pixel`: ha `x < 0 || y < 0 || x >= self.width as i32 || y >= self.height as i32`, akkor `return`. Különben `self.pixels[y as usize * self.width + x as usize] = color;`
---
A `fill_rect` a vágással: számold ki a látható téglalap sarkait, és csak azon menj végig.
```rust
let x0 = x.max(0);
let y0 = y.max(0);
let x1 = (x + w).min(self.width as i32);
let y1 = (y + h).min(self.height as i32);
for py in y0..y1 {
    for px in x0..x1 { /* ... */ }
}
```
Ha a téglalap teljesen kívül esik, akkor `x0 >= x1`, és a ciklus egyszer sem fut le. Ezt az esetet nem is kell külön kezelni.
:::

:::solution
```rust
pub struct Canvas {
    pub width: usize,
    pub height: usize,
    pub pixels: Vec<u32>,
}

pub const fn rgb(r: u8, g: u8, b: u8) -> u32 {
    ((r as u32) << 16) | ((g as u32) << 8) | (b as u32)
}

impl Canvas {
    pub fn new(width: usize, height: usize) -> Canvas {
        Canvas { width, height, pixels: vec![0; width * height] }
    }

    pub fn clear(&mut self, color: u32) {
        for p in self.pixels.iter_mut() {
            *p = color;
        }
    }

    pub fn put_pixel(&mut self, x: i32, y: i32, color: u32) {
        if x < 0 || y < 0 || x >= self.width as i32 || y >= self.height as i32 {
            return;
        }
        let idx = y as usize * self.width + x as usize;
        self.pixels[idx] = color;
    }

    pub fn fill_rect(&mut self, x: i32, y: i32, w: i32, h: i32, color: u32) {
        let x0 = x.max(0);
        let y0 = y.max(0);
        let x1 = (x + w).min(self.width as i32);
        let y1 = (y + h).min(self.height as i32);
        for py in y0..y1 {
            for px in x0..x1 {
                self.pixels[py as usize * self.width + px as usize] = color;
            }
        }
    }
}
```
:::
