Megépíted a `Token` enumot (kezdőtag, zárótag, szöveg, komment), és a `match` segítségével biztonságosan feldolgozod. Ez lesz a tokenizered kimenete a modul végén.

## Az enum Rustban más, mint amit megszoktál

C#-ban és C++-ban az enum lényegében elnevezett egész számok listája. Rustban az enum minden változata **saját adatot hordozhat**:

```rust
#[derive(Debug, Clone, PartialEq)]
enum Token {
    StartTag { name: String, self_closing: bool },  // struct-szerű változat
    EndTag { name: String },
    Text(String),                                    // tuple-szerű változat
    Comment(String),
}
```

Egy `Token` értéke **pontosan egy** a négy közül, és csak az ahhoz tartozó adatot tárolja. Szövegtokennek nincs `self_closing` mezője, zárótagnak nincs szövege.

```rust
let a = Token::StartTag { name: String::from("p"), self_closing: false };
let b = Token::Text(String::from("Szia"));
let c = Token::EndTag { name: String::from("p") };
```

:::compare
@@ C#
```csharp
// C#-ban osztályhierarchiával szokás:
abstract record Token;
record StartTag(string Name, bool SelfClosing) : Token;
record EndTag(string Name) : Token;
record Text(string Value) : Token;
```
Működik, de négy típus, öröklés, és semmi nem garantálja, hogy egy `switch` minden esetet lekezel.
@@ C++
```cpp
using Token = std::variant<StartTag, EndTag, Text, Comment>;
std::visit(overloaded{ ... }, token);
```
A `std::variant` a legközelebbi rokon, de a használata nehézkes.
@@ Rust
```rust
enum Token {
    StartTag { name: String, self_closing: bool },
    EndTag { name: String },
    Text(String),
    Comment(String),
}
```
Egy típus, és a `match` garantálja, hogy egyik esetet se felejtsd el.
:::

## match: mintaillesztés

```rust
fn describe(token: &Token) -> String {
    match token {
        Token::StartTag { name, .. } => format!("kezdőtag: {name}"),
        Token::EndTag { name } => format!("zárótag: {name}"),
        Token::Text(t) => format!("szöveg: {t:?}"),
        Token::Comment(_) => String::from("komment"),
    }
}
```

- Minden ág egy **minta** (`=>` előtt) és egy **kifejezés** (utána).
- A minta **szétszedi** az adatot: a `Token::Text(t)` ágban a `t` a szöveg.
- A `..` jelentése: „a többi mező nem érdekel”.
- A `_` jelentése: „van itt valami, de nem érdekel”.
- A `match` is kifejezés: az értéke az éppen illeszkedő ág értéke.

### A fordító ellenőrzi, hogy minden esetet kezeltél-e

Ez a legjobb rész. Ha kitörlöd a `Comment` ágat:

```text
error[E0004]: non-exhaustive patterns: `&Token::Comment(_)` not covered
 --> src/main.rs:2:11
  |
2 |     match token {
  |           ^^^^^ pattern `&Token::Comment(_)` not covered
```

Ha egy fél év múlva hozzáadsz egy új tokenfajtát (pl. `Doctype`), a fordító **minden** helyet megmutat, ahol kezelni kell. Egy böngészőmotorban, ahol a tokeneket tíz különböző helyen dolgozod fel, ez felbecsülhetetlen.

### Minták, amiket gyakran fogsz használni

```rust
match token {
    // konkrét értékre illesztés a mintán belül
    Token::StartTag { name, self_closing: true } => { /* önzáró */ }
    // őrfeltétel (guard): if a minta után
    Token::Text(t) if t.trim().is_empty() => { /* csak whitespace */ }
    // _ : minden más
    _ => {}
}
```

### if let: ha csak egy eset érdekel

```rust
if let Token::Text(t) = &token {
    println!("szöveg: {t}");
}
```

Ugyanaz, mint egy kétágú `match`, ahol a másik ág `_ => {}`.

### matches!: igen vagy nem

```rust
let is_tag = matches!(token, Token::StartTag { .. } | Token::EndTag { .. });
```

A `|` a mintában azt jelenti: „ez vagy az”.

## Te jössz

:::task
Hozd létre a `Token` enumot, és írd meg hozzá ezeket az `impl Token { ... }` blokkban:

1. `fn describe(&self) -> String`, ezekkel a kimenetekkel:
   - önzáró kezdőtag: `"önzáró tag: br"`
   - sima kezdőtag: `"kezdőtag: p"`
   - zárótag: `"zárótag: p"`
   - szöveg: `"szöveg: \"Szia\""` (a `{t:?}` formátum teszi köré az idézőjeleket)
   - komment: `"komment"`
2. `fn is_whitespace_text(&self) -> bool`: igaz, ha a token szöveg, és csak szóközféléket tartalmaz.
3. `fn from_tag(tag: Tag) -> Token`: az előző leckében írt `Tag`-ből készít tokent (`EndTag`, ha `closing`, különben `StartTag`).
:::

```rust test
    #[test]
    fn token_describe() {
        let t = Token::StartTag { name: "p".into(), self_closing: false };
        assert_eq!(t.describe(), "kezdőtag: p");
        assert_eq!(Token::StartTag { name: "br".into(), self_closing: true }.describe(), "önzáró tag: br");
        assert_eq!(Token::EndTag { name: "p".into() }.describe(), "zárótag: p");
        assert_eq!(Token::Text("Szia".into()).describe(), "szöveg: \"Szia\"");
        assert_eq!(Token::Comment("x".into()).describe(), "komment");
    }

    #[test]
    fn token_whitespace_text() {
        assert!(Token::Text("  \n ".into()).is_whitespace_text());
        assert!(!Token::Text(" a ".into()).is_whitespace_text());
        assert!(!Token::EndTag { name: "p".into() }.is_whitespace_text());
    }

    #[test]
    fn token_from_tag() {
        assert_eq!(Token::from_tag(Tag::parse("</p>")), Token::EndTag { name: "p".into() });
        assert_eq!(
            Token::from_tag(Tag::parse("<br/>")),
            Token::StartTag { name: "br".into(), self_closing: true }
        );
    }
```

:::note Mi az a `.into()`?
A tesztekben a `"p".into()` egy `&str`-ből `String`-et csinál. Ugyanaz, mint a `String::from("p")`, csak rövidebb. A fordító a környezetből tudja, hogy `String` kell. Az `Into` trait egyike a sok átalakító traitnek. A 01-12-es leckében megérted, hogyan működik.
:::

:::hint
A `describe`-nál a sorrend számít! Az önzáró ág (`self_closing: true`) kerüljön a sima `StartTag { name, .. }` **elé**, különben az általánosabb minta „elnyeli” az önzáró tageket.
---
Az `is_whitespace_text`-hez egy `match` két ággal: `Token::Text(t) => ...`, és `_ => false`. A szövegnél végig kell nézni a karaktereket. Egy ciklussal is megy, de van rövidebb is: `t.chars().all(|c| c.is_whitespace())`. Ez egy iterátor egy closure-rel, a 01-10-es leckében részletesen megnézzük.
---
A `from_tag` a `tag`-et `self` értékként kapja (move), így a `tag.name`-et közvetlenül átteheted a tokenbe, nem kell `clone()`:
```rust
if tag.closing {
    Token::EndTag { name: tag.name }
} else { ... }
```
:::

:::solution
```rust
#[derive(Debug, Clone, PartialEq)]
enum Token {
    StartTag { name: String, self_closing: bool },
    EndTag { name: String },
    Text(String),
    Comment(String),
}

impl Token {
    fn describe(&self) -> String {
        match self {
            Token::StartTag { name, self_closing: true } => format!("önzáró tag: {name}"),
            Token::StartTag { name, .. } => format!("kezdőtag: {name}"),
            Token::EndTag { name } => format!("zárótag: {name}"),
            Token::Text(t) => format!("szöveg: {t:?}"),
            Token::Comment(_) => String::from("komment"),
        }
    }

    fn is_whitespace_text(&self) -> bool {
        match self {
            Token::Text(t) => t.chars().all(|c| c.is_whitespace()),
            _ => false,
        }
    }

    fn from_tag(tag: Tag) -> Token {
        if tag.closing {
            Token::EndTag { name: tag.name }
        } else {
            Token::StartTag { name: tag.name, self_closing: tag.self_closing }
        }
    }
}
```
:::

:::why Az Option és a Result is csak enum
A következő leckében két enummal találkozol, amelyeket a standard könyvtár ad, és amelyek ott vannak az egész Rustban:
```rust
enum Option<T> { Some(T), None }
enum Result<T, E> { Ok(T), Err(E) }
```
Semmi varázslat: ugyanaz a nyelvi eszköz, amivel most a `Token`-t írtad. A `<T>` azt jelenti, hogy bármilyen típust tartalmazhat (generikus).
:::

:::quiz
Miért jobb a Rust `match`, mint egy C#-os `switch` alapértelmezett ág nélkül?
- [ ] Gyorsabb
- [x] A fordító ellenőrzi, hogy minden lehetséges esetet lekezeltél-e
- [ ] Rövidebb a szintaxisa
> Ezt hívják *exhaustiveness checking*-nek. Ha új változatot adsz az enumhoz, a fordító minden olyan `match`-nél szól, ahol még nincs kezelve.
:::

:::card
K: Miben más a Rust enum, mint a C#/C++ enum?
V: Minden változata saját adatot hordozhat (pl. `Text(String)`, `StartTag { name, self_closing }`). Inkább egy „tagged union”, nem csak elnevezett számok.
:::

:::card
K: Mit jelent a `..` és a `_` egy mintában?
V: `..`: a többi mező nem érdekel. `_`: van itt egy érték, de nem kötöm változóhoz. Utolsó ágként (`_ =>`) minden más esetet elkap.
:::

:::card
K: Mikor használsz `if let`-et `match` helyett?
V: Ha csak **egy** változat érdekel, és a többi esetben nem kell semmit csinálni.
:::

- `match` mintákkal, őrfeltétellel, `..`-tal és `_`-sal.
- Láttad, hogy a fordító szól, ha egy esetet elfelejtesz.
