## Mit tud a Rozsda 0.1?

Szándékosan keveset. A 0.1-es változat még nem épít DOM-fát (az a 3. modul). Az oldalt egyszerűen **szövegblokkok listájaként** látja:

```text Ábra
Page
├── title: "Az első oldalam"
└── blocks:
    ├── Heading(1): "Szia, Rozsda!"
    ├── Paragraph:  "Ez az első oldal, amit…"
    ├── Heading(2): "Amit már tud"
    ├── ListItem:   "Megnyit egy HTML-fájlt"
    └── ListItem:   "Kiveszi a címet és a szöveget"
```

Ennyi elég ahhoz, hogy a címsorok nagyobbak legyenek, a listaelemek elé jel kerüljön, és a szöveg bekezdésekre tagolódjon.

## Dokumentációs kommentek

Mielőtt nekiállsz: a Rustban a `///` kezdetű komment **dokumentáció**. A `cargo doc --open` ebből szép HTML-dokumentációt készít, és a rust-analyzer is megmutatja, ha a típus fölé viszed az egeret. A `//!` a modul (vagy crate) egészét dokumentálja, a fájl tetején.

```rust
//! A Rozsda közös típusai és traitjei.

/// Egy szövegblokk az oldalon.
pub struct Block { /* ... */ }
```

:::adhd Dokumentáció = üzenet a jövőbeli önmagadnak
Három hét múlva nem fogsz emlékezni, mire való a `BlockKind::Heading(u8)` száma. Egy egysoros `///` most 10 másodperc, és később rengeteg „mit is csináltam itt?” pillanattól kímél meg.
:::

## A típusok

:::task
Írd meg a `crates/rozsda-core/src/lib.rs`-be (az előző leckés `version()` maradhat):

1. `BlockKind` enum: `Heading(u8)`, `Paragraph`, `ListItem`. Derive: `Debug, Clone, Copy, PartialEq`.
2. `Block` struct: `kind: BlockKind`, `text: String`. Minden mező legyen `pub`. Derive: `Debug, Clone, PartialEq`.
3. `Page` struct: `title: Option<String>`, `blocks: Vec<Block>`, `pub` mezőkkel. Derive: `Debug, Clone, PartialEq, Default`.
4. `impl Page`: `pub fn plain_text(&self) -> String`, ami a blokkok szövegét sortöréssel (`"\n"`) fűzi össze.
5. `HtmlParser` trait: `fn name(&self) -> &'static str;` és `fn parse(&self, html: &str) -> Page;`
6. `Implementation` enum: `Own`, `Pro`. Derive: `Debug, Clone, Copy, PartialEq`.

Mindegyikhez írj egy rövid `///` kommentet!
:::

```rust test
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn plain_text_joins_blocks() {
        let page = Page {
            title: None,
            blocks: vec![
                Block { kind: BlockKind::Heading(1), text: "Cím".into() },
                Block { kind: BlockKind::Paragraph, text: "Szöveg".into() },
            ],
        };
        assert_eq!(page.plain_text(), "Cím\nSzöveg");
    }

    #[test]
    fn default_page_is_empty() {
        let p = Page::default();
        assert_eq!(p.title, None);
        assert!(p.blocks.is_empty());
    }
}
```

:::note Miért lehet a BlockKind Copy, a Block miért nem?
A `BlockKind` csak egy kis szám (melyik változat, és egy `u8`), ezért olcsó másolni. Ha `Copy`, akkor nem kell vele move-ok miatt bajlódni. A `Block`-ban viszont van egy `String`, ami a heapen él, ezért az **nem lehet** `Copy`. A fordító nem is engedné.
:::

:::note Mit ad a Default derive?
A `Page::default()` egy „üres” oldalt ad: `title: None`, `blocks: vec![]`. Minden mező a saját alapértékét kapja (`Option` → `None`, `Vec` → üres, szám → 0, `bool` → `false`). A parserben így kezdjük majd: `let mut page = Page::default();`.
:::

:::hint
A `plain_text` iterátorral szép:
```rust
self.blocks
    .iter()
    .map(|b| b.text.as_str())
    .collect::<Vec<_>>()
    .join("\n")
```
A `collect::<Vec<_>>()` a „turbofish” szintaxis: így mondod meg a `collect`-nek, milyen típust gyűjtsön, ha a környezetből nem derül ki. A `_` azt jelenti: „az elemtípust találd ki te”.
---
Egy sima ciklussal is tökéletes: egy `String`, és minden blokk előtt (az első kivételével) egy `push('\n')`.
:::

:::solution
```rust
//! A Rozsda közös típusai és traitjei.

pub fn version() -> &'static str {
    "0.1.0-dev"
}

/// Egy blokk fajtája. A 0.1-ben ennyit különböztetünk meg.
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum BlockKind {
    Heading(u8),
    Paragraph,
    ListItem,
}

/// Egy szövegblokk az oldalon.
#[derive(Debug, Clone, PartialEq)]
pub struct Block {
    pub kind: BlockKind,
    pub text: String,
}

/// A parse eredménye. A 3. modulban ezt egy igazi DOM váltja fel.
#[derive(Debug, Clone, PartialEq, Default)]
pub struct Page {
    pub title: Option<String>,
    pub blocks: Vec<Block>,
}

impl Page {
    /// Az összes blokk szövege, sortörésekkel elválasztva.
    pub fn plain_text(&self) -> String {
        self.blocks
            .iter()
            .map(|b| b.text.as_str())
            .collect::<Vec<_>>()
            .join("\n")
    }
}

/// Bármi, ami HTML-ből oldalt tud csinálni.
pub trait HtmlParser {
    fn name(&self) -> &'static str;
    fn parse(&self, html: &str) -> Page;
}

/// Melyik implementáció fusson egy alrendszerben.
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum Implementation {
    Own,
    Pro,
}
```
:::

## Nézd meg a saját dokumentációdat

```powershell
cargo doc -p rozsda-core --open
```

Megnyílik a böngésződben a crate dokumentációja, a `///` kommentjeiddel, ugyanabban a formában, ahogy a docs.rs-en a profi crate-eké. Ez kicsit büszkeséggel tölthet el. 🙂

:::why Miért nem DOM már most?
Mert a gyors győzelem fontosabb, mint a tökéletesség. Egy igazi DOM-hoz arénára, NodeId-kre, fa-építő algoritmusra és hibatűrésre van szükség. Ez egy egész modul (a 3.). A `Page` viszont egyetlen délután alatt elvisz a működő ablakig. Amikor a 3. modulban jön a DOM, a `HtmlParser` trait kimenetét egyszerűen lecseréljük, és a fordító megmutatja az összes helyet, amit módosítani kell. A Rust-refaktorálás pont ilyen: a fordító végigvezet rajta.
:::

:::card
K: Mi a különbség a `//`, a `///` és a `//!` között?
V: `//`: sima komment. `///`: dokumentáció a következő elemhez (típus, függvény). `//!`: dokumentáció a befoglaló modulhoz vagy crate-hez.
:::

:::card
K: Mit ad a `#[derive(Default)]`?
V: Egy `Típus::default()` függvényt, ami minden mezőt a saját alapértékére állít (`None`, üres `Vec`, 0, `false`…).
