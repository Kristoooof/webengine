## A szerkesztő

Rusthoz a legelterjedtebb ingyenes szerkesztő a **VS Code** a **rust-analyzer** bővítménnyel. A rust-analyzer írás közben megmutatja a típusokat, aláhúzza a hibákat, és kiegészíti a kódot. ADHD-hoz ez aranyat ér: a hiba akkor jelenik meg, amikor még a fejedben van, amit írtál, nem öt perccel később a fordításnál.

:::steps Telepítés
- Telepítsd a VS Code-ot a [code.visualstudio.com](https://code.visualstudio.com) oldalról (vagy PowerShellben: `winget install Microsoft.VisualStudioCode`).
- Nyisd meg a VS Code-ot, és bal oldalt kattints a **Bővítmények** ikonra (négy kis négyzet), vagy nyomd meg a `Ctrl+Shift+X` billentyűket.
- Telepítsd a **rust-analyzer** bővítményt (kiadó: *rust-lang*). Ez a legfontosabb.
- Telepítsd az **Error Lens** bővítményt. Ez a hibaüzenetet közvetlenül a hibás sor mellé írja, nem kell a kis piros hullámvonal fölé vinni az egeret.
- Telepítsd az **Even Better TOML** bővítményt (a `Cargo.toml` szerkesztéséhez) és a **CodeLLDB**-t (hibakereséshez, később jól jön).
:::

:::tip Kevesebb zaj, jobb fókusz
A VS Code-ban `Ctrl+K Z` a **Zen mód**: eltűnik minden panel, csak a kód marad. Ugyanezzel a billentyűkombinációval lépsz ki belőle (`Esc` `Esc` is működik). Nehezebb napokon kifejezetten hasznos.
:::

## Az első projekt

Készíts egy mappát a kódjaidnak, például `C:\kod`. Nyiss benne egy terminált (VS Code-ban: `` Ctrl+` ``), és futtasd:

```powershell
cd C:\kod
cargo new szia_rozsda
cd szia_rozsda
code .
```

A `cargo new` létrehozta ezt a szerkezetet:

```text Mappaszerkezet
szia_rozsda/
├── Cargo.toml      ← a projekt leírása (név, verzió, függőségek)
├── .gitignore      ← a target/ mappát nem kell gitbe tenni
└── src/
    └── main.rs     ← itt kezdődik a program
```

Nyisd meg a `Cargo.toml` fájlt:

```toml
[package]
name = "szia_rozsda"
version = "0.1.0"
edition = "2024"

[dependencies]
```

Ez ugyanaz, mint C#-ban a `.csproj`: itt van a név, a verzió, és itt lesznek a függőségek (crate-ek) is. Az `edition` a Rust nyelv „évjárata”. A 2024-es a legújabb.

Most nézd meg a `src/main.rs` fájlt:

```rust
fn main() {
    println!("Hello, world!");
}
```

:::compare
@@ C#
```csharp
static void Main() {
    Console.WriteLine("Hello, world!");
}
```
@@ C++
```cpp
int main() {
    std::cout << "Hello, world!" << std::endl;
}
```
@@ Python
```python
print("Hello, world!")
```
@@ Rust
```rust
fn main() {
    println!("Hello, world!");
}
```
A `fn` jelöli a függvényt. A `println!` végén lévő felkiáltójel azt jelenti, hogy ez egy **makró**, nem sima függvény. Később megnézzük, miért. Egyelőre elég annyit tudni, hogy így kell írni.
:::

## Futtassuk!

```powershell
cargo run
```

Az első futtatás pár másodpercig tart. Ezt kell látnod:

```text
   Compiling szia_rozsda v0.1.0 (C:\kod\szia_rozsda)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.61s
     Running `target\debug\szia_rozsda.exe`
Hello, world!
```

A `cargo run` két dolgot csinált: lefordította a programot (`target\debug\szia_rozsda.exe`), és el is indította.

:::task
Írd át a programot úgy, hogy ezt írja ki:

```text
Szia, Rozsda!
Ez az első Rust programom.
```

Két `println!` sor kell hozzá. **Gépeld be**, ne másold! Figyeld meg, hogy a rust-analyzer már gépelés közben segít.
:::

:::hint
A meglévő `println!` sort írd át, és alá írj egy másodikat ugyanígy. Ne felejtsd el a pontosvesszőt (`;`) a sor végén.
---
Ha piros hullámvonalat látsz, vidd fölé az egeret, vagy nézd meg az Error Lens üzenetét. Gyakori hiba, hogy a szöveg idézőjele lemarad, vagy a „magyar” idézőjelet (`„”`) használod a sima `"` helyett.
:::

:::solution
```rust
fn main() {
    println!("Szia, Rozsda!");
    println!("Ez az első Rust programom.");
}
```
:::

## Három cargo-parancs, amit naponta használsz

| Parancs | Mit csinál | Mikor használd |
|---|---|---|
| `cargo check` | Csak ellenőrzi, hogy lefordulna-e. Nem készít `.exe`-t. | Gyors visszajelzés, nagyon gyors |
| `cargo run` | Fordít és futtat | Ha látni akarod, mit csinál |
| `cargo test` | Lefuttatja a teszteket | Minden leckében, a 01-02-től |

Van még a `cargo build --release`, amely optimalizált, gyors `.exe`-t készít a `target\release` mappába. Ez lassabban fordul, ezért fejlesztés közben a sima `cargo run` a jobb.

- VS Code-ban nyomd meg a `Ctrl+,` billentyűket (Beállítások).
- Keresd meg: **format on save**, és pipáld be.
- Mostantól mentéskor (`Ctrl+S`) a `rustfmt` automatikusan rendbe teszi a kódod formázását. Így soha nem kell azon gondolkodnod, hova kell a szóköz.

:::quiz
Mi a különbség a `cargo check` és a `cargo run` között?
- [ ] Nincs különbség, csak a régi név
- [x] A `check` csak ellenőrzi a kódot, nem készít futtatható fájlt, ezért sokkal gyorsabb
- [ ] A `check` a teszteket futtatja
> A `cargo check` kihagyja a gépi kód generálását, ezért pár tized másodperc alatt megmondja, hogy fordulna-e. Nagyobb projektnél (és a böngészőmotor az lesz) ez óriási különbség.
:::

:::card
K: Mire való a `Cargo.toml`?
V: A projekt leírófájlja: név, verzió, edition, és a függőségek (crate-ek) listája. Mint C#-ban a `.csproj`.
:::

:::card
K: Miért van felkiáltójel a `println!` végén?
V: Mert **makró**, nem függvény. A makró fordítási időben kódot generál; a `println!` így tudja ellenőrizni a formátum-szöveget, és fogadni tetszőleges számú paramétert.
:::
