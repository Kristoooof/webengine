## 3. A lapító: a CSS dönt

A 03-11-es `flatten.rs`-ben két dolog volt beégetve: a `block_kind` táblázat (mi blokk, mi címsor) és a kihagyott elemek listája (`head`, `script`, `style`, `template`). Mostantól mindkettőt a stílus mondja meg:

| Eddig (Rust) | Mostantól (CSS) |
|---|---|
| `matches!(name, "head" \| "script" \| …)` → kihagy | `display: none` → kihagy (a user-agent stíluslapból) |
| `block_kind(name)` → blokk | `display: block` vagy `list-item` → blokk |
| `BlockKind::Heading(1)` → nagy betű | `font-size: 32px` a `Block` stílusában |

Ha egy oldal azt írja, hogy `.rejtett { display: none }`, az is eltűnik. Ha azt, hogy `span { display: block }`, a `span` új blokkot kezd. Pont, mint egy igazi böngészőben.

:::task
Írd át a `flatten.rs`-t:

1. A `Flattener` kapjon egy `styles: &'a StyleMap` mezőt, a `page_from_document` pedig egy második paramétert: `styles: &StyleMap`.
2. A `block_kind` függvény és a kihagyott tagek listája törlődik.
3. A `walk` elem-ágában: kérd le az elem stílusát (ha nincs, `return`). Ha `display: none`, `return`. A `br` marad, ahogy volt. Ha a `display` `Block` vagy `ListItem`: `flush`, a `ListItem`-nél a blokk fajtája `ListItem`, és az aktuális blokk stílusa legyen az elemé. A gyerekek után: `flush`, és **állítsd vissza** a szülő blokk stílusát.
4. A `flush` a kész `Block`-ba tegye bele az aktuális stílust is (`self.current.style.clone()`).
:::

Miért kell visszaállítani? Nézd ezt: `<body><p>kék</p>piros</body>`. A „piros” szöveg a `p` **után** jön, tehát a `body`-hoz tartozik, és a `body` stílusával kell megjelennie. Ha a `p` stílusa ott maradna az aktuális blokkban, a „piros” is kék lenne. Az elmentéshez és a cseréhez a `std::mem::replace` a legtisztább: kicseréli egy változó értékét, és visszaadja a régit.

```rust
let saved = std::mem::replace(&mut self.current.style, style.clone());
// ... a gyerekek bejárása ...
self.current.style = saved;
```

Miért fordul le a `self.flush()`, miközben a `style` még él? A `style` nem a `self`-ből van kölcsönözve, hanem a `StyleMap`-ből, amire a `self.styles` csak egy közös (`&'a`) referencia.
```rust
//! Átmeneti híd: a DOM-ból és a stílusokból a 0.1-es `Page` blokklistája lesz,
//! amíg az 5. modulban el nem készül az igazi layout.

use rozsda_core::dom::{Document, NodeData, NodeId};
use rozsda_core::style::{ComputedStyle, Display, StyleMap};
use rozsda_core::{Block, BlockKind, Page};

// ... a collapse_whitespace változatlan ...

struct Flattener<'a> {
    doc: &'a Document,
    styles: &'a StyleMap,
    page: Page,
    current: Block,
}

impl Flattener<'_> {
    fn flush(&mut self) {
        let lines: Vec<String> = self
            .current
            .text
            .split('\n')
            .map(|l| collapse_whitespace(l).trim().to_string())
            .filter(|l| !l.is_empty())
            .collect();
        if !lines.is_empty() {
            self.page.blocks.push(Block {
                kind: self.current.kind,
                text: lines.join("\n"),
                style: self.current.style.clone(),
            });
        }
        self.current.text.clear();
        self.current.kind = BlockKind::Paragraph;
    }

    fn walk(&mut self, id: NodeId) {
        match &self.doc.node(id).data {
            NodeData::Text(t) => self.current.text.push_str(&collapse_whitespace(t)),
            NodeData::Element(e) => {
                let Some(style) = self.styles.get(id) else {
                    return;
                };
                if style.display == Display::None {
                    return;
                }
                if e.name == "br" {
                    self.current.text.push('\n');
                    return;
                }
                let block = matches!(style.display, Display::Block | Display::ListItem);
                let mut saved = None;
                if block {
                    self.flush();
                    if style.display == Display::ListItem {
                        self.current.kind = BlockKind::ListItem;
                    }
                    saved = Some(std::mem::replace(&mut self.current.style, style.clone()));
                }
                for &child in self.doc.children(id) {
                    self.walk(child);
                }
                if let Some(parent_style) = saved {
                    self.flush();
                    self.current.style = parent_style;
                }
            }
            NodeData::Document => {
                for &child in self.doc.children(id) {
                    self.walk(child);
                }
            }
            NodeData::Doctype(_) | NodeData::Comment(_) => {}
        }
    }
}

pub fn page_from_document(doc: &Document, styles: &StyleMap) -> Page {
    let mut f = Flattener {
        doc,
        styles,
        page: Page {
            title: doc.title(),
            blocks: Vec::new(),
        },
        current: Block {
            kind: BlockKind::Paragraph,
            text: String::new(),
            style: ComputedStyle::default(),
        },
    };
    f.walk(doc.root());
    f.flush();
    f.page
}
```

## 4. A layout: a stílusból rajzolunk

A `layout.rs` `style_for` függvénye (ami a `BlockKind`-ból találta ki a nagyítást és a színt) helyére egy kisebb kerül. A font8x8 betűi 8 pixelesek, tehát a nagyítás a betűméret osztva 8-cal, kerekítve: 16px → 2×, 32px → 4×, 24px → 3×.

```rust
/// A 8×8-as betűk nagyítása a betűméretből: 16px → 2×, 32px → 4×.
pub fn scale_for(style: &ComputedStyle) -> i32 {
    ((style.font_size / GLYPH as f32).round() as i32).max(1)
}
```

Nézd meg: a user-agent stíluslap `h1 { font-size: 2em }`-je pontosan a régi 4× nagyítást adja, a `h2` a 3×-ost, a bekezdés a 2×-est. A Rozsda betűméretei eddig is a CSS szabványos méreteit utánozták, csak most már a CSS-ből jönnek.

:::task

2. A `Style` struct és a `style_for` helyére a fenti `scale_for` jön (`use rozsda_core::style::ComputedStyle;`).
3. A `layout` ciklusában a blokk stílusából: `scale`, `color` (`to_u32()`), `bold` (ha a `font_weight >= 600`), és `bullet`, ha a blokk `ListItem`. A felsorolásjel (`»`) is a szöveg színével rajzolódjon.
4. A `layout_stacks_blocks` tesztben a blokkok stílust kapnak (lásd lent), és jön egy új teszt a nagyításra.

:::solution A layout függvény
```rust
pub fn layout(page: &Page, width: i32, margin: i32) -> (Vec<Line>, i32) {
    let mut lines = Vec::new();
    let mut y = margin;
    for block in &page.blocks {
        let scale = scale_for(&block.style);
        let color = block.style.color.to_u32();
        let bold = block.style.font_weight >= 600;
        let bullet = block.kind == BlockKind::ListItem;
        let indent = if bullet { 3 * GLYPH * scale } else { 0 };
        let char_w = GLYPH * scale;
        let max_chars = ((width - 2 * margin - indent) / char_w).max(1) as usize;
        let line_h = char_w + scale * 4;
        for (i, para) in block.text.split('\n').enumerate() {
            for (j, text) in wrap(para, max_chars).into_iter().enumerate() {
                if bullet && i == 0 && j == 0 {
                    lines.push(Line {
                        x: margin + GLYPH * scale,
                        y,
                        scale,
                        color,
                        bold,
                        text: "»".into(),
                    });
                }
                lines.push(Line {
                    x: margin + indent,
                    y,
                    scale,
                    color,
                    bold,
                    text,
                });
                y += line_h;
            }
        }
        y += line_h / 2;
    }
    (lines, y + margin)
}
```

:::card
K: Mit csinál a `StyleEngine` trait a Rozsdában?
V: Egy DOM-hoz kiszámolja minden elem stílusát (`StyleMap`). A saját (`OwnStyleEngine`) és a 16. modulban a profi (Stylo) motor is ezt valósítja meg, és a `--css=sajat|profi` kapcsoló választ köztük.
:::

:::card
K: Hogyan lesz a `font-size`-ból nagyítás a Rozsda 8×8-as betűinél?
V: `scale = round(font_size / 8)`, legalább 1. Így 16px → 2×, 24px → 3×, 32px → 4×.
:::
