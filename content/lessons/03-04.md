:::goal
A tokenizered beolvassa az attribútumokat mind a négy formájukban (`"…"`, `'…'`, idézőjel nélkül, érték nélkül), kisbetűsíti a nevüket, és a szabály szerint eldobja a duplikátumokat. A lecke végére az `<a href="/x" title='Szia' data-n=5 hidden>` hibátlanul tokenizálódik.
:::

## Az attribútumok négy formája

```html
<input type="text" value='Szia' maxlength=20 disabled>
```

| Forma | Példa | Érték |
|---|---|---|
| Idézőjelben | `type="text"` | `text` |
| Aposztrófban | `value='Szia'` | `Szia` |
| Idézőjel nélkül | `maxlength=20` | `20` (az első szóközig vagy `>`-ig) |
| Érték nélkül | `disabled` | `""` (üres szöveg) |

Az 1. modul tokenizere egyszerűen átugrotta őket. Most minden attribútum bekerül a `StartTag` `attrs` listájába, mert a CSS-nek (`class`, `id`) és később a JS-nek is szüksége lesz rájuk.

## Hét új állapot

```text Ábra
TagName ──szóköz──► BeforeAttributeName ──betű──► AttributeName ──'='──► BeforeAttributeValue
                         ▲                            │                    │  │  │
                         │                       szóköz,'/','>'           '"' '\'' más
                         │                            ▼                    ▼  ▼  ▼
                         │                     AfterAttributeName     DQ  SQ  Unquoted
                         │                                             │  │
                         └────── szóköz ─── AfterAttributeValueQuoted ◄┘──┘
```

A legfontosabb szabályok (a szabvány 13.2.5.32–13.2.5.42 része alapján):

- **BeforeAttributeName**: szóköz → átugorjuk. `/`, `>` vagy EOF → reconsume az **AfterAttributeName**-ben. Minden más → **új attribútum** indul, reconsume az **AttributeName**-ben. (Egy furcsaság: ha `=` jön, az új attribútum neve `=` lesz. Ezt is a szabvány írja elő.)
- **AttributeName**: szóköz, `/`, `>`, EOF → reconsume az AfterAttributeName-ben. `=` → **BeforeAttributeValue**. Minden más → kisbetűsítve a névhez.
- **AfterAttributeName**: szóköz → átugorjuk. `/` → SelfClosingStartTag. `=` → BeforeAttributeValue. `>` → a tag kész. Minden más → új attribútum, reconsume az AttributeName-ben.
- **BeforeAttributeValue**: szóköz → átugorjuk. `"` → **DQ**. `'` → **SQ**. `>` → a tag kész (üres értékkel). Minden más → reconsume az **Unquoted**-ban.
- **DQ** / **SQ**: a záró idézőjel → **AfterAttributeValueQuoted**. Minden más → az értékhez.
- **Unquoted**: szóköz → BeforeAttributeName. `>` → a tag kész. Minden más → az értékhez.
- **AfterAttributeValueQuoted**: szóköz → BeforeAttributeName. `/` → SelfClosingStartTag. `>` → a tag kész. Minden más → parse error („hiányzik a szóköz”), reconsume a BeforeAttributeName-ben.

:::warn A `<img src=x/>` nem önzáró!
Idézőjel nélküli értékben a `/` **az érték része**. A `<img src=x/>` attribútuma `src="x/"`, és a tag nem önzáró. A böngésző ezért egy `x/` nevű képet próbál betölteni! Az **Unquoted** állapotban csak a szóköz és a `>` zárja az értéket. Emiatt jó szokás mindig idézőjelet használni.
:::

## A félkész attribútum

```rust
attrs: Vec<Attribute>,
attr_name: String,
attr_value: String,
```

Két segédfüggvény kezeli az attribútumok elejét és végét:

```rust
fn start_attr(&mut self) {
    self.finish_attr();
    self.attr_name.clear();
    self.attr_value.clear();
}

fn finish_attr(&mut self) {
    if self.attr_name.is_empty() {
        return;
    }
    let name = std::mem::take(&mut self.attr_name);
    let value = std::mem::take(&mut self.attr_value);
    // Duplikált attribútum: parse error, a későbbit eldobjuk.
    if !self.attrs.iter().any(|a| a.name == name) {
        self.attrs.push(Attribute { name, value });
    }
}
```

Egy új attribútum kezdetekor és a tag kibocsátásakor az előző (félkész) attribútum lezárul. A duplikált nevű attribútumok közül **az első nyer**: `<img src=a src=b>` → `src="a"`.

Az `emit_tag` és a `new_tag` is bővül:

```rust
fn new_tag(&mut self, is_end: bool) {
    self.tag_name.clear();
    self.tag_is_end = is_end;
    self.self_closing = false;
    self.attrs.clear();
    self.attr_name.clear();
    self.attr_value.clear();
}

fn emit_tag(&mut self) {
    self.finish_attr();
    let name = std::mem::take(&mut self.tag_name);
    let token = if self.tag_is_end {
        Token::EndTag { name }
    } else {
        let attrs = std::mem::take(&mut self.attrs);
        Token::StartTag { name, attrs, self_closing: self.self_closing }
    };
    self.emit(token);
    self.state = State::Data;
}
```

(A zárótag attribútumait a szabvány szerint eldobjuk: `</p class=x>` → `EndTag { name: "p" }`.)

:::hint
A DQ és az SQ állapot majdnem ugyanaz, csak a záró karakter más. Összevonhatod őket egy ágba a `|` mintával, és a lezáró karaktert a `self.state`-ből számolod ki:
```rust
State::AttributeValueDoubleQuoted | State::AttributeValueSingleQuoted => {
    let quote = if self.state == State::AttributeValueDoubleQuoted { '"' } else { '\'' };
    match c {
        Some(c) if c == quote => self.state = State::AfterAttributeValueQuoted,
        Some(c) => self.attr_value.push(c),
        None => break,
    }
}
```
---
Az `AttributeName`-ben a szóköz, a `/`, a `>` és az EOF ugyanazt csinálja: reconsume, aztán `AfterAttributeName`. A `None` nem illeszthető egy őrfeltételbe a `Some(c)`-vel együtt, ezért ahhoz kell egy külön ág ugyanazzal a törzzsel.
---
A `value = 'x'disabled` esetén: az `x` után az `'` lezárja az értéket (→ AfterAttributeValueQuoted), aztán a `d` „bármi más”, tehát reconsume a BeforeAttributeName-ben. Ott a `d` új attribútumot indít. A szóköz hiánya parse error, de a böngésző ugyanígy olvassa.
:::

:::solution
```rust
State::BeforeAttributeName => match c {
    Some(c) if is_whitespace(c) => {}
    Some('/') | Some('>') | None => {
        self.reconsume();
        self.state = State::AfterAttributeName;
    }
    Some('=') => {
        self.start_attr();
        self.attr_name.push('=');
        self.state = State::AttributeName;
    }
    Some(_) => {
        self.start_attr();
        self.reconsume();
        self.state = State::AttributeName;
    }
},
State::AttributeName => match c {
    Some(c) if is_whitespace(c) || c == '/' || c == '>' => {
        self.reconsume();
        self.state = State::AfterAttributeName;
    }
    None => {
        self.reconsume();
        self.state = State::AfterAttributeName;
    }
    Some('=') => self.state = State::BeforeAttributeValue,
    Some(c) => self.attr_name.push(c.to_ascii_lowercase()),
},
State::AfterAttributeName => match c {
    Some(c) if is_whitespace(c) => {}
    Some('/') => self.state = State::SelfClosingStartTag,
    Some('=') => self.state = State::BeforeAttributeValue,
    Some('>') => self.emit_tag(),
    Some(_) => {
        self.start_attr();
        self.reconsume();
        self.state = State::AttributeName;
    }
    None => break,
},
State::BeforeAttributeValue => match c {
    Some(c) if is_whitespace(c) => {}
    Some('"') => self.state = State::AttributeValueDoubleQuoted,
    Some('\'') => self.state = State::AttributeValueSingleQuoted,
    Some('>') => self.emit_tag(),
    _ => {
        self.reconsume();
        self.state = State::AttributeValueUnquoted;
    }
},
State::AttributeValueDoubleQuoted | State::AttributeValueSingleQuoted => {
    let quote = if self.state == State::AttributeValueDoubleQuoted { '"' } else { '\'' };
    match c {
        Some(c) if c == quote => self.state = State::AfterAttributeValueQuoted,
        Some(c) => self.attr_value.push(c),
        None => break,
    }
}
State::AttributeValueUnquoted => match c {
    Some(c) if is_whitespace(c) => self.state = State::BeforeAttributeName,
    Some('>') => self.emit_tag(),
    Some(c) => self.attr_value.push(c),
    None => break,
},
State::AfterAttributeValueQuoted => match c {
    Some(c) if is_whitespace(c) => self.state = State::BeforeAttributeName,
    Some('/') => self.state = State::SelfClosingStartTag,
    Some('>') => self.emit_tag(),
    Some(_) => {
        self.reconsume();
        self.state = State::BeforeAttributeName;
    }
    None => break,
},
```

:::why Miért nyer az első duplikátum?
Biztonsági okból. Képzeld el, hogy egy oldal a felhasználó nevét beilleszti egy taggé: `<a href="/profil" title="NÉV">`. Ha a támadó a nevébe azt írja, hogy `" href="javascript:...`, akkor a tag így néz ki: `<a href="/profil" title="" href="javascript:...">`. Mivel az első `href` nyer, a támadás ebben a formában nem működik. (Ettől még az ilyen beillesztés veszélyes, és mindig escape-elni kell. Ezt a 17. modulban, a biztonságnál részletesen megnézzük.)
