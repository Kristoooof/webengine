:::goal
Megírod a **kaszkádot**, a CSS névadó algoritmusát (*Cascading* Style Sheets). Egy elemre illeszkedő összes deklaráció közül eldönti, melyik nyer: előbb az eredet és a fontosság, aztán a `style=""` attribútum, aztán a specificitás, végül a sorrend. A lecke végére egy elemhez megkapod a nyertes értékeket, tulajdonságonként.
:::

## Honnan jöhet egy deklaráció?

Egy elemre egyszerre többféle forrásból jöhet stílus:

- **A böngésző stíluslapja** (*user-agent stylesheet*): ettől nagy és félkövér a `h1`, és ettől nem látszik a `<head>`. A 04-11-ben megírjuk a Rozsdáét.
- **Az oldal készítőjének stíluslapjai** (*author*): a `<style>` elemek tartalma.
- **A `style=""` attribútum**: közvetlenül az elemen, pl. `<p style="color: red">`.

(Létezik egy harmadik eredet is, a felhasználói stíluslap, amivel pl. egy gyengénlátó felhasználó mindenhol nagyobb betűt kérhet. Mi most kihagyjuk.)

## A kaszkád négy lépése

Ha több deklaráció is ugyanazt a tulajdonságot állítja, a szabvány (CSS Cascade, 6. fejezet) szerint ez dönt, **ebben a sorrendben**:

| # | Szempont | Ki nyer? |
|---|---|---|
| 1 | **Eredet és fontosság** | lásd a lenti táblázatot |
| 2 | **`style=""` attribútum** | az attribútumban lévő deklaráció legyőzi a stíluslapokét |
| 3 | **Specificitás** | a nagyobb (04-07) |
| 4 | **Sorrend** | a később írt |

Egy szempont csak akkor számít, ha az előzőek mind döntetlenek. Az első lépés szintjei, a gyengétől az erősig:

| Szint | Eredet | Fontosság |
|---|---|---|
| 0 | böngésző | normál |
| 1 | oldal | normál |
| 2 | oldal | `!important` |
| 3 | böngésző | `!important` |

Furcsa, hogy a böngésző fontos deklarációi a legerősebbek? Pont ez a lényeg: amit a böngésző (vagy a felhasználó) **fontosnak** jelöl, azt egy weboldal se írhassa felül. A böngésző ezt például akadálymentesítési beállításokra használja.

## A trükk: rendezés, aztán felülírás

Hogyan valósítsuk meg ezt egyszerűen? Minden illeszkedő deklarációhoz készítünk egy **kulcsot**, ami a négy szempontot tartalmazza:

```rust
/// Sorbarendezési kulcs: (eredet és fontosság, inline-e, specificitás, sorrend).
type Key = (u8, bool, Specificity, usize);
```

A tuple-ök balról jobbra hasonlítanak, mint a specificitás. A `bool`-nál a `false < true`, tehát az inline deklaráció a nagyobb. Ezután:

1. **Rendezd** a deklarációkat a kulcsuk szerint, növekvő sorrendbe.
2. Menj végig rajtuk, és mindegyiket írd be egy `HashMap`-be a tulajdonság neve alá.

Mivel a gyengébbek jönnek előbb, az erősebbek **felülírják** őket, és a végén minden tulajdonságnál a nyertes marad. Egy rendezés és egy ciklus, és kész a kaszkád!

A `type Key = …` egy **típus-alias**: nem új típus, csak egy rövidebb név egy hosszú típusra. A fordító szemében a `Key` és a `(u8, bool, Specificity, usize)` ugyanaz.

## Apróságok, amik számítanak

**Szelektor-lista.** A `h1, #fo { … }` szabálynál a specificitás annak a szelektornak a pontszáma, amelyik **illik** az elemre (ha több is illik, a legnagyobbé).

**Érvénytelen érték.** A `p { color: red } p { color: 12px }` esetén a szöveg **piros** lesz. A `color: 12px` értelmetlen, és a szabvány szerint egy érvénytelen deklaráció olyan, mintha ott se lenne. Ezért a felülírás előtt ellenőrizzük, hogy az érték értelmes-e az adott tulajdonsághoz. Egyelőre öt tulajdonságot ismerünk:

| Tulajdonság | Elfogadott értékek |
|---|---|
| `display` | `block`, `inline`, `list-item`, `none` |
| `color`, `background-color` | szín |
| `font-size` | hossz, százalék, `small`…`xx-large`, `larger`, `smaller` |
| `font-weight` | `normal`, `bold`, `bolder`, `lighter`, 1–1000 közötti szám |

Ezek mellett mindegyik elfogadja az `inherit` és az `initial` kulcsszót (a következő leckében kapnak értelmet). Minden mást eldobunk.

**Rövidítés.** A `background: #fdf6e3` nagyon gyakori. A `background` egy **rövidítő tulajdonság** (*shorthand*), ami egyszerre több dolgot állít (szín, kép, ismétlés…). Mi egyelőre csak a színt ismerjük belőle: a `background` nevet `background-color`-ra fordítjuk.

```rust
//! A kaszkád: az elemre illeszkedő deklarációk közül eldönti, melyik nyer.

use crate::parser::{Declaration, Stylesheet, parse_declarations};
use crate::selector::{Specificity, matches};
use crate::tokenizer::tokenize;
use crate::value::{Value, parse_value};
use rozsda_core::dom::{Document, NodeId};
use std::collections::HashMap;

/// Honnan jön egy stíluslap?
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Origin {
    /// A böngésző beépített stíluslapja
    UserAgent,
    /// Az oldal készítőjéé (`<style>`, `style=""`)
    Author,
}

/// A kaszkád első szempontja: eredet és fontosság. A nagyobb nyer.
pub fn precedence(origin: Origin, important: bool) -> u8 {
    match (origin, important) {
        (Origin::UserAgent, false) => 0,
        (Origin::Author, false) => 1,
        (Origin::Author, true) => 2,
        (Origin::UserAgent, true) => 3,
    }
}

/// Csak az általunk ismert tulajdonságokat és hozzájuk illő értékeket engedjük át.
pub fn accepts(name: &str, value: &Value) -> bool {
    if let Value::Keyword(k) = value
        && (k == "inherit" || k == "initial")
    {
        return true;
    }
    match (name, value) {
        ("color" | "background-color", Value::Color(_)) => true,
        ("display", Value::Keyword(k)) => {
            matches!(k.as_str(), "block" | "inline" | "list-item" | "none")
        }
        ("font-size", Value::Length(..) | Value::Percentage(_)) => true,
        ("font-size", Value::Keyword(k)) => matches!(
            k.as_str(),
            "xx-small"
                | "x-small"
                | "small"
                | "medium"
                | "large"
                | "x-large"
                | "xx-large"
                | "larger"
                | "smaller"
        ),
        ("font-weight", Value::Keyword(k)) => {
            matches!(k.as_str(), "normal" | "bold" | "bolder" | "lighter")
        }
        ("font-weight", Value::Number(n)) => (1.0..=1000.0).contains(n),
        _ => false,
    }
}

/// A rövidítések közül egyelőre csak ennyi: `background: <szín>` = `background-color: <szín>`.
fn longhand(name: &str) -> &str {
    if name == "background" {
        "background-color"
    } else {
        name
    }
}

/// Sorbarendezési kulcs: (eredet és fontosság, inline-e, specificitás, sorrend).
type Key = (u8, bool, Specificity, usize);

pub fn cascade(
    doc: &Document,
    id: NodeId,
    sheets: &[(Origin, &Stylesheet)],
) -> HashMap<String, Value> {
    let inline: Vec<Declaration> = doc
        .element(id)
        .and_then(|e| e.attr("style"))
        .map(|style| parse_declarations(&tokenize(style)))
        .unwrap_or_default();

    let mut found: Vec<(Key, &Declaration)> = Vec::new();
    let mut order = 0;
    for (origin, sheet) in sheets {
        for rule in &sheet.rules {
            let best = rule
                .selectors
                .iter()
                .filter(|s| matches(doc, id, s))
                .map(|s| s.specificity())
                .max();
            let Some(specificity) = best else { continue };
            for decl in &rule.declarations {
                let level = precedence(*origin, decl.important);
                found.push(((level, false, specificity, order), decl));
                order += 1;
            }
        }
    }
    for decl in &inline {
        let level = precedence(Origin::Author, decl.important);
        found.push(((level, true, Specificity::default(), order), decl));
        order += 1;
    }

    found.sort_by_key(|(key, _)| *key);
    let mut values = HashMap::new();
    for (_, decl) in found {
        let name = longhand(&decl.name);
        if let Some(value) = parse_value(&decl.value)
            && accepts(name, &value)
        {
            values.insert(name.to_string(), value);
        }
    }
    values
}
```

:::why Miért nem mindenhol `!important`?
Mert háborúhoz vezet. Ha valami nem úgy néz ki, ahogy szeretnéd, csábító odaírni, hogy `!important`, és működik. Aztán valaki más (vagy te, fél év múlva) felül akarja írni, és ő is `!important`-ot ír, de nagyobb specificitással. A végén minden fontos, vagyis semmi sem. A CSS 2022 óta egy jobb eszközt is ad erre, a **kaszkád-rétegeket** (`@layer`): a fejlesztő maga dönti el, melyik stíluscsoport erősebb a másiknál. A kaszkádban ez egy újabb lépés az eredet után, és pontosan ugyanígy egy újabb elem lenne a kulcsban.

```rust
fn winner(decls: &[Decl]) -> Option<&'static str> {
    let mut best: Option<(u8, (u32, u32, u32), &'static str)> = None;
    for d in decls {
        let level = match (d.origin, d.important) {
            (Origin::UserAgent, false) => 0,

            (Origin::Author, true) => 2,
            (Origin::UserAgent, true) => 3,
```
