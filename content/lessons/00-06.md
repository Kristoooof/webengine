A lényeg a középső doboz, a **rozsda-core**. Ez nem *csinál* semmit, csak **leírja**, mit kell tudnia egy HTML-parsernek, egy layout-motornak és így tovább. A saját és a profi implementáció is ezt a leírást követi, ezért a böngésző számára mindegy, melyiket kapja.

## A kapcsoló működése, előzetesben

A Rustban az ilyen „leírást” **traitnek** hívják. Ez nagyon hasonlít a C#-os `interface`-re. Ezt a kódot most **még nem kell értened, se begépelned**, csak nézd meg, mi felé tartunk. Az 1. modul végére minden része érthető lesz.

```rust
// rozsda-core: a szerződés
pub trait HtmlParser {
    fn name(&self) -> &'static str;
    fn parse(&self, source: &str) -> Document;
}

// rozsda-html: a te implementációd
pub struct OwnHtmlParser;
impl HtmlParser for OwnHtmlParser {
    fn name(&self) -> &'static str { "Rozsda (saját)" }
    fn parse(&self, source: &str) -> Document { /* a te tokenizered + fa-építőd */ }
}

// rozsda-pro: a profi, egy "adapterrel" a mi Document típusunkra
pub struct Html5everParser;
impl HtmlParser for Html5everParser {
    fn name(&self) -> &'static str { "html5ever (Servo)" }
    fn parse(&self, source: &str) -> Document { /* html5ever → átalakítás Document-té */ }
}

// rozsda-browser: a kapcsoló
let html: Box<dyn HtmlParser> = if settings.own_html {
    Box::new(OwnHtmlParser)
} else {
    Box::new(Html5everParser)
};
```

:::compare
@@ C#
```csharp
interface IHtmlParser { Document Parse(string source); }
class OwnHtmlParser : IHtmlParser { ... }
IHtmlParser html = settings.OwnHtml ? new OwnHtmlParser() : new Html5everParser();
```
Ugyanaz az ötlet: interfész, két implementáció, futásidőben választunk.
@@ Rust
```rust
trait HtmlParser { fn parse(&self, source: &str) -> Document; }
struct OwnHtmlParser;
impl HtmlParser for OwnHtmlParser { ... }
let html: Box<dyn HtmlParser> = ...;
```
A `Box<dyn HtmlParser>` jelentése: „valami, ami megvalósítja a `HtmlParser` traitet, és a heapen van”. Pont úgy, mint C#-ban egy interfész típusú változó.
:::

:::note Az adapter, és egy őszinte figyelmeztetés
A profi crate-ek a saját adattípusaikkal dolgoznak (a html5ever például a saját DOM-jával). Hogy a kapcsoló működjön, egy **adapter** átalakítja az eredményüket a mi közös típusainkra. A legtöbb alrendszernél ez egyszerű. A Stylónál (a Firefox CSS-motorjánál) viszont komolyabb munka, mert az a DOM-ot is a saját elvárásai szerint akarja látni. Ezt a 16. modulban részletesen megnézzük. Előre szólok, hogy ne érjen meglepetésként.
:::

## Miért „nulláról” először?

Mert csak akkor érted igazán, mit csinál a html5ever, ha te magad is megírtál egy tokenizert. És mert a saját változatod **olvasható**: 300 sor, nem 30 000. Amikor a 16. modulban bekapcsolod a profit, és hirtelen működik egy oldal, ami addig szét volt esve, pontosan tudni fogod, *miért*.
