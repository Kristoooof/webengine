## Nincs null

A null-referenciát a feltalálója „milliárd dolláros hibának” nevezte. Rustban nincs. Ahol egy érték **hiányozhat**, ott a típus maga mondja meg, hogy `Option`:

```rust
enum Option<T> {
    Some(T),
    None,
}
```

Emlékszel a 01-03-as lecke bónuszára, ahol `-1` jelezte volna, hogy nincs találat? Így néz ki rendesen:

```rust
fn first_tag_position(s: &str) -> Option<usize> {
    for (i, c) in s.char_indices() {
        if c == '<' {
            return Some(i);
        }
    }
    None
}
```

A hívónak **muszáj** foglalkoznia a `None` esettel, mert egy `Option<usize>`-t nem lehet `usize`-ként használni:

```rust
match first_tag_position("szöveg <p>") {
    Some(i) => println!("az első tag a(z) {i}. bájtnál kezdődik"),
    None => println!("nincs tag"),
}
```

### Hasznos Option-metódusok

```rust
let pos = first_tag_position(s);

pos.is_some();          // van-e érték
pos.unwrap_or(0);       // az érték, vagy ha nincs, 0
pos.map(|i| i + 1);     // ha van, átalakítja: Some(i) → Some(i + 1)
pos.unwrap();           // az érték, vagy PÁNIK, ha None (óvatosan!)
pos.expect("kell tag"); // mint az unwrap, de saját üzenettel pánikol
```

A standard könyvtárban rengeteg függvény ad vissza `Option`-t. Ilyen például a `str::find`:

```rust
"ab<p>".find('<')       // Some(2)
"nincs".find('<')       // None
```

## Result: ha valami elbukhat

```rust
enum Result<T, E> {
    Ok(T),      // sikerült, itt az eredmény
    Err(E),     // nem sikerült, itt a hiba
}
```

Rustban **nincsenek kivételek** (exceptionök). Ha egy függvény elbukhat, ezt a visszatérési típusában jelzi. A hiba típusa bármi lehet, de a legjobb egy **saját enum**, ami felsorolja, mi romolhat el:

```rust
#[derive(Debug, PartialEq)]
enum TagError {
    Empty,
    MissingOpen,
    MissingClose,
    InvalidName(String),
}
```

:::compare
@@ C#
```csharp
Tag ParseTag(string src) {
    if (src == "") throw new ArgumentException("üres");
    ...
}
// A hívó vagy elkapja, vagy nem. A fordító nem szól.
```
@@ Rust
```rust
fn parse_tag(src: &str) -> Result<Tag, TagError> {
    if src.is_empty() { return Err(TagError::Empty); }
    ...
}
// A típusból látszik, hogy elbukhat, és a hívónak kezelnie KELL.
```
@@ Python
```python
def parse_tag(src: str) -> Tag:
    if not src: raise ValueError("üres")
```
Pythonban a dokumentációból (vagy a futásidejű hibából) derül ki, mit dobhat a függvény. Rustban a típusból.
:::

## A ? operátor: a hiba továbbadása

Ha egy függvényen belül több, elbukható dolgot hívsz meg, minden hívás után `match`-elni fárasztó. A `?` ezt intézi el:

```rust
fn parse_two(a: &str, b: &str) -> Result<(Tag, Tag), TagError> {
    let first = parse_tag(a)?;    // ha Err, AZONNAL visszatér vele
    let second = parse_tag(b)?;   // ha Ok, kicsomagolja az értéket
    Ok((first, second))
}
```

A `?` jelentése: *„ha ez `Err`, add vissza a hívónak; ha `Ok`, add ide az értéket”*. **`Option`-nel is működik**, ha a függvényed is `Option`-t ad vissza:

```rust
fn find_tag(s: &str) -> Option<(usize, usize)> {
    let start = s.find('<')?;           // ha nincs '<', None
    let len = s[start..].find('>')?;    // ha nincs '>', None
    Some((start, start + len + 1))
}
```

A `(usize, usize)` egy **tuple**: két érték egy csomagban. Az elemeit `.0`-val és `.1`-gyel éred el, vagy szétszedheted így: `let (a, b) = pair;`.

:::warn unwrap: prototípusban oké, kész kódban kerüld
Az `unwrap()` azt mondja: „biztos vagyok benne, hogy itt van érték, és ha nincs, omoljon össze a program”. Teszteknél és gyors kísérletnél rendben van. A böngészőben viszont egy rossz weboldal **soha** nem döntheti be a programot. Ott mindig kezeld a hibát. Ha mégis `unwrap`-ot írsz, kérdezd meg magadtól: „mi történik, ha egy rosszindulatú oldal pont ezt a hibát idézi elő?”
:::

Az első három szabály egyszerű `if ... { return Err(...); }` sor. Használd az `is_empty()`, `starts_with('<')` és `ends_with('>')` metódusokat.

A név első karakterét a `name.chars().next()` adja, ami **`Option<char>`** (üres névnél `None`). Ezt `match`-csel érdemes kezelni, és egy őrfeltétel (guard) pont jól jön:
```rust
match name.chars().next() {
    Some(c) if c.is_ascii_alphabetic() => Ok(Tag::parse(src)),
    _ => Err(TagError::InvalidName(name.to_string())),
}
```
---
Miért `Some(7)` az „árvíz<p>” eredménye, és miért nem 5? Mert az á és az í 2-2 bájtos, és a `char_indices` bájtindexet ad.

:::solution
```rust
fn first_tag_position(s: &str) -> Option<usize> {
    for (i, c) in s.char_indices() {
        if c == '<' {
            return Some(i);
        }
    }
    None
}

fn find_tag(s: &str) -> Option<(usize, usize)> {
    let start = s.find('<')?;
    let len = s[start..].find('>')?;
    Some((start, start + len + 1))
}

#[derive(Debug, PartialEq)]
enum TagError {
    Empty,
    MissingOpen,
    MissingClose,
    InvalidName(String),
}

fn parse_tag(src: &str) -> Result<Tag, TagError> {
    if src.is_empty() {
        return Err(TagError::Empty);
    }
    if !src.starts_with('<') {
        return Err(TagError::MissingOpen);
    }
    if !src.ends_with('>') {
        return Err(TagError::MissingClose);
    }
    let name = tag_name(src);
    match name.chars().next() {
        Some(c) if c.is_ascii_alphabetic() => Ok(Tag::parse(src)),
        _ => Err(TagError::InvalidName(name.to_string())),
    }
}

fn parse_two(a: &str, b: &str) -> Result<(Tag, Tag), TagError> {
    let first = parse_tag(a)?;
    let second = parse_tag(b)?;
    Ok((first, second))
}
```
:::

:::why Panic vagy Result?
**Panic** akkor, ha egy *programhiba* történt, ami „nem fordulhat elő” (pl. egy belső invariáns sérült). Ilyenkor jobb megállni, mint rossz adattal folytatni. **Result** akkor, ha a hiba *várható*: rossz bemenet, hiányzó fájl, megszakadt hálózat. A böngésző szinte minden bemenete a „várható hiba” kategória, hiszen a weboldalakat nem te írod. Ezért a Rozsda parserei Resultot (vagy hibatűrő viselkedést) használnak, nem panicot.
:::

:::card
K: Mi a különbség az `Option` és a `Result` között?
V: Az `Option<T>`: lehet, hogy van érték (`Some`), lehet, hogy nincs (`None`). A `Result<T, E>`: a művelet sikerült (`Ok`) vagy elbukott, és megmondja, miért (`Err`).
:::

:::card
K: Mit csinál az `unwrap()`, és mikor kerüld?
V: Kiveszi az értéket, vagy pánikol, ha `None`/`Err`. Kész kódban kerüld, főleg külső bemenetnél (weboldal, fájl, hálózat).
:::

:::card
K: Mire való a `?` operátor?
V: A hiba (`Err`/`None`) automatikus továbbadására a hívónak. Ha nincs hiba, kicsomagolja az értéket.
