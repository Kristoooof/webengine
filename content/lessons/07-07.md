## Egy betű, két glif

A 07-03-ban az `outline` `None`-t adott, ha a glif kontúrjainak száma negatív. Most nézzük meg, mi van ott! Az `ő` glifje (275) mindössze 24 bájt:

```text Ábra
ff ff                 kontúrok száma: −1 → összetett glif
00 71 ff e3 04 75 06 66   befoglaló téglalap

10 27                 jelzők: 0x1027 (ARG_WORDS, ARGS_ARE_XY, MORE_COMPONENTS, …)
02 9f                 glif: 671 (a „˝” ékezet)
00 a0 00 00           eltolás: (160, 0), két i16

12 06                 jelzők: 0x1206 (ARGS_ARE_XY, nincs több elem)
00 52                 glif: 82 (az „o”)
00 00                 eltolás: (0, 0), két i8
```

Az `ő` tehát egy `o` és egy kettős ékezet, 160 egységgel jobbra tolva. Az `á` ugyanígy egy `a` (68) és egy `´` (118), az utóbbi 82 egységgel jobbra. Ez sok helyet spórol: a DejaVu Sansban több száz ékezetes betű van, és mindegyik pár bájt.

Egy **összetevő** (component) felépítése:

| Mező | Típus | Mikor |
|---|---|---|
| jelzők | `u16` | mindig |
| glif | `u16` | mindig |
| két szám | 2 × `i16` vagy 2 × `i8` | `ARG_WORDS` (0x01) szerint |
| nagyítás | 1, 2 vagy 4 × `F2Dot14` | `HAS_SCALE` (0x08), `XY_SCALE` (0x40), `TWO_BY_TWO` (0x80) |

A két szám általában **eltolás** (`ARGS_ARE_XY`, 0x02). Ha ez a bit nincs bekapcsolva, a két szám pont-sorszám: „tedd úgy, hogy a te 5. pontod az én 3. pontomra essen”. Ez ritka, mi nem toljuk el ilyenkor. Ha a `MORE_COMPONENTS` (0x20) be van kapcsolva, újabb összetevő jön.

A nagyítás egy 2×2-es **mátrix** (`a`, `b`, `c`, `d`), ami egy pontot így alakít át:

```text Képlet
x' = a·x + c·y + dx
y' = b·x + d·y + dy
```

Az egyszerű nagyításnál `a = d = s`, `b = c = 0`. Tükrözés (pl. egy `‚` a `'`-ből) vagy elforgatás is leírható vele. Az `F2Dot14` (07-01) egy 16 bites fixpontos szám: 16384 = 1,0.

Egy összetevő maga is lehet összetett. Egy hibás (vagy rosszindulatú) fontban egy glif akár saját magára is hivatkozhat, és a rekurzió végtelen lenne. Ezért egy **mélységkorlát** kell: 8 szintnél mélyebbre nem megyünk.

:::solution
```rust
// Az összetett glifek jelzőbitjei
const ARG_WORDS: u16 = 0x0001;
const ARGS_ARE_XY: u16 = 0x0002;
const HAS_SCALE: u16 = 0x0008;
const MORE_COMPONENTS: u16 = 0x0020;
const XY_SCALE: u16 = 0x0040;
const TWO_BY_TWO: u16 = 0x0080;

/// Ennél mélyebben egymásba ágyazott összetett glifet nem követünk (egy rossz fájl végtelen ciklust okozhatna).
const MAX_DEPTH: u8 = 8;
```

```rust
    /// Egy glif kontúrjai font-egységben. Üres glifnél üres a lista.
    pub fn outline(&self, glyph: u16) -> Option<Vec<Contour>> {
        self.outline_at_depth(glyph, 0)
    }

    fn outline_at_depth(&self, glyph: u16, depth: u8) -> Option<Vec<Contour>> {
        let data = self.glyph_data(glyph)?;
        if data.is_empty() {
            return Some(Vec::new());
        }
        let num_contours = Reader::new(data).i16()?;
        if num_contours >= 0 {
            parse_simple(data, num_contours as usize)
        } else {
            self.parse_composite(data, depth)
        }
    }

    /// Összetett glif: más glifek eltolva (és ritkán nagyítva). Az `á` egy `a` és egy `´`.
    fn parse_composite(&self, data: &[u8], depth: u8) -> Option<Vec<Contour>> {
        if depth >= MAX_DEPTH {
            return None;
        }
        let mut r = Reader::at(data, 10);
        let mut contours = Vec::new();
        loop {
            let flags = r.u16()?;
            let component = r.u16()?;
            let (dx, dy) = if flags & ARG_WORDS != 0 {
                (r.i16()? as f32, r.i16()? as f32)
            } else {
                (r.i8()? as f32, r.i8()? as f32)
            };
            // Az átalakítás mátrixa: x' = a·x + c·y + dx, y' = b·x + d·y + dy
            let (a, b, c, d) = if flags & HAS_SCALE != 0 {
                let s = r.f2dot14()?;
                (s, 0.0, 0.0, s)
            } else if flags & XY_SCALE != 0 {
                (r.f2dot14()?, 0.0, 0.0, r.f2dot14()?)
            } else if flags & TWO_BY_TWO != 0 {
                (r.f2dot14()?, r.f2dot14()?, r.f2dot14()?, r.f2dot14()?)
            } else {
                (1.0, 0.0, 0.0, 1.0)
            };
            // Ha a két szám nem eltolás, hanem pontsorszám (pontillesztés), nem toljuk el: ritka.
            let (dx, dy) = if flags & ARGS_ARE_XY != 0 {
                (dx, dy)
            } else {
                (0.0, 0.0)
            };
            for contour in self.outline_at_depth(component, depth + 1)? {
                let moved = contour
                    .into_iter()
                    .map(|p| Point {
                        x: a * p.x + c * p.y + dx,
                        y: b * p.x + d * p.y + dy,
                        on_curve: p.on_curve,
                    })
                    .collect();
                contours.push(moved);
            }
            if flags & MORE_COMPONENTS == 0 {
                break;
            }
        }
        Some(contours)
    }
```
:::

A `(r.f2dot14()?, 0.0, 0.0, r.f2dot14()?)` sorban a két olvasás **balról jobbra** fut le: a Rust garantálja, hogy egy tuple elemei sorrendben értékelődnek ki. Az első szám az x, a második az y nagyítása, ahogy a fájlban is.

## Az ékezetes betűk a szövegben: UTF-8

Most, hogy a font tudja az ékezeteket, nézzük meg a másik oldalt: hogyan érkeznek a karakterek? Az 1. modulban (01-01) már szó volt róla, hogy a hálózatról **bájtok** jönnek, és a böngészőnek kell karakterekké alakítania őket. A web szinte kizárólag **UTF-8**-at használ, és a Rust `String`-je is UTF-8.

A UTF-8 egy karaktert 1–4 bájton tárol. Az első bájt elejéből látszik, hány bájtos:

| Kódpont | Bájtok | Bitminta |
|---|---|---|
| U+0000 – U+007F | 1 | `0xxxxxxx` |
| U+0080 – U+07FF | 2 | `110xxxxx 10xxxxxx` |
| U+0800 – U+FFFF | 3 | `1110xxxx 10xxxxxx 10xxxxxx` |
| U+10000 – U+10FFFF | 4 | `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` |

Az `x`-ek helyére a kódpont bitjei kerülnek, balról jobbra. Az `ő` kódpontja U+0151:

```text Ábra
U+0151 = 001 0101 0001 (11 bit)
          ┌─┴──┐┌─┴───┐
         00101  010001
   110 + 00101 = 1100 0101 = C5
    10 + 010001 = 1001 0001 = 91          "ő" = [0xC5, 0x91]
```

Három tulajdonsága miatt lett a UTF-8 a web nyelve:

- Az angol szöveg (ASCII) **változatlan**: minden 128 alatti karakter egy bájt, ugyanaz, mint régen.
- **Önszinkronizáló**: a folytató bájtok mindig `10`-val kezdődnek, ezért egy szöveg közepéből is megtalálható a következő karakter eleje.
- Nincs **bájtsorrend**-gond: bájtonként olvassuk, nem 16 bites egységekben, mint az UTF-16-ot.

A magyar szövegben az ékezetes betűk 2 bájtosak. Ezért a `len()` (bájtok száma) és a karakterek száma eltér:

```rust test
    // 07-07
    #[test]
    fn hungarian_text() {
        let text = "Árvíztűrő tükörfúrógép";
        assert_eq!(text.chars().count(), 22);
        assert_eq!(text.len(), 31, "az ékezetes betűk 2 bájtosak");
        let font = Font::parse(DEJAVU_SANS).unwrap();
        assert!(
            text.chars().all(|c| font.glyph_index(c) != 0),
            "minden betű megvan"
        );
        assert!(
            text.chars()
                .all(|c| font.outline(font.glyph_index(c)).is_some())
        );
    }
```

Ezt a tesztet a `cmap.rs` tesztjei közé tedd. Az utolsó sor ellenőrzi, hogy minden betű körvonala kiolvasható: a 07-03 után az ékezetes betűknél ez még `None` lett volna.

:::compare Szövegek máshol
@@ C#
A `string` UTF-16, és a `Length` a 16 bites egységek száma. Az `ő` egy egység, de egy emoji kettő (surrogate pair). A bájtokká alakítás `Encoding.UTF8.GetBytes(s)`.
@@ C++
A `std::string` csak bájtokat tárol, a kódolás a programozó dolga. Egy `s.size()` a bájtok száma, és egy `s[3]` könnyen egy karakter közepére mutat.
@@ Python
A `str` kódpontok sorozata: a `len("ő")` 1. A bájtokhoz kódolni kell: `"ő".encode("utf-8")` → `b'\xc5\x91'`.
@@ Rust
A `String` és a `&str` **mindig érvényes** UTF-8, ezt a típus garantálja. A `len()` bájtokat ad, a `chars()` kódpontokat. Egy `&s[0..1]` pánikol, ha karakter közepére vágna.
@@ Érettségi
A karakterkódolás (ASCII, Latin-2, UTF-8) érettségi téma: egy fájl ugyanazon bájtjai más kódolással más szöveget adnak. Ha valaha láttál „Ã¡”-t „á” helyett, az egy UTF-8-as szöveg volt Latin-1-ként olvasva.
:::

:::warn Egy karakter nem mindig egy betű
A „betű, amit a felhasználó lát” (*grapheme cluster*) több kódpontból is állhat. Az `á` írható egyetlen kódponttal (U+00E1), de egy `a`-val és egy **kombináló** ékezettel is (U+0061 U+0301). A kettő ugyanúgy néz ki, de a `chars().count()` az elsőnél 1, a másodiknál 2. A zászló-emojik, a bőrszín-módosítók és sok indiai írás is ilyen. A Rozsda egyelőre kódpontonként rajzol. A kombináló ékezeteket egy profi szövegmotor (**shaping**) a megfelelő helyre teszi: ez a 16. modul.
:::

@@ feladat
Írj egy UTF-8 dekódolót! A bájtokból add vissza a kódpontokat (`u32`). Az első bájt mondja meg a hosszt:

- `0xxxxxxx`: 1 bájt
- `110xxxxx`: 2 bájt
- `1110xxxx`: 3 bájt
- `11110xxx`: 4 bájt

A folytató bájtok mindig `10xxxxxx` alakúak, és mindegyik 6 bitet ad. Ha egy első bájt egyik mintára sem illik, egy folytató bájt rossz, vagy a szöveg egy karakter közepén ér véget, adj vissza `None`-t. (A túl hosszú kódolásokkal és a többi finomsággal most nem kell foglalkozni.)

@@ megoldás
```rust
fn decode_utf8(bytes: &[u8]) -> Option<Vec<u32>> {
    let mut out = Vec::with_capacity(bytes.len());
    let mut i = 0;
    while i < bytes.len() {
        let b = bytes[i];
        let (len, first) = match b {
            0x00..=0x7F => (1, b as u32),
            0xC0..=0xDF => (2, (b & 0x1F) as u32),
            0xE0..=0xEF => (3, (b & 0x0F) as u32),
            0xF0..=0xF7 => (4, (b & 0x07) as u32),
            _ => return None,
        };
        let mut code = first;
        for k in 1..len {
            let c = *bytes.get(i + k)?;
            if c & 0xC0 != 0x80 {
                return None;
            }
            code = (code << 6) | (c & 0x3F) as u32;
        }
        out.push(code);
        i += len;
    }
    Some(out)
}
```
