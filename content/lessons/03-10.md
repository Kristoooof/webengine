:::goal
A fa-építőd megtanulja kezelni a valódi weboldalak hibáit. A `<p>` lezárja az előző `<p>`-t, a `<li>` az előző `<li>`-t, egy blokkelem lezárja a nyitott bekezdést, a kóbor zárótagok pedig nem rontják el a fát. Mindez a szabvány szerint, a **hatókör** (scope) fogalmával.
:::

## A HTML, ahogy az emberek írják

A web nagy részét nem fordító ellenőrzi. Ilyesmiket fogsz látni:

```html
<p>Első bekezdés
<p>Második bekezdés
<ul>
  <li>egy
  <li>kettő
</ul>
<div>Valami</span> elírva</p>
```

Az előző lecke fa-építője ebből egy egymásba ágyazott szörnyet csinálna (a második `<p>` az első **belsejébe** kerülne). A szabvány viszont pontosan megmondja, mi a helyes fa, és a böngészők ezt építik:

```text Várt DOM
| <html>
|   <head>
|   <body>
|     <p>
|       "Első bekezdés\n"
|     <p>
|       "Második bekezdés\n"
|     <ul>
|       <li> "egy"
|       <li> "kettő"
|     <div> ...
```

## 1. eszköz: implicit lezárás

Bizonyos kezdőtagok **lezárják** a nyitott elemeket:

| Kezdőtag | Mit zár le |
|---|---|
| `p`, `div`, `ul`, `ol`, `h1`–`h6`, `section`, `header`, … (26 elem) | egy nyitott `<p>`-t, ha az **hatókörben** van |
| `h1`–`h6` | ha a verem tetején épp egy címsor van, azt is (címsor nem lehet címsorban) |
| `li` | egy nyitott `<li>`-t (lista-hatókörben) |
| `dd`, `dt` | egy nyitott `<dd>`-t vagy `<dt>`-t |

## 2. eszköz: a hatókör (scope)

Mit jelent az, hogy egy elem „hatókörben van”? A szabvány definíciója: menj végig a vermen **felülről lefelé**. Ha megtalálod a keresett elemet, hatókörben van. Ha előbb egy **határoló elembe** ütközöl, nincs hatókörben.

| Hatókör | Határoló elemek |
|---|---|
| alap | `html`, `table`, `td`, `th`, `caption`, `marquee`, `object`, `template` |
| gomb (*button scope*) | az alap + `button` |
| lista (*list item scope*) | az alap + `ol`, `ul` |

Miért kell ez? Mert egy táblázatcellában (`<td>`) lévő `<p>` **nem** zárhatja le a táblázat **előtt** nyitott `<p>`-t. A cella egy új „világ”. Hasonlóan: a beágyazott listában lévő `<li>` nem zárhatja le a külső lista elemét.

```text Ábra
verem (alul → felül):  html, body, p, table, tr, td
in_scope("p")?         td → tr → table = határoló! → NINCS hatókörben
```

## 3. eszköz: implicit zárótagok

Mielőtt egy elemet lezárunk, a fölötte nyitva maradt `dd`, `dt`, `li`, `option`, `optgroup` és `p` elemeket csendben lezárjuk. Ezeknek a zárótagja elhagyható. A szabvány neve erre: *generate implied end tags*.

## 4. eszköz: a zárótagok három fajtája

| Zárótag | Szabály |
|---|---|
| `</p>` | Ha nincs `p` hatókörben, a szabvány szerint létre kell hozni egy **üres** `<p>`-t, és lezárni. (Igen, a `</p>` magában egy üres bekezdést hoz létre!) |
| `</br>` | Úgy kezeljük, mint egy `<br>`-t (régi böngészők hibája, ami szabvány lett) |
| `</h1>`–`</h6>` | Bármelyik nyitott címsort lezárja (a `</h2>` lezárhat egy `<h1>`-et) |
| blokk (`div`, `ul`, `li`, `section`, …) | Ha hatókörben van: implicit zárótagok, aztán pop a nevéig. Ha nincs: figyelmen kívül hagyjuk. |
| minden más (`b`, `span`, `a`, …) | Felülről lefelé keressük a veremben. Ha megvan: lezárjuk. Ha előbb egy **különleges** elembe (`div`, `p`, `li`, `table`…) ütközünk: figyelmen kívül hagyjuk. Egy kóbor `</span>` így nem tud „átnyúlni” egy divet. |

:::solution
```rust
/// Ezek a kezdőtagok lezárnak egy nyitott `<p>`-t.
const CLOSES_P: [&str; 26] = [
    "address", "article", "aside", "blockquote", "details", "dialog", "div", "dl", "fieldset", "figcaption",
    "figure", "footer", "form", "h1", "h2", "h3", "h4", "h5", "h6", "header", "hr", "main", "nav", "ol", "p", "ul",
];

/// Ezek a zárótagok a "blokk" szabály szerint záródnak (hatókör + implicit zárások).
const BLOCK_END: [&str; 26] = [
    "address", "article", "aside", "blockquote", "button", "details", "dialog", "div", "dl", "fieldset",
    "figcaption", "figure", "footer", "form", "header", "li", "dd", "dt", "main", "nav", "ol", "pre", "section",
    "summary", "ul", "table",
];

const HEADINGS: [&str; 6] = ["h1", "h2", "h3", "h4", "h5", "h6"];

/// "Különleges" elemek: egy ismeretlen zárótag nem zárhat le rajtuk keresztül semmit.
const SPECIAL: [&str; 40] = [
    "address", "article", "aside", "blockquote", "body", "br", "button", "dd", "details", "div", "dl", "dt",
    "fieldset", "footer", "form", "h1", "h2", "h3", "h4", "h5", "h6", "head", "header", "hr", "html", "img", "input",
    "li", "link", "main", "meta", "nav", "ol", "p", "pre", "section", "table", "td", "th", "ul",
];

const IMPLIED_END: [&str; 6] = ["dd", "dt", "li", "option", "optgroup", "p"];

const SCOPE_BOUNDARY: [&str; 8] = ["html", "table", "td", "th", "caption", "marquee", "object", "template"];

// ... az impl TreeBuilder-ben:

fn in_scope(&self, name: &str, extra: &[&str]) -> bool {
    for &n in self.stack.iter().rev() {
        let tag = self.doc.tag_name(n).unwrap_or("");
        if tag == name {
            return true;
        }
        if SCOPE_BOUNDARY.contains(&tag) || extra.contains(&tag) {
            return false;
        }
    }
    false
}

fn generate_implied_end_tags(&mut self, except: &str) {
    while let Some(name) = self.current_name() {
        if name != except && IMPLIED_END.contains(&name) {
            self.stack.pop();
        } else {
            break;
        }
    }
}

fn close_element(&mut self, name: &str) {
    self.generate_implied_end_tags(name);
    self.pop_until(name);
}

fn in_head_element(&self) -> bool {
    matches!(self.current_name(), Some(n) if HEAD_ELEMENTS.contains(&n) || n == "head")
}

// ... a start_tag utolsó ága:
_ => {
    self.ensure_body();
    if CLOSES_P.contains(&name) && self.in_scope("p", &["button"]) {
        self.close_element("p");
    }
    if HEADINGS.contains(&name) && matches!(self.current_name(), Some(n) if HEADINGS.contains(&n)) {
        self.stack.pop();
    }
    match name {
        "li" => {
            if self.in_scope("li", &["ol", "ul"]) {
                self.close_element("li");
            }
            if self.in_scope("p", &["button"]) {
                self.close_element("p");
            }
        }
        "dd" | "dt" => {
            for other in ["dd", "dt"] {
                if self.in_scope(other, &["dl"]) {
                    self.close_element(other);
                }
            }
        }
        _ => {}
    }
    let id = self.insert_element(name, attrs);
    if !VOID.contains(&name) {
        self.stack.push(id);
    }
}

// ... az új end_tag és any_other_end_tag:
fn end_tag(&mut self, name: &str) {
    match name {
        "head" => {
            if self.body.is_none() && self.in_head_element() {
                self.pop_until("head");
            }
        }
        "body" | "html" => {}
        "p" => {
            if !self.in_scope("p", &["button"]) {
                self.ensure_body();
                let id = self.insert_element("p", vec![]);
                self.stack.push(id);
            }
            self.close_element("p");
        }
        "br" => self.start_tag("br", vec![]),
        _ if HEADINGS.contains(&name) => {
            if HEADINGS.iter().any(|h| self.in_scope(h, &[])) {
                self.generate_implied_end_tags("");
                while let Some(n) = self.stack.pop() {
                    if matches!(self.doc.tag_name(n), Some(t) if HEADINGS.contains(&t)) {
                        break;
                    }
                }
            }
        }
        _ if BLOCK_END.contains(&name) => {
            let extra: &[&str] = if name == "li" { &["ol", "ul"] } else { &[] };
            if self.in_scope(name, extra) {
                self.close_element(name);
            }
        }
        _ => self.any_other_end_tag(name),
    }
}

fn any_other_end_tag(&mut self, name: &str) {
    for i in (0..self.stack.len()).rev() {
        let tag = self.doc.tag_name(self.stack[i]).unwrap_or("");
        if tag == name {
            self.generate_implied_end_tags(name);
            self.stack.truncate(i);
            return;
        }
        if SPECIAL.contains(&tag) {
            return;
        }
    }
}
```

:::why A legendás „adoption agency” algoritmus
Mi történik ezzel: `<b>félkövér <i>mindkettő</b> csak dőlt</i>`? A tagek keresztezik egymást. A mi fa-építőnk a `</b>`-nél lezárja az `<i>`-t is, így a „csak dőlt” szöveg dőlt nélkül marad. A böngészők viszont dőltnek mutatják! Ehhez a szabványnak van egy hírhedten bonyolult algoritmusa, az **adoption agency** („örökbefogadási iroda”). Ez a formázó elemeket (`b`, `i`, `a`, `em`, `font`…) egy külön listában tartja nyilván, és a keresztezett tageket **klónozza**, hogy a fa mégis helyes legyen. Kb. 50 sornyi szabvány-pszeudokód, és a böngészőfejlesztők rémálma. Ha egyszer kedved lesz hozzá, kihívásnak kiváló. A html5ever (16. modul) természetesen tudja.
